# ADR153 proposal: operation-owned connector enrollment and signing proof

Source-only review after direct native3. No production source, runtime selector, test payload or build is part of this proposal. ADR150 remains the observation-only contract and cannot authorize this change implicitly.

## Contract boundary

ADR126 and `connector-renewal.md` require current actual Pod/token/controller proof, independently protected source/workload, exact source/backing, unchanged current recovery and current SQL effects. Historical signed material or acknowledged admission never becomes fresh permission. They do not make continuously unobserved Kubernetes history or instantaneous revocation possible.

ADR153 should explicitly permit a new, purpose-fixed, process-local operation object for each Enroll, client signing, and server signing. Existing `ReadConnectorProcessProof`, source/registry, retirement and legacy bootstrap consumers retain their full behavior. The new object must not implement those general source/proof interfaces, and cannot be installed as a caching callback behind them.

Each operation owns the original request ID, exact process/Pod identity, both immutable CSR/key digests, full original source/profile/roles/backing, native guard pins, token bytes/expiry, cancellation, and earliest original <=5s end. The owner clones all mutable inputs. Returned correlations or JSON values cannot recreate the object. Enroll, client signing and server signing have separate objects; none carries native authority across operations or extends Reconcile's original <=30s end.

The native object has four closed phases matching the existing coordinator boundaries. First and Final each perform a genuine complete native boundary using actual responses once: source guard and workload guard are independent; exact namespace/account/Deployment/ReplicaSet/Pod chain and online token checks are bound to those actual observations. Reuse the actual denied-probe Deployment in the chain and pure source decoding, rather than nesting full standalone readers that discard those same bodies. The final boundary is another real I/O observation and must agree with original identities and security-relevant facts. Status/resource-version changes allowed by existing startup proof are not falsely classified as new process identity.

The two intervening phases perform actual direct current checks, not an original-proof lookup alone: both policy/binding objects, exact full source/body/roles/backing, current online TokenReview for the original token, live namespace/account/Deployment/ReplicaSet/Pod security facts. The same response can satisfy overlapping checks within that one phase and its original interval. No response is represented as two independent reads. No fresh denied dry-run is claimed at these intermediate phases; the original positive native enforcement proof remains bounded and final denial is independently reproved. A known mismatch/unavailable response, cancellation or expiry permanently closes the operation.

Source/body read dates and initial/final native dates stay distinct. Current reads only shorten the original proof, caller, token, issuer-root and recovery caps; each earlier cap immediately narrows subsequent native/SQL/provider/audit contexts. No final read renames its observation time to create a fresh five seconds.

## Proposed deduplicated native request target

This must be implemented as genuine complete boundaries, not two calls to the existing 54-request attester. The existing ADR150 native boundary is evidence that its *pure object validation/actual response ownership* can be shared, not authority to reuse an observation-purpose proof in enrollment.

| New closed phase | Observer | Probe | Actual work |
| --- | ---: | ---: | --- |
| First native boundary plus full source value | 22 | 6 | Source guard 6; independent workload/token/chain boundary 13; namespace-bracketed full source 3 |
| Before outcome (Enroll) / before claim (signing) | 12 | 0 | Four policy/binding GETs; namespace before/after; full source GET; account/Deployment/Pod/ReplicaSet GETs; online TokenReview |
| Before acceptance / activation | 12 | 0 | Same fresh direct current checks, original identities/caps |
| Final independent native boundary plus full source value | 22 | 6 | New complete actual native observation and full final value |
| One operation target | 68 | 12 | No new clients, limiters or credential scope |

The initial/final chains must bind the actual original token/CSR/key and source before any effect. The source's actual full value may be decoded from a response already read in the same boundary only if its namespace/guard and exact UID are still independently bracketed. Count reductions beyond this conservative table must be explicitly evidenced, never inferred.

For a full initial Reconcile, retain the outside-operation source/registry checks unchanged first: 3*68+112 = 316 observer and 60 probe requests. The source-rate floor becomes 14.8s cold, about 15.8s with a depleted observer bucket, before real SQL/audit/provider work; the existing <=30s cap stays. Each individual operation's native floor is 2.4s cold/3.4s depleted, leaving finite but unqualified room under its original <=5s. Actual accepted recovery/source freshness can leave less time than five seconds; no minimum freshness is fabricated and no source polling/retry is introduced to make it pass. Measure the complete Reconcile and shared-client phases before claiming availability.

## Effect/state preservation

Keep all original coordinator effect ordering and independent SQL49 transaction/current-root/recovery checks. Enroll checks before Prepare, after Begin before Store, after Finish before Accept, and after Accept before returning an acknowledged process. Signing checks before Prepare, after Begin before irreversible Claim/provider signing, after Finish before Activate, and after Activate before delivery. Preserve current proof/permit/cancellation checks after all blocking calls, exact stored-result comparison and before/after provider verification. Do not repeat unknown signing, issue replacement IDs, refill budget, refund a late result, or activate from a failed final check.

The new typed application current state must retain the original proof's dates and separately represent the actual phase/value read. It may reuse existing SQL predicates only through an explicit private conversion that preserves their original identity/source/expiry fields and current transaction checks; no newly returned value silently masquerades as a fresh legacy full attestation. If SQL needs an explicit semantic discriminator, add a reviewed additive contract instead of ignoring it. The exact smallest carrier/conversion is an implementation-review item before effects are wired.

Native changes observed before an effect deny it; final native changes suppress successful delivery. Unknown prior effects remain charged and their original exact rows/keys retained. A transient A→B→A between reads is not proven absent by either old standalone checks or this protocol; native namespace protection and original five-second expiry remain the stated trust boundary. There is no claim of partition-proof instantaneous revocation or cryptographic protection against the authorized local process.
