# Connector identity, automatic process replacement and renewal

ADR-126 supplies component foundations for a connector that can restart without asking an administrator to reenroll it. The logical installation/cluster/peer account remains stable; actual Pod/controller proof admits a bounded process child and separate client/server keys. This is not an installed connector runtime or a public evidence route.

The SQL49 checkpoint adds five tables: `connector_identity_root`, `connector_identity_profile`, `connector_identity_process`, `connector_credential_attempt` and `connector_backing_transition`. The root retains original role/incarnation and shared backing. Per-peer profiles preserve central multi-cluster management. Process rows bind exact Pod UID, process epoch, two public-key digests and original run/period bounds. A credential attempt retains immutable signing spend and the possible leaf. Backing transitions are independently paid children of their original encrypted pair; current observation never changes earlier dates or counters.

The source, journal, acknowledgement, cleanup, verifier and finalizer duties use distinct actual PostgreSQL logins. Protected source staging resolves their real names/OIDs and current database incarnation after first activation. Exact lifecycle views expose identity rows to the three cleanup duties without granting human audit base-table access or changing complete-history scans. A separate read-only registry performs exact leaf lookup; labels, a source status field or possession of an unregistered certificate do not confer authority. Role replacement, added role membership, current recovery failure and complete-source mutation deny.

Automatic process admission uses current TokenReview and the live Pod/account/ReplicaSet/Deployment chain plus independent workload protection. There is one pending child per Pod and separately bounded serving/history slots. Both new purposes must activate before a same-Pod serving child retires. Prior unknown claims and late signing results cannot overwrite the replacement or regain a slot. A container restart within the same Pod generates a new process epoch and keys; a rolling Pod consumes a separately available serving slot.

Client leaves are exactly clientAuth with one fixed connector URI and no DNS/IP/email SANs. Server leaves are exactly serverAuth with that URI and one protected DNS name. Their key digests and issuer purposes differ. Thirty-minute periods, one-minute early renewal/overlap, two attempts per purpose/period and the process's original finite end remain binding. The OpenBao provider fixes its endpoint/role/purpose, rejects provider-returned private keys and checks the independently current source before and after signing. Production issuer credentials and protected role provisioning remain required. The process-owned credentials close retained signers and join their in-flight work; socket ownership stays with the listener/forwarder.

The immutable signing request start may precede sequential current proof reads. Historical permit validation requires a nonempty intersection of those original intervals, starting at the latest request/proof/source/recovery observation; it preserves their original ends and five-second limits. Stored-result verification may validate that historical intersection, but every new effect still checks the actual current time, current source/recovery/identity and the unchanged original signing deadline.

Only Backing is excluded from the behavioral digest. Complete source digest, backing revision/digest and current protection still travel with every observation. A backing-only edit can preserve existing process/key/leaf identity after independently acknowledged acceptance, but an old or mutated full source cannot regain authority merely because behavior is equal. One source-owned candidate UUID is retained across uncertainty. Staging pays for stage and exact close/promotion; the final transition does not require another ordinary source-budget slot. Exhausted transition backing denies ordinary process/signing/serving authority. Same-revision mutation is durably blocked; a transient unavailable read is fenced and can recover only under fresh exact original facts.

The private audit uses the existing conditional PUT, exact verified GET, positive joined write completion, independent acknowledgement and finite purge/history protocol. A stateless per-intent wrapper keeps fixed store/role/qualification resources while honoring each exact pre-admitted record's original policy. SQL checks that immutable business record before any object effect; selecting a policy from caller data is not admission. Public human JSON bytes and public operation discovery remain unchanged. No process key, Pod token, personal bearer or certificate private key is serialized into SQL/audit.

Verification remains component-specific. Focused synthetic tests exercise purpose separation, real TLS with synthetic issuer/registry, current source/identity continuity, unknown replies, paired process replacement and joined closure. `TestContextAdmissionWithRealServices/connector-identity-fast` now passes actual SQL/S3 admission, six private duties, encrypted audit, exact leaf activation, backing continuation, view isolation, exhausted-source close/promotion and bounded lock waits. Protected source/Pod/qualification and local issuer facts remain explicitly synthetic. The [terminal report](../../test/results/connector49-fast-qualified-check.log) records unchanged tested sources and complete cleanup; the earlier temporal-validation and fixture-name failures remain in the [progress record](../implementation-progress.md). Parser acceptance and type-valid backing do not measure heap/index/TOAST/WAL or qualify real backup/provider budgets.

Remaining work is explicit: distinct prepaid restrictive tickets usable after an original process dies or ordinary admission expires; finite profile/source/backing/root retirement with original writer/leaf/history obligations; the actual minimum 31-minute cleanup qualification; deployment-owned source/role/issuer provisioning and connector listener/supervisor attachment. A provisional proactive live-proof retirement coordinator is excluded from this checkpoint because it does not solve historical retirement. The typed retirement-only attester remains separate and never makes its proof valid for ordinary issuance. Ordinary last-cluster removal must keep the logical installation root usable; permanent minimized root retirement is reserved for complete installation teardown.

Credential availability does not qualify larger native transfers. The implemented context exchange retains its original at-most-five-second observations; ongoing large native responses still require separately qualified renewal across those boundaries. Helm/public native runtime remains disabled until the missing composition and lifecycle requirements pass.
