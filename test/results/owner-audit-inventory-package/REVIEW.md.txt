# Owner audit inventory diagnostic — staged, uncompiled

Source checkpoint 2 preserves checkpoint 1 as explicitly unrun. Three new adapter/test files only; no live source, SQL, role, runtime constructor or public route changes. Proposed qualification is scoped objectstore compile/races/vet plus Go architecture after parent allocates a slot. No job launched.

The concrete reader is bound to one independently supplied original `fleet.OwnerConfiguration` and selected StoreID/Store. Configuration is deep-copied. Historical roots/configuration are structurally validated, not treated as current source/issuer authority. Actual LIST rights belong to the separately configured inspection credential; its backend binding and provisioning remain caller-owned installer prerequisites, just as existing CustodyStore pins store identity. There is no arbitrary key argument or authority callback.

Read owns a caller-shortened five-second diagnostic interval and exactly three bounded LIST requests. It returns exact-key versions (including actual null IDs and zero-byte physical data), markers, uploads and a current-key cross-check. Every returned source row must be within the queried prefix, while neighboring decimal generations are omitted from the result. Each per-LIST completion flag is assigned only after all its rows and the original deadline have been checked. A later malformed row, unavailable LIST or cancellation returns already validated entries together with its error; the failed/unissued LIST remains incomplete. All per-LIST truncation flags survive; no cursor or complete multi-page scan is selected in this first diagnostic. Empty exact-key data on a truncated neighbor page is incomplete. No atomic snapshot, writer quiescence, deletion certificate or release can be derived from this result.

Version bytes are actual provider metadata, not a logical-audit allowance. Unexpected huge versions remain visible, without unchecked sums. Markers have no ciphertext body but are not declared free metadata. Upload IDs have no fabricated version or byte count; ListParts/backing and subsequent all-page accounting remain separate work. A current key without a listed matching latest version is explicit and never creates a null version. Returned configuration cannot mutate the pin.

Staged meaningful tests use real TLS and the actual SDK with synthetic provider replies: historical expired observation/actual expired issuer DER, deleted caller source copy, exact identity and copy isolation, generation 1/10/11, three separate incomplete neighbor pages, explicit null/marker/upload distinction, malformed/foreign/duplicate rows, page overflow, authorization denial, cancelled/expired caller before I/O, blocked final native read cancellation/deadline with prior entries retained, and all three late-failure phases (missing truncation, malformed tail or provider unavailability). Constructor/root and returned interval checks are separate from authority. These are source assertions until the allocated job actually runs; no native backend qualification implied.

The original source proposal remains `../audit-version-authority-inventory-20261013/PHYSICAL-OWNER-AUDIT-PROPOSAL.md`. Its producer/backing and finite retirement decision remains pending; no migration is reserved and existing logical audit behavior is unchanged.

The existing accepted versioned-storage and custody contracts cover this diagnostic. No new ADR is proposed here. The separate producer/backing/retirement decision will need its own explicit contract review, including all-page continuation, immutable original storage identity, physical ledger capacity, and independent writer quiescence. This component neither selects that protocol nor implements a retirement reader.
