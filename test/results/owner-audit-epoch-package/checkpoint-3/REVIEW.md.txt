# ADR156 finite epoch values: reviewed source checkpoint 3

Nine new staged files and two additive architecture/catalog updates. No existing Go, wire, schema, SQL, IAM or runtime file is modified; the two documentation changes preserve qualified ADR155 and ADR157 entries and identify this foundation as unselected. Gofmt parses these files; compiler, tests and gates have NOT run. No migration/grant or format selection is authorized by this checkpoint.

Compared with checkpoint 1, the review closes three concrete gaps:

1. The previous synthetic 5-minute interval / 280-minute full lifecycle / 8-slot policy was mathematically unsustainable. A fixed automatic interval now provides explicit overlap and a reported lower bound: ceil(full original residual horizon / interval) + one pending + explicitly configured uncertain allowance. With two uncertain slots the fixture needs at least 59, and its new unshipped value is explicitly 64. This is a test value, not a default or measured capacity. Insufficient limits return the required minimum and remain unchanged.
2. Dependency identity now includes the exact purpose-owned effect/attempt ID. New admission also requires its complete original lifecycle to fit current retained receipt availability; fresh five-second source observations cannot admit a 20-minute effect under a one-minute shortened cutoff. Independently admitted work can still continue within its current shortened cutoff. Only the concrete SQL owner can prove the actual stored effect.
3. Aggregate reservations account for every dimension and retain full unknown claims. Empty observed inventory never subtracts unknown charge. One pending attempt, exhausted uncertain allowance, out-of-contract copies, negative counters and overflow all reject another claim. No release/refund method exists in these values.

The accepted/admitted ports remain distinct from the existing raw observation and from each other. Rollover does not change semantic configuration, current source freshness or an original dependency. The old v1 configuration/key/receipt/encryption code remains byte-for-byte untouched. Tests use the actual existing v1 receipt type and key producer; no copied legacy implementation or mixed-format fallback exists. Existing envelope codec qualification remains separate until the new codec is implemented.

`SQL-PLAN.md` is the separately reviewed-before-implementation facet plan. `INSTALLED-PATH.md` fixes the proposed new exact key/AAD and names the actual worker/SQL/effect consumers needed for a complete selected graph. Both are proposals, not implemented facets. Inventory pagination is parent-owned; no inventory adapter changes belong to this checkpoint.

Routine rollover and cleanup are installation services under one finite administrator policy, not per-epoch human approvals. Missing capacity produces a concrete operator condition and stops new work; it does not ask a developer to recreate the configuration. Full physical backing, cleanup latency, admission/retirement SQL, independent restore and installed worker sustainability remain unqualified.

Parent review found a draft-only admission defect in checkpoint 2: an original dependency could have already ended while the encompassing five-second source observation remained fresh. Checkpoint 3 requires `now.Before(EndsAt)` without changing any original date. A regression tests one microsecond before, the exact end, and one microsecond after. The forthcoming runner first reproduces only the unshipped checkpoint-2 failure under the new tests, then runs corrected package tests; neither stage will be described as a production failing-before regression. All staged Go imports now use standard-library and local groups.
