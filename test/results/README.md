# Product component test evidence

These files record synthetic component verification, not product release acceptance. `make go-check` checks the embedded schema bundle and runs ordinary Go race tests; `make context-integration` creates two owned Kind clusters and private S3/OpenBao/PostgreSQL containers, runs the real-service tests and removes them.

Fixture reports name exact images and cleanup outcomes without credentials. `context-storage-failure-01.json` recorded the initial failed executable start; its apparent empty cleanup-failure list missed a created-but-untracked container. That exact labelled container was subsequently removed, and the harness was corrected to track creation before startup. Subsequent failed-fixture reports are preserved separately. The final environment report and test log determine whether the integration run passed.

Logs contain no native evidence bodies, keys or service tokens. A default `go test` invocation explicitly skips the external fixture test; that skip is not a passing integration verdict. See [the implementation record](../../docs/research/artifact-foundation.md) for supported claims and remaining work.

The final `context-storage-environment.json` records Go 1.27.2, exit 0, source hashes unchanged during the test and no cleanup failures. `context-storage-before-patch.*` is earlier successful integration evidence; the final result supersedes it after the Go/x/net security update. `go-check.log` and `govulncheck-verbose.log` record final component gates. The one module-only advisory is the unused/unmaintained OpenPGP package; the import gate forbids it.

The custody continuation adds `custody.log` and `custody-environment.json`: real PostgreSQL/S3 storage transactions, concurrency/expiry tests and version/marker/multipart deletion, with final source hashes and cleanup evidence. `custody-initial.*` predates final refinements; `custody-failure-01.json` records the initial TCP-readiness failure. `custody-go-check.log`, `custody-design-checks.log` and `custody-vuln-check.log` are the continuation's gate results. See the [custody record](../../docs/research/custody-foundation.md) for the distinction between unpublished storage custody and complete authorized publication. `context-storage-before-custody.*` preserves the earlier context integration before the shared S3 changes.

The manifest continuation extends `context-storage.log` and its environment report with complete pod-status manifest/envelope/native verification followed by PostgreSQL unpublished receipt storage. `context-storage-before-manifest.*` and `custody-before-manifest.*` preserve preceding runs; `*-manifest-initial.*` preserve the successful runs before final dependency-lock tidying. `manifest-go-check.log`, `manifest-fuzz.log`, `manifest-design-checks.log`, `manifest-vuln-check.log` and the `manifest-*-fixture.log` files record this continuation's commands. See the [manifest record](../../docs/research/manifest-foundation.md); synthetic accepted facts are not real grants, and no artifact is published to a developer.

`custody-network-exhaustion.*` records a failed concurrent fixture start before any service was created. The host ran out of Docker default subnets; these two suites must run sequentially here. Successful reruns retain their own actual exits and cleanup reports.

The identity continuation adds `identity-initial-tests.log`, `identity-regressions-before-fix.log` and `identity-error-regression-before-fix.log` for reproduced defects; `identity-focused-tests.log` for the corrected TLS/JWT/application flow; and `identity-go-check.log`, `identity-fuzz.log`, `identity-vuln-check.log` and `identity-design-checks.log` for final gates. See the [identity record](../../docs/research/identity-foundation.md). The JWKS HTTPS server and signed tokens are synthetic; configuration/catalog readers are test-only. No real IdP, public login, accepted capture or durable audit is implied. Previous external-service reports remain historical and were not rerun for these new packages.

`identity-audience-growth-before-fix.log` preserves the final retained-reader regression. The final Go gate includes its correction. `identity-verification.json` inventories source and logs after the passing checks; it does not rewrite or replace earlier integration source records. `identity-documentation-final.log` records the final documentation checks.

The permission continuation adds `permission-deny-before-fix.log` and `permission-independent-source-before-fix.log` for reproduced freshness/availability defects; `permission-focused-tests.log`, `permission-fuzz.log` and `permission-vuln-check.log` cover the new reader/evaluator components. `permission-kubernetes.log` and `permission-kubernetes-environment.json` record a real owned Kind/RBAC fixture with source hashes and cleanup. Its test CRDs deliberately accept malformed specs; this is not production admission or source-trust qualification. See the [permission record](../../docs/research/permission-foundation.md). Previous SQL/storage integration reports were not rerun because those implementations and their dependencies did not change.

`permission-go-check-initial.log` preserves a catalog-ownership failure after successful Go tests; the corrected final batch is `permission-go-check.log`. `permission-kubernetes*-before-tidy.*` preserves the earlier passing fixture before the dependency classification cleanup. `permission-verification.json` inventories final inputs and logs after checks; the real-server report independently verifies unchanged inputs during its test.
