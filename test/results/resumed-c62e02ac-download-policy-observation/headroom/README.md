# Near-expiry request headroom correction

A live observation can still be too old to give a newly started request its existing five-second interval. The regression primed the cache at an observation age of 59.9 seconds, then invoked the actual CurrentDownloadEnvironment with a processing port that performs a joined 150-millisecond wait. The initial implementation clipped that read to the old policy expiry, about 100 milliseconds away.

The genuine RED Go command exited **1**, package **0.142s**. Its fresh-request subtest failed after about 100ms with one raw read and the processing deadline equal to the old policy expiry. The original-40ms-caller negative case passed. Exact production/test checkpoint snapshots, raw output, command/environment and before/after source hashes are retained here. The wall clock and actual context cancellation run normally; priming uses an injected policy clock offset to avoid a sixty-second sleep. Policy and processing data are synthetic, so this is a deterministic service composition regression, not installed latency attribution.

The correction reuses cached policy only with at least five seconds remaining. A caller encountering less starts the existing synchronous bounded live refresh; concurrent callers share that flight. The new interval is the new raw observation's original start plus sixty seconds. No cache hit slides an interval, no background read occurs and a failed refresh cannot return the still-valid but thin old observation. Caller deadlines are unchanged. Exactly five seconds remaining still reuses the observation; the next nanosecond requires refresh.

The focused race GREEN command exited **0**: authorization **1.228s**, privacy **1.008s**. The fresh request completed its 150ms processing read using two total raw reads (priming plus refresh); its processing bound was approximately 4.9 seconds later than the old cache expiry. The short original caller still failed at forty milliseconds. Boundary, failed-refresh, ownership, cancellation, current recovery/processing and strict administrative-validity tests also passed. All five recorded sources were unchanged during GREEN. Production changes are only the two cache/waiter eligibility conditions and their explanatory comment; production-fix.patch captures them.

This phase supplements the earlier cache evidence without rewriting it. No external fixture or full package gate ran.
