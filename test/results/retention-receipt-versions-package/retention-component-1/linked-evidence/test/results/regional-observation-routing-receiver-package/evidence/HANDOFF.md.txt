# Closed observation routing receiver checkpoint

Scope: ten isolated paths; no live source mutation. This adds the purpose-fixed
common-SNI locator GET / exact-SNI claim POST handler and its concrete existing
owner-registry/Ready/native-workload checker. No listener, loader, SQL query,
forwarding runtime or public installed-v2 carrier selects these routes yet.

## Contracts

The original permission root remains distinct from installation identity. Both
actual mTLS owners must match one explicitly installed source/pool/template/image/
guard pin. The checker independently traverses current registration, Ready route
and guard for each owner, observes both exact native workloads, and rechecks the
actual peer and private serving key after blocking work. The handler repeats
that check before returning, requiring unchanged identities and current revision
without replacing the first proof's original deadline.

Locator GET requires common SNI and matching authority; claim POST requires the
exact local process SNI and matching authority. Browser credentials, HWORK tokens,
idempotency headers, alternate request representations and wrong purposes deny
before proof/holder work. An exact holder claim is irreversible; the result is
returned only after the existing four regional proofs, metadata, Receipt/EOF and
admitted handler cleanup join. A failed final proof or reply does not refund or
replay that claim. Original request/caller/proof/socket bounds only shorten.

OwnerPool.NativeCandidateLimit is an optional domain value: zero preserves old
omitted bytes, and nonzero requires the opted bootstrap profile plus1..1024.
Its identical isolated domain-field-v1 copy was provided to console for the one
coordinated fresh installed-v2 carrier. This package adds no public configuration
field, SQL query or installed selection. The old context-start query remains
LIMIT17 with explicit >16 denial. A separate complete observation candidate
reader and all v2 consumers remain prerequisites.
