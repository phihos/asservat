# ADR140 configuration-role checkpoint

This is a reviewed-source integration candidate, not an installed public
runtime or a completed ADR140 handoff. All external qualification remains
parent-owned. No live repository file, SQL schema, listener or chart was changed.

## Included scope

The three fixed configuration roles now have an actual protected Kubernetes
source/Secret/projection producer, actual PostgreSQL provisioning and current
acknowledgement, a callable private installer and a verifying runtime
constructor. The native SQL/S3/OpenBao matrix is ready for execution. The source
is selected from immutable `checks/configuration-path-5`, with one explicit
integration refinement: `RunHubWorker` retains its existing constructor until
the new projection is produced and qualified. `pending/hub-worker-command.patch`
records the required later switch. No silent legacy fallback is added to the
new verifying constructor.

The package includes the partial public-role implementation because its exact
receipt DTOs, immutable-projection mechanics, SQL grant/ACL checks and test
helpers are shared dependencies. It is an 18-purpose identity/read subset, not
the final public inventory or aggregate connection-budget proof. No public
installer command, public HTTP server or incomplete public handler graph is
included. The configuration CLI implementation is callable but is not yet
registered in `cmd/asservat/main.go`.

## Contracts and authority

- Separate closed `configuration-runtime-roles/v1`, private original state,
  immutable credential manifest and 96 KiB configuration-installer DTO. Fixed
  roles `_cfg_00..02`; each pool one connection; each role limit three for two
  retained reconciler processes plus a verifier. No caller-selected grants.
- Original 30-minute private root and one-use five-second claims. SQL receives
  exact provenance and public role identities, never passwords or HMAC seeds.
  Unknown claims/results allow exact lookup only; no repair/adoption/new grant.
- Original positive initial activation, actual process/database incarnation,
  current issuer/recovery/suspension and independently current guarded
  fleet/owner/workload source checks. Only this fixed configuration bootstrap
  can replace stale stored observation freshness; public-role gates stay
  stronger. The producer neither observes nor accepts configuration itself.
- Same-operation proof retention is private to the concrete source. Repeat
  actual negative RBAC/admission checks, exact canonical sources/workload and
  guard versions. Preserve original starts/earliest ends and cancellation.
  First role and final inventory reads occur after SQL locks. UTC normalization
  changes time representation only.
- Current configuration acknowledgement locks recovery before configuration
  and preserves the original current snapshot/deadline through COMMIT.
  Historical acknowledgement behavior is not changed; neither one activates.
