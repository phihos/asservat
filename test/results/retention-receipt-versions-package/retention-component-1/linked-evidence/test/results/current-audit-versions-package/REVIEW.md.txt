## Scope and actual consumers

- Six domain files require nonempty/non-null versions for download-worker intent/configuration, acquisition enrollment/certificate, connector claim/certificate, and batch/window intent/outcome. The shared generic `workerReceipt` and other operation/evidence families stay structurally unchanged.
- `currentAuditedWorker` decodes the entire original worker receipt and matches its purpose/key/shape; a JSON presence check is insufficient. Current dispatch read, identity routing, owner claim, first-context response admission and native owner admission use it. Structural `decodeWorker` remains for termination/audit/retirement.
- `readWorkerIdentity` repeats exact worker and receipt-byte comparison after current configuration can block. The owner locator's existing SELECT now embeds its already-joined worker row, so validation adds no query or grant. Actual pinned sqlc generation is pending, expected to change only custodydb/worker_owners.sql.go.
- Current acquisition certificate activation/registry also read and validate the exact retained enrollment receipt and original enrollment identity. This adds one actual bounded enrollment SELECT to those certificate paths, within their original operation context; no freshness is reset.
- Current batch/window decoders, metadata permission and native-parent checks require strict receipts. Native preparation explicitly requires its acknowledged flag as well as its body. Historical decoders are called only from CancelDownload, FinishDownloadBatch and FinishDownloadWindow; they cannot grant a lease, key or new I/O.
- Current connector signing/activation verify retained version columns; PeerRegistry verifies its own retained certificate version. Historical certificate decoding/audit preservation are unchanged.

## Regression design

`TestReachableAuditReceiptsRequireImmutableVersions` contains ten receipt purposes, each with original/empty/null/maximum/oversize cases. Overlaying this new test alone on the original domain implementation gives the intended old-behavior before: the twenty empty/null cases must fail for the explicit version predicate reason. No fabricated old production variant is needed.

Pure PostgreSQL decoder tests compare exact original row/receipt bytes and distinguish strict current reads from historical accounting. A wrong-key/zero-digest worker remains unavailable even with a nonempty version. The generic worker receipt omission behavior remains covered by the existing owner-version separation regression.

The selected native `download-worker-enrollment-audit-versions` continuation uses actual existing SQL/S3 worker configuration, dispatch and certificate acknowledgements, with its existing explicitly synthetic native proof/issuer. Only the fixture administrator models old retained empty/null receipts through a transaction-local trigger bypass, registered for exact restoration before write. Runtime trigger bypass is denied. Every negative retains its original authority deadline and follows positive original reads; neither expiration nor missing grants may pass for the intended reason. Tests cover current configuration, identity, locator/claim, signing/activation, native certificate and actual native parent admission. Native denials do not advance the original fence.

The same continuation verifies that recording already performed synthetic bytes and cancellation still work with historical receipt versions, without refunding prepaid charges. The existing window accounting test similarly denies old-version leases but records the already permitted synthetic physical outcome. Connector provider and registry fixtures exercise retained version-column denials and exact original restoration.

Five actual fixture buckets enable versioning before first relevant audit write. Generic mixed evidence stores remain generic. capture_admission_test.go was based after the root's pool fix and retains `qualifyContextPublications(..., create, authorityPool.Reset)` exactly.
