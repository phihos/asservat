* worker_runtime_admission.go retains one total ticket per purpose, five total,
  one active. Queue plus pre-selection notice waiting has one original five-second
  scheduling end, additionally bounded by the original outer caller. Cancellation
  does not release actual active work before its owner joins.
* configuration_runtime_source_notice.go forwards only concrete
  *postgres.FleetObservation. Full changed values invalidate scheduling and cancel
  active work before the actual SQL observation; source errors invalidate before
  actual FenceAdministration. Only an acknowledged, still-current original SQL
  observation produces a notice. Unknown/failed commits do not. No callback,
  recovery writer, SQL pool, extra observer or retry is introduced.
* worker_runtime_source_notice.go stores complete cloned public source values and
  their exact original interval solely for scheduling. A ticket waits for a read
  begun at/after its FIFO grant. It can consume one notice, then its context is
  capped at that original source end. A later notice cannot extend it. This is
  not a minimum-age guess or returned RecoveryProof: the effect still performs
  exactly one actual recovery selection, retaining its possibly earlier end.
* owner_provider_lifetime.go waits for this scheduling event only for due wrap or
  unwrap maintenance. Healthy ticks remain zero-native-work hints. Actual provider

* worker_owner_audit.go acquires its ticket and scheduling opportunity before

  active work, even before a blocked negative SQL call returns.
* configuration_provider_audit_operation.go consumes the exact same owner-audit
  ticket once. It does not acquire a nested ticket. The application retains that
  ticket until write/readback/final checks and acknowledgement have joined. A
