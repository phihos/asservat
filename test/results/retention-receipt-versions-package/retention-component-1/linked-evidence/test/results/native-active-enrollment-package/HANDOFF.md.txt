# Exact activated enrollment avoids unused preparation routing

This immutable outside-repository package contains three paths. It changes no SQL,
wire format, native polling interval, capacity, deadline, current authorization or
cryptographic operation. The live repository is unchanged by this agent.

`ContextNativeRuntime.ContinueContextDownload` retains the existing current exact
Job/Pod observation, independent SQL attachment read and final C03 check. When its
initial and latest observations have the same exact worker, enrollment and active
peer covering the original request without certificate renewal, it starts the
existing first preparation directly. It does not construct/register an unused
enrollment owner or repeat an attachment read solely to rediscover that peer.
Native SQL claim, exact hub/process routing, actual TLS/Pod/current certificate,
key binding, frames and final checks remain unchanged. Selected active identity
loss/change fails and cannot fall back to issuance. Pending/unactivated workers
and renewal windows keep the original enrollment path and bounded wait.

Renewal scheduling uses the actual peer NotAfter minus the existing renewal lead,
including equality, as the supervisor does. Original-period compatibility also
uses WorkerCertificateEpoch. The test deliberately fixes CreatedAt to .500s to
cover the difference between original epoch arithmetic and second-truncated leaf
NotAfter. The existing final-period exception requires the exact original
RunUntil at second precision and the peer must still cover the request end.
