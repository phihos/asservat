## Minimal ordering

1. Make only this fixture's input Secret projection required. No container can start while the Secret is absent; the original helper's two-minute input loader remains unchanged.
2. Split discovery of the original Pod identity from observing it Running. Before creating inputs, retain the exact Pending Pod UID and its actual controller chain/defaulted Deployment template. Reject multiple Pods, deletion, replacement or any container that has already started unexpectedly. Do not guess UID or reuse a later Pod.
3. Construct existing immutable inputs from that retained Pod UID, defaulted original Deployment/template, existing namespace guard and protected regional source. Create exactly the same Secret once, using the current unknown-create accounting.
4. Under one finite two-minute setup observation interval fixed at the original input-create attempt (and capped by the whole fixture), wait for that same Pod to start with its actual Pod IP. Reject restarts/replacement/termination. No authority/proof/enrollment request starts or is retried by this wait.
5. Start the unchanged 60-second control-readiness observation only after this setup barrier. Existing helper enrollment and product calls keep their own original five-/thirty-second contexts. The whole fixture remains eight minutes.

The required Secret still requires actual Pod creation first: its Input.PodUID is exact. It does not require a running container or Pod IP. `baseInput` consumes only Pod UID. The current native namespace guard proves the Deployment/namespace and denied dry-run, without Ready or Pod checks; the regional source reads its protected ConfigMap. Thus retaining a Pending Pod breaks the fixture dependency without inventing identity.

Kubelet obtains the dedicated projected tokens for the actual existing Pod and account during volume setup. Those token paths/audiences and token RBAC remain unchanged. No helper consumes a token until it actually runs; actual online TokenReview/native Pod/RS/Deployment checks remain required later. An absent required Secret may prevent token volume completion, which is harmless because setup uses its separate existing fixture observer/probe credentials, not a helper's token.
