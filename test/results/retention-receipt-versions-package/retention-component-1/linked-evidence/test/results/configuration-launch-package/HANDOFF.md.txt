## Behavior and contract

The original configuration-role Secret can retain one optional launch disposition
only after its three positive role receipts and immutable projection are present.
An acknowledged first CAS permits exactly one inert-to-running Deployment UPDATE.
The original spec, object UIDs, resourceVersion, launch marker, immutable inputs,
original five-second interval, current source and independently current SQL
activation/recovery/role inventory remain binding. Unknown claim/UPDATE replies
are lookup-only. The original role claims are never rewritten for replicas one.

Successful replay checks the original launch result without provisioning roles
again. The separate SQL verification facet retains actual OID, authenticated
login, ACL, provenance, incarnation, epoch and recovery checks. It accepts only
the exact recorded zero-to-one spec transition; the credential creation method
has no such exception. The configuration-role CLI handles that retained branch.
The installed hub-worker constructor switch still requires actual generated
object/input handoff qualification.

ReadLaunched retains its complete post-lock source proof and performs exact
original-state/deadline checks after passive object reads. Record compares the
same original snapshot and freshly rechecks all enforcement/source facts before
the receipt CAS. This removes duplicate complete proof passes within the original
interval without caching authority between independent operations. Existing
receipt replay also performs the full current check.
