# Exact native completion handoff

Frozen 2026-10-12 outside the repository. Parent owns integration and external fixtures. No live source was edited.

## Result and contract

The current worker can finish its successful conversation while the original SQL owner is still routeable. The previous immediate-reconnect experiment exposed this in a real native run; restoring one second of delay made that workflow pass but did not prove closure.

This package retains the existing wire and worker scheduling. The hub sends successful final Done only after a fresh ordinary frame check and an acknowledged exact open-to-closed SQL transition under the original operation, fence, lease sequence and deadline. Existing restrictive cleanup cannot certify completion. Missing, replaced, closed, expired or unknown completion denies Done. A request-owned callback, retained in the original process, supplies the SQL transition; no wire callback or reconstructed credential is added.

After closure, a private transport capability permits only that original zero-byte marker using the last complete gate's unextended bound. Every other frame keeps its current checks. The relay already has a terminal-only path; the final h2 regression now makes ordinary relay checks deny immediately on simulated SQL closure. Final-marker loss remains uncertain, even if the SQL close committed.

Router and handler slots remain held until actual joined Close. A concurrent same-worker registration is denied before SQL admission. Old close handles cannot remove replacements. PrepareCurrent's final C03/metadata checks, Observe final authority and content outcome checks remain independent and unchanged. They do not require the native owner to remain open. No migration, grant, refill, replay, authority cache or deadline increase is added. SQL completion uses the existing exact row lock and close query, checks time again after the trigger's backing lock and commit, and charges the same original close transition.
