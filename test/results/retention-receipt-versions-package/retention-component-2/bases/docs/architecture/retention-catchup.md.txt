# Applying retained policy history

C-15 owns the restrictive catch-up facet under REQ-PRV-002/004 and S-01/S-02. C-01 owns [durable policy checkpoints](retention-checkpoints.md); C-15 owns their application to already registered evidence and [lifecycle decisions](retention-lifecycle.md). This is still an initial context-artifact implementation, not a complete retention controller. The separate [source read facet](retention-checkpoints.md) derives readiness only after catch-up, audits and fresh complete observation.

Migration 00017 adds one catch-up job for every accepted policy checkpoint, including earlier persisted checkpoints during migration. A transaction processes only the oldest unfinished checkpoint for the exact enrolled source, with at most 16 context attempts per page. It selects candidate IDs itself; a caller cannot submit a convenient subset or claim completion. The candidate set contains the installation's context registrations created by the checkpoint's SQL acceptance time. A local source visits only its own cluster; a hub source visits all enrolled-cluster contexts in that root. Already deleted attempts require no new deadline change.

The lock order begins with the installation root and source, then the catch-up cursor, allocation and attempt. Calls do no remote I/O and share the existing five-second SQL transaction bound. Source acceptance uses the same root lock, so a later relaxed checkpoint cannot overtake the older one. Each page atomically appends exact restrictive lifecycle decisions and their checkpoint/attempt links, adjusts effective dates, and advances its cursor and counts. A failed page rolls back its effects and cursor together. Retrying an uncertain COMMIT resumes from the durable cursor; it does not refund storage, repeat completed effects or reset counts. Completed jobs cannot rewind.

The historical resolver can only reduce existing dates. It does not require a currently fresh acquisition policy, or invent a complete baseline around one local subset. Defaults never reselect the original requested lifetime. It applies known class/type maxima and cleanup budgets inside the already-bound hard deadline; a larger budget can close the entire readable interval. A historical purpose conflict cannot grant access, but does not prevent enforcing known restrictive ceilings. Ordinary current acquisition resolution still requires a complete, compatible baseline/intersection.

The initial matcher supports unscoped and explicit cluster rules plus the policy UIDs already bound to the artifact. It follows a bound UID after selector changes and rejects revision rollback. A newly encountered namespace/workload selector requires qualified historical metadata. This initial adapter stops that page as unavailable instead of guessing from current labels or silently skipping the rule. Historical selector facts, additional evidence producers and derivative lineage remain required product work.

Kubernetes bookmarks update a separately fenced durable watch cursor. They create no policy checkpoint, audit event or evidence-rescan job, and do not renew source observation freshness. On restart, the controller loads the immutable checkpoint plus that resume cursor. Actual policy/object transitions retain their ordered checkpoints. This avoids background rescans caused solely by watch keepalives.

The catch-up SQL role cannot acknowledge either audit stream, rewrite original custody dates, alter source protection, clear restore blocking or delete work. The source role cannot advance existing catch-up jobs. Every shortening remains linked to its signed/encrypted lifecycle journal. Job completion only establishes the bounded SQL reconciliation result: The migration-00018 source read facet separately requires all earlier catch-up work, all source/lifecycle audit receipts, a fresh complete LIST/current guard, watch progress through that LIST watermark and the source restore fence. Full policy resolution additionally requires protected accepted topology. New production capture/disclosure gates must consult that barrier under their root transaction. No public route is enabled by this component.

Unit/race checks pass in `test/results/retention-catchup-unit.log`, including expired historical observations, original/later-bound policy relationships, unknown selectors, relaxed maxima and impossible readable windows. The full real SQL/S3 regression passed with exit 0 in `test/results/retention-catchup-integration-check.log` (45.860-second Go run). Eight workers competed for one-item pages over three artifacts and three checkpoints: nine visits, three exact shortening decisions, three completed checkpoints and no revival on relaxation. Unknown historical selectors roll back the page; guard mismatch, restore blocking and oversized pages fail. Bookmark persistence does not add a checkpoint or catch-up job. Tested sources remained unchanged and owned fixture cleanup completed.
