# Configuration credential provisioning

The ADR-140 configuration bootstrap breaks the credential dependency cycle
without accepting fleet configuration or recovery. It consumes actual guarded
Kubernetes fleet/owner sources, native namespace/workload protection and the
original positive SQL activation. The complete installed public graph remains
unfinished and disabled.

## Source and effect order

`RunConfigurationRoleInstaller` reads a closed private deployment document and
fixed administrator/probe/SQL files. It constructs the native protection and
fleet/owner readers, `ConfigurationRoleSource`, the protected Secret root and
`ConfigurationRuntimeSQLRoles`. The callable implementation exists; command
registration and its generated protected input producer remain pending.

The first source proof brackets three actual negative enforcement proofs with
exact namespace/guard checks and canonical fleet/owner/live Deployment/account
reads before and after. The Deployment supports one desired reconciler plus
one retained rollout process. Rechecks repeat the actual negative checks,
administrator identity, exact canonical sources/workload and before/after guard
versions. Matching object identities alone never proves unchanged enforcement.

The original operation deadline covers Claim, SQL lock acquisition, post-lock
current source read, role creation/readback, login verification and receipt
completion. Final read-only role verification and projection publication share
another explicit original operation. Operation-local reuse removes duplicated
full setup around passive GETs; it supplies no authority to another request.
Any changed/failed proof invalidates that slot. Close cancels and joins work.
UTC normalization preserves timestamp instants; it does not move deadlines.

SQL creation locks recovery then the installation, rereads the protected root
after waits, checks original claims/current sources, and consumes only a
positively acknowledged first claim. Exact lookup following an unknown result
cannot create, repair, grant, reset a password or adopt a pre-existing role.
OID, SCRAM login, provenance and direct/ambient privileges are checked. No
secrets or secret-payload digests enter SQL audit or safe diagnostics.

## Fixed role inventory

Each pool has `MaxConns=1`. Each configuration role has a cluster-wide connection
limit of three: two retained reconciler processes and one verifier. This bound
is separate from the partial public hub role allowance. Complete all-purpose
PostgreSQL budget validation remains an installed-provisioning prerequisite.

| Purpose | SQL role suffix | Projection | Effects |
| --- | --- | --- | --- |
| configuration-fleet | `_cfg_00` | `sql-fleet.json` | Fleet observation and restrictive source state; no activation/recovery writes |
| configuration-source | `_cfg_01` | `sql-configuration.json` | Pending owner configuration/source projection; no audit acknowledgement |
| configuration-audit | `_cfg_02` | `sql-audit.json` | Exact current owner-configuration receipt acknowledgement; no source acceptance or activation |

All three have bounded current-trust reads and lock privileges. The compiled
plan is authoritative for exact columns. In particular, lock privilege on an
immutable identity column does not permit lease, allocation or activation
mutation. The native SQL matrix must verify actual trigger/ACL behavior,
including PUBLIC, membership and ownership effects.

The original protected Secret is finite and mutable only through its closed
claim/receipt CAS transitions. The runtime projection is immutable, carries
`configuration-roles.json` and those three credential files, and is accepted
only after positive exact readback and original UID receipt. No audit HMAC or
artifact key is present. Existing initial installation credentials and retired
manager state are not reopened.

`NewProvisionedHubWorkerDeployment` verifies the original manifest, fixed SQL
names, current role OIDs/ACLs and one-connection pools before composing actual
reconciliation. `CurrentOwnerConfigurationAcknowledgements` locks recovery
before configuration, retains the current snapshot and shortest original bound
through COMMIT, and does not activate configuration. The legacy constructor and
command continue their prior behavior in this checkpoint. The command switch
is a required subsequent integration hunk once projections are actually
produced; it is not a permanent fallback for installed public serving.

## Actual qualification boundary

The isolated path4 source passed six-package compile and five-package vet.
Selected original-deadline, joined-close and unchanged-object negative tests
passed. Its complete-path assertion failed because the test did not pass the
deadline it asserted; that failure is retained. Path5 changes only that test
to supply the exact original deadline and passes the full loopback API path.

At unchanged production 20 QPS/burst-20 and real time, the three Claim →
post-lock read → Complete operations took 4.551993804s, 4.550681374s and
4.551830073s, each with 118 HTTP requests and nine phase/purpose negative
probes. Final inventory → immutable projection took 4.650914493s, 120 requests
and nine probes. The API, enforcement responses and role receipts in this
measurement are synthetic; source clients, Secret CAS and cancellation are
real implementation code. The remaining headroom is small and does not prove
native installed availability.

Earlier failed checkpoints remain recorded: initial root setup exhausted
4.951955789s/149 requests; the first flattening exposed timestamp readback;
UTC normalization then exposed a complete-role 4.999557525s timeout. No passing
claim replaces those failures or extends the original five-second contract.

The staged native SQL/S3/OpenBao tests cover exact grants, stale stored source
freshness with fresh independent proof, negative recovery/source state,
post-lock source change, unknown claim/completion and current audit
acknowledgement. Their source/Secret facts are explicitly synthetic. They have
compiled but have not run. Actual Kubernetes protection/Secret qualification,
combined provider path, installed command, restart/projection continuity and
public browser/MCP/capture/download journey remain required.

The reduced integration package excludes unfinished public HTTP/session/service
composition and preserves the existing command. Its extraction still needs an
integrated compile, repository contract/architecture gates and native tests;
the larger passing overlay is not proof those new integration steps passed.
