# Pending locator lifetime after framed composition

This is an isolated source candidate, not a selected runtime or qualification result. Ten new Go files are drafted under changes; no compile, race, vet or native result exists for this candidate yet.

The bootstrap-owned receiver owns a fixed finite process map (same admitted slot through prepared/sending/claimed/closing/spent states). Each entry retains the exact query and authenticated sender leaf/process, original server leaf/process, exact holder sequence and locator, private owner native operation and earliest original end. Public IDs locate only this original entry; they cannot create or repair a missing native handle. Current new TLS, independent current SQL/configuration/key and exact holder checks precede claim.

The operation root derives from the original receiver process root and the minimum of the original accepted GET socket deadline, original query end, returned native/configuration/leaf ends. It is created once before native I/O. During preparation, cancellation of the actual GET cancels/joins preparation. Before the first possible locator output, the receiver atomically records possibly-delivered and detaches/joins only that temporary GET-cancellation callback. It never derives retained lifetime from a completed Request.Context or starts a fresh five-second clock after GET. Any original process/proof/leaf expiry remains binding.

Before any possible locator output, ReserveLocator irreversibly reserves the exact regional holder sequence under the original query/socket end, without selecting metadata. Lookup alone would leave a lost GET able to rebind that standby and is insufficient. Possibly-delivered or successfully flushed GET retains both this spent socket and the original proof/map slot until exact claim or original expiry. A failed flush cannot report absence or recreate the record. A request cancelled before output closes native work and leaves only the original bounded spent marker. No lookup response authorizes metadata.

Claim atomically spends that same entry before subsequent blocking work. It verifies the exact new actual TLS client, current unchanged identity/configuration, original query/holder/sequence and original dates, then lends the one native pointer through the concrete bootstrap standby wrapper. A missing/replaced entry, changed sender, duplicate/concurrent POST, unknown prior POST or expired bound denies without reopening native work or selecting another standby. The reserved holder permits exactly one matching full request to Select that original conversation; it does not perform another lookup or claim. A later request with a different purpose cannot replace the first selected request. Neither a rejected selection nor a lost locator returns that standby to the routing set.

The locator record is sole owner of native Close. Final native observation is performed by the borrowed operation before ordinal four; the result boundary uses only its original retained final facts plus mandatory current SQL/key checks. Actual regional Receipt and EOF must finish before response admission. A failed final delivery remains spent. Closing waits for actual admitted native/stream/output work before releasing active handles; the same-slot spent marker persists to the original end. Timers perform restrictive cancellation/cleanup only, never source reads, retries or freshness refresh.

Draft, unrun tests exercise positive and lost GET delivery, request cancellation before/after possible output, duplicate/unknown claim, same sequence with replaced entry, process/key/SQL revocation, original near-expiry and slow locks, exact original native instance, response delivery cancellation, and delayed old cleanup. Actual full HWORK→B→A→R shared-client native timing is still mandatory. No rate, pool, candidate or deadline expansion is proposed.
