# Bounded syscall evidence

This adds `syscallTrace` as a typed evidence action and a reusable capture-profile building block. Inspektor Gadget traceloop is the selected integration candidate; [research](../docs/research/capture-profile-feasibility.md) documents what upstream establishes and what needs an Asservat adapter. No runtime support or overhead guarantee has been measured.

## REQ-SYS-001 — Pod-wide tracing with precise event semantics

Trace `allPodProcesses`: existing and newly created processes/threads inside the selected authorized pod, including forks/exec/reloads during the armed interval. There is no container selector or host-wide fallback. Verify pod/cgroup, namespace, process-start and node-boot identity before attribution or user-memory inspection. Exclude Asservat diagnostic workers and the sandbox process. Existing pod process/runtime ceilings still apply; cap concurrently tracked threads separately (default 4,096, portable maximum 16,384). Overflow or uncertain membership is a reported coverage gap, never scope widening.

Support `syscalls: {mode: all}` or an explicit include list of at most 128 architecture-qualified syscall names, plus result `all|errors`. Map names to the qualified kernel/ABI table; unknown names or incompatible ABI coverage fail visibly, not as a successful empty trace. Include process and thread identities, syscall name/number/ABI, entry/exit timestamps where observed, duration where paired, success/errno and approved non-pointer scalar results. Indicate unfinished, unmatched, restarted and nonreturning calls rather than inventing a duration or return value. Capture order is not a total causal ordering across CPUs/nodes.

The `metadata` mode MUST avoid user-memory argument reads, argv/environment, file paths, buffer contents, address/pointer return values and argument-derived predicates before emitting records. Metadata still receives conservative privacy classification. The qualified adapter must enforce this at acquisition, not collect everything and redact it later. No default ptrace/strace fallback or runtime injection is permitted. Unsupported node/ABI/mode combinations disable that capability.

### SC-SYS-001

Given two workers fork and exec replacements during an armed trace, when events arrive, then only current pod members are attributed with distinct process/thread start identities. PID reuse, an exiting thread or a missing entry event cannot assign the call to a replacement process. Metadata mode never reads or persists a synthetic secret passed to write().

## REQ-SYS-002 — Finite rings, loss accounting and sensitive arguments

Parameters include before/after, a segmented ring, maximum frozen bytes/snapshots, maximum retained events and event rate, tracked-thread ceiling, mode and syscall filter. At least one time window is positive; after must fit within action timeout. The shipped ongoing metadata profile defaults to before 30 s, after 10 s, four 2 MiB memory segments, maxEvents 100,000, maxEventsPerSecond 10,000, maxFrozenBytes 16 MiB, one snapshot and 20-second per-incident action deadline. The ring age is 30 seconds; its byte cap can shorten achieved history. Finite future-only variants use before: 0s. Portable ceilings: 1,000,000 retained events, 100,000 events/s, 256 MiB ring/frozen maximum, 64 segments, 60-second post-trigger window and one-hour ring age. Administrator limits may be lower. Ring history, frozen copies and parser/state buffers are independently charged under ordinary workload/node quotas; first-acquisition retention applies to ring events.

Kernel-side admission/filtering and bounded maps must limit work before user-memory reads or expensive formatting. Rate caps apply to observed eligible probe activity, not just output matching `errors`. Enter/exit probes can consume separate event units; explain the definition in provenance. Full output/ring capacity, lost perf/ring events, map overflow, truncated arguments, missed entry/exit, suppressed intervals and early stops are separate counters. Unknown loss is reported as unknown, never zero. Stop or bounded-drop under the qualified engine profile; do not block workload syscalls waiting for upload and do not promise zero overhead. Periodic circuit-breaker checks stop collection on impact limits.

`arguments` mode additionally needs explicit settings `maxBytesPerEvent` (maximum 4 KiB) and `captureBuffers` plus a reviewed sensitive-observation grant before arming. Pointer dereference and string/buffer reads are bounded by the adapter/ABI allowlist; arbitrary dereference expressions are forbidden. `captureBuffers: false` can still expose sensitive paths and argument strings and therefore is not harmless metadata. `true` permits bounded buffers only for qualified syscall adapters; never follow arbitrary nested pointers or dump a process's address space. No raw argument values enter control fields or audit.

For argument tracing, observationLimits additionally includes cumulative `maxObservedEvents`; grant status tracks observedEventsReserved/Spent. Reserve event units and requested argument-read bytes before probe processing, including attempted/faulting reads and data later filtered out. Each admitted entry or exit probe consumes one observation event unit and a conservative fixed 256-byte charge plus all requested user-memory read lengths (including failed attempts); the qualified adapter cannot undercharge larger fixed records. Reserve any larger fixed-record charge before processing. The accounting rule and adapter digest are pinned in the permit; it is distinct from wire-byte accounting for packet actions. Combined grants charge both sources against aggregate byte/session/event caps with per-source provenance. A result/errors filter may require inspecting events later discarded and does not narrow observation authority retroactively. Session restart or rolling-ring eviction never refills grant budgets.

Approved automatic policies may arm tracing under their finite matching policy grant; ad hoc argument traces require their individual matching capture grant. Metadata observation uses ordinary scoped collection permission and impact budgets unless an administrator requires more. An action's `mode` determines its minimum impact; overrides cannot label arguments as observe. No syscall evidence authorizes changing seccomp policy, sending signals or injecting calls.

### SC-SYS-002

Given a busy pod exceeds an event/ring/grant limit, when tracing continues to receive probes, then bounded admission stops or drops visibly before extra sensitive reads. Another workload retains its reserved capacity. Argument collection cannot begin while approval is pending, continue after revocation or refill observation budgets by restarting. Filtering only errors still accounts for sensitive observations of eventual successes.

## REQ-SYS-003 — Evidence, projections and MCP

Use `syscallTrace` as the manifest kind and privacy evidence type. New types default to potentially personal data and inherit configured maxima; an administrator can set a stricter syscall/argument ceiling. Records and artifact provenance include engine/decoder/ABI digests, pod/process origins, windows, mode, filters, budgets and loss. Raw arguments are encrypted raw evidence. Fixed approved metadata projections omit arguments, paths, pointers and buffers and inherit source deadlines.

`get_syscall_summary` returns bounded per-syscall counts, errors and duration aggregates over an approved projection; missing/partial pairs and gaps are explicit. `get_syscall_events` returns a paginated metadata timeline with no argument option. `syscall_query` is a bounded typed raw operation for already collected artifacts, requiring evidence:raw, current artifact rights and a matching raw-query grant. It can select syscall names/errors and return bounded recorded arguments; no arbitrary code, address dereference, live tracing or new acquisition. Add this operation consistently to raw grant/share contracts and delivery checks. Sharing a metadata projection does not grant raw argument queries or live tracing.

The guidance engine can recommend a narrow syscall include list based on the diagnostic goal (for example file errors or network calls), while explaining ABI/overhead limits. All names and recorded strings remain untrusted data. UI and external agents use the same projections and capture-profile compiler. Unsupported syscall decoders produce partial evidence; they cannot silently broaden collection into a custom command.

### SC-SYS-003

Given an argument trace with a synthetic credential buffer, when a reader asks for summary/events, then only the approved metadata projection is returned. Raw-query and raw-sharing checks remain separate and cumulative. A hostile argument string is never executed or fetched, and expired source evidence cannot be revived by a derived summary or history repeat.

## Source lifetime versus saved incidents

Under [action lifecycles](action-lifecycle.md), syscallTrace defaults to ongoing: authorize/arm its bounded source during policy activation and save on admitted triggers. Observation event/rate/thread and sensitive-read budgets run even when no trigger occurs. Snapshot limits/timeouts apply per incident; neither the 20-second default action deadline nor a trigger restarts the recorder. Stop, expiry, loss and policy-generation changes produce source gaps, with new epochs for reattachments. An explicit onTrigger variant requires before: 0s and records a finite future interval. Manual ongoing requests are finite sessions, never persistent policies.

For an ongoing source, maxEvents limits resident ring entries and each saved snapshot separately; it is not a cumulative event count that silently stops a metadata recorder after its first window. Normal ring eviction replaces old entries within the event/byte/age caps and reports shortened history. Frozen snapshots retain their separate event/byte reservations. In contrast, grant maxObservedEvents is cumulative observation spend and exhaustion stops sensitive observation. Source loss/overflow and actual safety circuit breakers still stop or degrade recording as specified.

## Approved live syscall views

[Live watch](live-watch.md) adds a bounded metadata view of an already running syscall source, separate from saved-artifact get_syscall_events/syscall_query. It uses fixed syscall/PID/error/paired-duration fields and typed display filters; no user-memory reads, argument bytes, paths, argv or speculative dereference. Unpaired events and lost/filtered/sampled rows are distinct. A viewer cannot change which processes are observed, prolong a manual session or obtain raw argument access through a live subscription. Closing/pausing the viewer leaves the source under its original acquisition authority and budgets.
