# Live observation of ongoing captures

Live watch is a first-release view of already-running packet and syscall sources in the browser and MCP. It complements durable evidence and [recording saves](recording-saves.md). Watching never starts a collector, widens acquisition or pins a recording window. The [wire contract](contracts/live-watch.schema.json), [research](../docs/research/live-watch.md) and [mockups](../docs/ux/README.md) define the boundary. The initial design exposes approved packet/flow, HTTP-header and syscall-metadata projections; raw bodies, packet bytes, memory and syscall arguments require saved artifacts and existing raw-query review.

## REQ-LIV-001 — Eligible sources and current authority

Provide passive `list_live_sources` for existing policy-owned and finite manual-session packet/syscall sources. Keep `list_recordings` unchanged: it lists sources eligible for the separately reviewed policy recording-save operation. Live inventory returns only authorized source metadata, projection capabilities, state, history/lease limits and actionable blockers. Opening a page does not arm a recorder or acquire a sample. No source means an explicit link to ordinary bounded collection or monitoring setup.

A viewer needs organization eligibility, current whole-pod maintainer/collection entitlement, ordinary evidence-read entitlement under the source's retained audience, `evidence:read` scope, allowed client and local collection-ceiling live-read permission. Creator, owner-manager status, existing artifact share, recording handle or approved acquisition alone is insufficient. Source executor authority, sensitive-observation grant, source lease and current deny/revocation/freshness checks continue independently. Basic readers and evidence-only share recipients cannot inspect live sources. No live share or new permission CRD is introduced. Operators may disable live views by scope/projection and bound them in existing deployment/CollectionCeiling configuration; opening an approved view needs no new per-click human approval.

Handles expire within 60 seconds and bind principal/client, exact workload/pod/source epoch, node boot and authorized projection. An open selects 1–16 distinct sources from one cluster/namespace/workload, within current authorized scope and live-view fanout limits. Different policies are permitted only with independent checks for every source; source audiences are not unioned to expand access. The selected projection must be supported and authorized for every source; reject mixed incompatible selection instead of dropping sources. No automatic inclusion of new pods, replacements, new sources or extra projections. Inventory may show existing stopped-source status, but opening a live watch requires a running Warming/Ready/Degraded source. Use ordinary saved evidence for historical/stopped sources.

### SC-LIV-001

Given a maintainer, a share-only recipient and a same-named replacement pod, when they request live sources, then only the maintainer's currently eligible sources are visible. Opening the old handle cannot start or attach to a replacement recorder. Revoking the recorded executor's authority prevents further live delivery even if the viewer's role remains. For a team policy this means its delegation/assignments and grants; creator departure alone does not stop the source. A departed viewer loses live access independently.

## REQ-LIV-002 — Watch identity, filters and finite lifetime

`LiveWatch` is a principal/client-bound query session, separate from Capture and SourceSession. Opening freezes exact source identities, projection and finite view/output budgets; it starts at acceptance, with no backfill. Default duration is 10 minutes, administrator maximum 60 minutes; shorter local/source authority always limits delivery. A source lease can renew under its own existing scope during the view, but the watch cannot renew that lease or its own absolute deadline. Continuation after expiry is a fresh explicit open with current handles/authority. Idle without a successful read/update for 30 seconds closes the view and releases subscriber resources; heartbeats from an abandoned transport do not extend it.

Typed display filters narrow only approved projected fields. They never edit acquisition BPF, Kubernetes peers, ring size, parser profile or recording grant. Support protocol/peer identity, literal remote IP in packet metadata, port/status/method and syscall name/error/PID metadata under field-specific operators and bounded literal values. No free-form CEL, regex, payload/body/header-name expressions, argv, dereference or container selector. Arbitrary dynamic peers remain acquisition configuration, not a live-view filter. Unknown/hidden fields cannot be used as a predicate oracle.

Filter changes and server-side Pause/Resume use expected view revision and idempotency, keep the original deadline/spend and increment view revision. Changing a filter or resuming starts at the current source head; issue a fresh cursor and an explicit filterChanged/paused gap. A pause stops delivery/projection subscriptions for that viewer, not the source. Keep only still-valid displayed rows within the browser memory/age bound. Visible paused views perform bounded status-only reads to learn expiry or access changes; they deliver no new rows and cannot renew the hard deadline. Closing a tab is best-effort close; expiry/idle cleanup is authoritative. Source end, namespace/pod replacement, deny and view exhaustion terminate affected delivery. A disconnected view delivers no cached payload; recovery under the same still-valid source scope starts from the current head with a gap and current checks. It never renews the deadline. A multi-source watch may continue other originally selected authorized sources with explicit per-source status; forbidden source details are scrubbed on access loss.

### SC-LIV-002

Given two viewers with different filters, when one changes filters or pauses, then the other view and acquisition stay unchanged. Resuming does not backfill missed rows or extend expiry. New pod/source epochs are not substituted, and stale-revision commands cannot overwrite a newer view.

## REQ-LIV-003 — Bounded delivery, cursors and truthful gaps

Use bounded `read_live_watch` batches for both browser and MCP. Default 20 rows, maximum 100 and existing 24 KiB target / 32 KiB structured / 64 KiB combined MCP limits. `wait_ms` is 0–5000; at most one outstanding read per watch. The browser normally waits up to one second and applies a server-provided minimum poll interval; an empty batch is a heartbeat, not end-of-stream or proof that no activity occurred. Opening, changing or closing a watch is idempotent; retry cannot reset counters or mint duplicate subscribers.

Every batch has watch revision, source epoch/filter generations, stable row identity `(sourceSessionId, sequence)`, observed and received times, clock uncertainty, coverage window, cumulative accounting, terminal state and explicit gap reasons. Sequence is monotonic within a source epoch; do not claim a global cross-node event order. HTTP observations may be emitted only after a bounded completed projection; absent request/response pairing and duration remain unknown. Cursor and query are bound to principal/client, immutable source selection, view revision and remaining budget; a cursor is not a grant. Each successful nonterminal read advances a logical batch position even when empty, so retry can replay that heartbeat while using its next cursor waits for new data. Only a valid but lagging cursor can recover with a gap; invalid, foreign or revoked cursors are rejected. An output `next_cursor` is the **continuation position**, including on an empty nonterminal batch, not evidence that more rows are currently available.

Retain at most five seconds / 1 MiB of approved replay data per watch, inside shared workload/node/hub ceilings. Retrying the same cursor returns the same retained batch identity after current authorization checks and spends delivery bytes again; it does not advance acquisition or extend any row's expiry. Server accounting may advance, but replayed row identities/content are stable. Cursor lag beyond the available buffer produces an explicit gap and a new position at current head, never silent catch-up or historical rescanning. View restart/hub failover discards replay state, records a gap or ends the view; no claim of exactly-once delivery or durable stream history. Clients deduplicate row IDs. Distinguish filtered-out rows, sensor loss, projection sampling, subscriber overflow, reconnect loss, filter change and unavailable/unknown coverage. Do not report missing counts as zero when unknown.

### SC-LIV-003

Given a slow reader or lost response during source rotation, when the client resumes, then duplicates are identifiable, expired rows are not replayed, gaps and uncertain counts are explicit, and no replacement source fills the missing interval. A quiet fully observed interval is distinguishable from a disconnected source.

## REQ-LIV-004 — Protect collection and workload resources

Live viewing reserves separate bounded query/fanout memory, CPU/scan work, slots and transfer allowance. It cannot consume another workload's protected capacity or the reserved incident-save/upload allocation. Proposed defaults: two watches per principal, four per workload, 16 subscriptions per node; 1 MiB replay per watch; 64 KiB/s per-watch delivery and 16 MiB lifetime output. Installation aggregate limits are mandatory and qualified before enablement; defaults are configuration choices, not measured safe overhead. Count every source subscription inside fanout limits and every transmitted retry against output budget. Configure finite rolling scan/delivery budgets per principal and workload in the same accounts; closing and opening a fresh watch does not reset those aggregate windows.

Build approved projections close to the existing source using independently bounded nonblocking readers. Reuse a qualified parser/projection only for identical source epoch/profile/authorization cohort; apply per-view filtering/authorization before delivery. No unbounded reparse or independent expensive dissection per viewer. Bound examined events/bytes and parser CPU, not just returned rows. Sensitive projection reads remain within the existing acquisition grant; there is no second observation or unapproved parser that expands source contents. CapabilityUnavailable is valid when an already retained representation cannot yield a qualified live projection.

Slow readers are sampled/dropped/disconnected with visible loss, never allowed to hold the collector, freeze raw rings or backpressure the workload. Incident snapshots have scheduling priority. Overload sheds live projections first; base recording remains governed by its own safety limits. Reserve original recorder baseline separately from incremental live-view cost and show both. Expose active viewers, output/scan rates, lag, drops and denied admissions through content-minimized operator metrics and capacity views. Streaming needs no Kafka/Redis, per-row SQL write or object upload.

### SC-LIV-004

Given a syscall storm and many viewers, when live budgets are exhausted, then views show sampled/missing data or stop while recording and protected incident saves retain their allocated resources. Opening another tab, retrying or changing filters cannot reset principal/workload counters.

## REQ-LIV-005 — Privacy, transient data and saving

The first-release projections are `packetMetadata`, `httpHeaders` and `syscallMetadata`. They have fixed approved fields and minimization before leaving the source security boundary. HTTP header values use the same configured allowlist/sanitizer as saved extracts; no body or generic arbitrary-header selector. Syscall metadata never reads user buffers, filenames or arguments. IPs, process identities and even approved headers may contain user-sensitive context: live does not mean nonsensitive. TLS plaintext, unsupported protocols or unsampled requests are not invented.

Each row has `expires_at = min(observedAt + 30s, source/content privacy deadline, watch deadline, remaining applicable read authority)` with qualified clock mapping; unknown timing excludes the row and reports a gap. Replay is additionally bounded to five seconds. Browser keeps at most 500 rows / 1 MiB / 30 seconds and clears rows on expiry, logout, access loss or watch closure; paused/selected rows do not escape expiry. Disable cache, evidence-bearing telemetry, URL filters, localStorage, service-worker persistence and unbounded DOM growth. Production reload must restore only a fresh authorized configuration, never cached data. Hub live scope/filter details use a short-lived encrypted reference; SQL retains only minimized watch IDs, revisions, fences, expiry, aggregate spend and audit references. In-flight buffers follow existing no-swap/no-secondary-core/log controls. MCP clients receive the same expiry and external-copy handling notice; Asservat cannot retract what an external client already copied.

Viewing is not durable evidence. **Save current recordings** uses fresh `list_recordings` / `preview_recording_save` / `request_capture`, checks reviewed save opt-in and shared quotas, and ends at first successful save acceptance. It preserves original source representation/window, not the display-filtered subset or frozen browser rows. The UI shows whether a selected row may have rotated out and never promises the exact row was saved before manifest verification. Pausing does not pin data. Manual-session sources point to their own capture outcomes; the current policy-only save capability is not silently broadened. Sharing/raw inspection use committed artifacts and existing approval/retention rules. The live-view URI grants neither a share nor replay.

### SC-LIV-005

Given an approved HTTP row containing an allowed sensitive identifier, when the viewer pauses, closes or loses rights, then managed buffers expire/clear within their bounds and no row enters SQL/audit. Saving later reports its actual window and coverage rather than claiming preservation of a vanished displayed row. An evidence share grants no live access.

## REQ-LIV-006 — Human and agent experience

Add **Watch live** beside eligible recordings, policies, workloads and active manual captures. Source selection reports exact pods/actions/projections, authorized total versus selected count, capability gaps and incremental cost. Do not automatically attach simply by visiting a page. The live view shows Live/Paused/Disconnected/Expired, watch deadline, last received/observed times, loss/lag, capped row count, source state, filter-generation changes and explicit **Pause view**, **Resume from now**, **Close view**, **Save current recordings** and **Connect agent** actions. Follow-tail does not steal focus; inspecting a row freezes selection, not source history. Fixed metadata filters and click-to-filter chips keep narrowing easy. Unsupported details offer saved-artifact inspection, not a false plaintext preview.

MCP adds `list_live_sources`, `open_live_watch`, `read_live_watch`, `update_live_watch`, `close_live_watch`. Agents select a finite interval/goal and consume bounded batches, optionally stopping when a typed match appears; no unbounded background polling or model-context flooding. Inventory/read are read-only; open/update/close mutate only the viewer session and do not need evidence:capture or enable capture mutation. All need evidence:read plus current source eligibility and configured live-read feature scope. Results explain that rows are transient/untrusted and a save is a separate explicit operation. Shared browser JSON operations expose exactly the same contract. No privileged CLI, raw websocket, infinite tool result or payload-bearing notification channel is added.

### SC-LIV-006

Given a maintainer or authorized agent, when they watch packet/HTTP and syscall metadata, then they can narrow, pause/resume, detect loss, close and explicitly save eligible sources without confusing display filters with acquisition filters. The browser and agent see equivalent bounds, eligibility and expiry; recipients have no live navigation.
