# Download evidence for local investigation

The maintainer requires local-tool access to **all gathered evidence**, including packet captures and cores. This supersedes the original brief's blanket prohibition on raw file export. Managed evidence remains encrypted; authorized delivery returns ordinary native files over authenticated HTTPS. Download is a common artifact operation, not a packet-only exception. See the [review correction](../docs/reviews/local-investigation.md).

## REQ-DLD-001 — Native files for every artifact

Every retained collected artifact and saved derivative MUST support authorized download in its recorded native representation. This includes sanitized or raw PCAPNG, native cores/runtime dumps, pprof and other runtime profiles, logs, files/pseudo-file snapshots, syscall recordings, command output, approved extracts and available executable/symbol companion artifacts. Unknown/new artifact kinds inherit download support: no per-kind allowlist may make bounded query support a prerequisite. A structured HTTP projection downloads as structured data, not an invented packet capture. Download cannot recover bytes excluded, truncated or lost during collection, nor expose unsaved live buffers.

Serve exact verified artifact bytes after removing Asservat's storage encryption/compression wrapper; do not require a proprietary decryptor or access to object storage/KMS. Preserve intrinsic format compression (such as a native compressed profile). Show size, format, full-file SHA-256, acquisition coverage, truncation and actual managed retention. Use safe server-generated filenames. Collected archives stay archives; do not silently execute or expand them. Optional adjacent provenance JSON is separately authorized and excludes hidden artifacts, credential material and unselected configuration.

For native cores, offer recorded architecture, runtime, executable/build identity and separately selectable existing authorized companion files. State missing/mismatched symbols and libraries before download; allow the core download anyway. Never substitute a current deployment image for the captured build, implicitly acquire new files, disclose private registry credentials or imply every runtime dump opens in GDB. Local debugger/tool choice is the user's; download is tool-neutral and requires no debugger selection. The UI describes compatible tools as optional examples, never as a supported-tool whitelist or a mandatory GDB workflow. Any named suggestion must match the recorded format, architecture and runtime; otherwise say ‘Your preferred compatible debugger’. Asservat never launches it on their workstation. Sensitive bytes in local tools remain untrusted input.

### SC-DLD-001

Given an authorized developer and saved packet, ELF core, pprof, log, syscall, file and command-output artifacts, when downloaded, then each is available in its native representation with verifiable checksum and coverage. The PCAPNG opens in Wireshark; the ELF core plus exact available executable/libraries opens in a compatible local debugger, with GDB as one representative test rather than the only supported choice. Missing symbols are explicit and do not block download. An HTTP-header JSON artifact is never mislabeled PCAP. These are required runtime tests, not results of this specification pass.

## REQ-DLD-002 — Reuse authority; review only missing raw permission

The maintainer accepts bounded permission-change handling during downloads;
immediate/per-step reconstruction of external policy is not required.
[ADR-214](../docs/decisions/214-bounded-download-policy-observation.md) permits the
protected installation download policy to be observed once and reused for at most
60 seconds from that original observation. Authentication, explicit expiry,
cancellation and current SQL permission/retention/recovery/processing/spend checks
remain independently enforced and may deny earlier. This observation bound does
not extend a request or transfer deadline and does not apply to privacy-operator
changes. The entire combined authorization decision is not reusable for 60 seconds.

[ADR-220](../docs/decisions/220-response-owned-download-permissions.md) permits one
original content response to retain its successful ordinary-entitlement decision
for at most 30 seconds from reconstruction start, recorded before I/O. It MUST
reconstruct at that cutoff, before output, and MUST discard the observation on
close or failed refresh/safety check. New GETs and preparation operations are
fresh. Current principal/client, identity, artifact/version/audience, retention,
recovery and processing checks remain; changed identity claims require fresh
scope eligibility before catalog lookup. Source freshness timestamps are never
rewritten. Each combined authority and native/delivery lease stays at most five
seconds and within every original caller/session/access bound. Current SQL
permission fences remain and MAY deny earlier; this is not a promised 30-second
revocation delay. The native response MAY consume the coordinator's exact checked
short authority through a private handoff instead of reconstructing it again.

A finite public worker-preparation operation may reuse its initial combined
authorization until the earliest original request, identity, evidence and proof
deadline, capped at five seconds. Each subsequent helper checks that retained
observation and cancellation locally; it need not repeat external identity or
catalog reads. New operations authorize again. Current SQL effect checks still
enforce permission revisions, retention, recovery, processing and spend. This
request-owned reuse neither renews a deadline nor authorizes a different scope.
The finite prepare coordinator, installed runtime and final status/metadata view
MAY consume the same original combined authority through private handoff. Current
SQL state and final identity are still checked. Each new public request MUST
construct fresh authority; an unknown effect reply MUST NOT become acknowledged
Preparing merely because its original authority is retained.

[ADR-221](../docs/decisions/221-admitted-worker-identity-enrollment.md) separates
identity enrollment from public preparation. An exact admitted worker MAY obtain
or renew its certificate under its own original request, without a connected
human preparation request. Current admitted parent, workload proof, configuration,
recovery, immutable key, finite signing and audit checks remain. Its certificate
MUST NOT confer evidence or key access: each acquisition still requires fresh
purpose-specific authority within the original worker and parent lifetimes.

Download needs current retained-artifact entitlement or explicit share coverage, no deny/restriction, current authenticated principal/client, `evidence:download`, finite transfer resources and durable audit. Ordinary artifact readers may download the actual approved artifact they can read without independent human review. An extract view does not confer access to its hidden raw parent. Existing ordinary shares that authorize reading an explicit approved artifact also authorize its native download; raw shares require explicit download coverage.

Reading already stored evidence (download preparation/transfer and approved inspection) MUST NOT depend on live capacity observations of the source workload; workload capacity gates collection only. Evidence of a deleted workload remains readable within retention, bounded by the shared acquisition worker limit, original charges, per-principal audit allowances and all authorization checks (maintainer decision 2026-10-23, [ADR-219](../docs/decisions/219-shared-approved-acquisition.md) revision).

A current processing decision MUST cover ordinary metadata reads as well as native bytes. Missing initialization, unknown restored lineage, or unsupported ancestry denies; publication or a new artifact ID cannot clear an existing artifact/workload-time restriction. Installation capacity renewal MUST NOT extend existing processing-history dates or erase a restriction when its administrative coverage expires. Release requires separate current privacy-operator authority and the exact independently acknowledged decision, not an ordinary read or capture approval. The complete installed storage/acquisition/connector/hub route and client/purpose/class policy are checked under [ADR-127](../docs/decisions/127-current-processing-and-download-placement.md); an S3 region or successful SQL lookup is insufficient. Unrelated publication does not invalidate an existing proof. An unrelated restrictive decision may conservatively interrupt a transfer, which may resume the same session under its original authority, range and spent budgets after fresh checks; no recapture or implicit preparation is introduced.

For raw artifacts, the existing per-principal/client artifact grant must explicitly cover `download_artifact`, exact existing artifact digests and sufficient cumulative plaintext output bytes. Reuse a valid covering grant without another approval. Otherwise the Download action opens the existing independent review flow with the selected artifacts and exact sizes prefilled; no manual hashes or byte arithmetic. `rawQuery` remains the stored grant-type name for artifact raw operations, now including download. The review explicitly grants disclosure of the whole file: local inspection cannot be limited to particular debugger commands after delivery. A bounded `pcap_query`, `read_memory` or collection grant alone does not authorize full-file export. The raw-request API supports the existing 1 TiB grant ceiling when download is included; other raw-query-only requests retain their prior 1 GiB request ceiling and tool-specific output caps. Multiple selected existing files can share one bounded review, while every transfer rechecks each file independently.

A one-off request may include its intended inspection and download in the same independent human review under [investigation approval](investigation-approval.md). Only verified resulting artifacts materialize exact child rawQuery grants. Collection-only grants still confer no raw access; later or uncovered needs use existing-artifact review. A regular developer with workload/raw eligibility can request download; being a team lead, evidence owner or administrator is not a prerequisite. Shares cannot authorize unrelated companion files.

### SC-DLD-002

Given an ordinary reader of a sanitized capture, a raw reader with a covering download grant, and an extract-only recipient, when Download is selected, then the first two proceed without new human review and the recipient can download only the shared extract. A query-only grant returns a prefilled missing-permission request. Repeated preparation reuses the same operation and reservation. A different principal/client cannot use the prepared transfer.

## REQ-DLD-003 — Bounded authenticated transfer and resume

Runtime readiness is consumed when checked; a transfer plan's freshness is
consumed through acknowledged session reservation. Their expiry after consumption
does not shorten later startup under a still-live original request and authority.
Expired preflight, expired/cancelled reservation and unknown replies refuse
continuation. Preserve the original session's accepted limits and absolute
access/backing deadlines, and current configuration/permission checks at effects.
See [ADR-218](../docs/decisions/218-consumed-download-preflight.md).

Use a minimized SQL `ArtifactDownload` session under C-14, referencing the exact immutable artifact/version, actor/client, authority revisions, output/read-work reservations, absolute deadline and conservative delivery counters. It is neither a new CRD nor a new plaintext evidence copy. States: Preparing, Ready, Streaming, Completed, Interrupted, Cancelled, Expired, Denied, Failed. A failed connection may enter Interrupted and resume within its original authority/deadline. Terminal cancellation/expiry/denial cannot restart. Preparation is idempotent; opaque paths are not bearer capabilities. Before verified native metadata is available, Preparing/early failure responses omit filename, format, size, checksum, ETag and coverage together; never invent a zero size or placeholder checksum. Ready/Streaming/Interrupted require that complete metadata group. Completed may omit it; if any native metadata is present, the entire verified group is required. Preparing and terminal states never advertise resume. The UI shows preparation progress and cancellation until the file is ready.

Terminal status remains readable after the transfer deadline while current identity, evidence metadata access, retained audience, retention and recovery checks still permit metadata disclosure. This status does not renew the original transfer deadline, resume authority or evidence lifetime. Expired nonterminal sessions project Expired without starting work or changing accounting; an existing Completed outcome stays Completed. A terminal-only response needs neither a live regional worker nor a native metadata cache. Status reads never dispatch, unwrap, decrypt or re-prepare evidence. Completed records the server transfer outcome and is not proof that a browser/client saved or verified the local file. A successful regional conversation must not permit the worker to poll while its completed old operation is still routeable. Its existing final zero-byte acknowledgement follows positive exact SQL-owner closure under the original deadline; scheduling delay, idempotent cleanup, absence or expiry cannot substitute for that acknowledgement. Failed or unknown closure/final delivery remains uncertain and conservatively charged.

When a native worker cannot be safely reused after an interrupted response, the console offers **Start a new download**. This explicit action first confirms restrictive Stop for the old download, then prepares one new session for the same immutable saved artifact under current covering rights. It restarts the browser transfer from the beginning and never claims to append to a browser-owned partial file. Keep the old cancellation key and new preparation key through unknown replies; retry the corresponding original operation, without repeated admission or automatic GET replacement. All old uncertain spend remains charged and new work needs existing allocation headroom. No new approval step or recapture is introduced.

Compatible authenticated clients may preserve the actual local partial-file length, original ETag and checksum, explicitly prepare a fresh session for that same artifact, and request the new content path with Range/If-Match. Require an exact 206 Content-Range before appending, reject a changed version, and verify the whole reconstructed checksum. A successful output receipt or local SQL/socket close is not proof that the remote worker received its last acknowledgement. Known failed/missing outcomes block reuse; an otherwise eligible next attempt remains subject to original finite spend and exact fresh worker progress before any key/read effect. The [retry flow](../docs/architecture/native-download-retry.md) distinguishes positive range completion, network interruption and full browser restart.

An acknowledged explicit prepare may return `continue_preparation: true` only while Preparing. The console can then continue the same key with finite backoff under the original absolute download/session bounds. Passive status never acquires this authority. Unknown replies stop automatic preparation; cancellation immediately stops continuation even if its reply is uncertain.

Stop requires current original actor/client authentication but must remain available after loss of evidence-read/download scopes. A download reserves one independently backed stop obligation before acquisition effects. Normal audit exhaustion cannot disable that already-backed restriction. The first stop fixes its request key/actor/server request ID/time; same-key replay does not spend again. A minimal `Cancelled`/`AlreadyTerminal` receipt plus `pending`/`recorded`/`overdue` audit state reveals no hidden artifact metadata or finer terminal result. Already-terminal sessions keep their original state. Restrictive fencing may precede separately encrypted audit only with a concrete bounded durable pending obligation and finite recovery/retirement; uncertain writes/spend cannot be refunded by expiry. See [ADR-119](../docs/decisions/119-public-context-download-and-prepaid-stop.md). Healthy retirement follows [ADR-124](../docs/decisions/124-prepaid-stop-retirement.md): close future Stop claims under the original lock, require actual positive joined writer completion or proof that no write was ever issued, independently verify signed/encrypted retirement and full backend absence, and preserve the original finite SQL/backup/WAL budget. A missed unclaimed audit is reported as an omission, never as recorded. Issued unknown writes remain charged. Stop retirement releases only its own backed obligation after required history cooling; it never refunds parent download or acquisition spend.

Browser/MCP share `prepare_artifact_download`, `get_artifact_download`, `cancel_artifact_download`. MCP returns bounded status/metadata and an authenticated application path, never file bytes/base64 or a presigned storage URL. An OAuth-capable local client streams the same HTTP resource outside the model transcript; a client without file-transfer support uses the authenticated browser handoff and prepares under its own client identity. Never put credentials in a command line, query string or copied link. UI uses its authenticated session. MCP cannot approve itself or select an arbitrary local path/remote destination.

`GET /api/v1/downloads/{download_id}/content` serves attachment bytes over TLS; same-origin browser checks, explicit OAuth audience/client validation, no public CORS or redirects to storage. Return safe Content-Disposition, `application/octet-stream`, `nosniff`, `Cache-Control: no-store, private`, opaque version ETag and a known native Content-Length. No HTTP content compression or proxy response buffering. Support a single byte range; reject multipart ranges. Asservat clients resume with `Range` plus the strong opaque `If-Match` ETag, returning 412 without file bytes on mismatch. Optional `If-Range` follows standard HTTP semantics: mismatch requests a full 200 response, which requires fresh authorization and sufficient accounting for the entire response. Clients must never append a 200 response to a partial file. Unknown range units follow the same fully accounted 200 fallback. If-None-Match uses weak comparison after current authorization and If-Match, with a matching GET returning 304 without file bytes; no-store still applies. Date validators are unavailable and ignored. Sessions always pin the same immutable artifact; they cannot switch to a replacement. [ADR-054](../docs/decisions/054-native-download-protocol.md) corrects the earlier nonstandard If-Range rule. Size, offset and exact version are checked before output. No successful completion is reported before integrity and exact output-length checks. The server can report bytes handed to the transport, not prove client disk persistence. Local clients verify the complete SHA-256; interruption leaves a clearly incomplete local file.

[ADR-136](../docs/decisions/136-first-context-native-content.md) requires the native HTTP preflight's encrypted operation intent and outcome to finish within their original finite interval before any representation metadata or conditional response is disclosed. This fixed HTTP-only operation is not an MCP tool and does not claim body completion; existing response/window accounting owns bytes. Current identity and artifact authority are checked again after blocking audit. Conditional selection precedes byte reservation. Browser GET never creates refresh ownership, dispatches a worker or repeats metadata preparation; authorized content decoding stays in the existing acquisition role. Failure after response headers aborts the stream after joined cleanup rather than appending an error body.

The bounded first-context composition may reuse immutable verified native metadata under fresh current authority, without caching payload, keys or credentials. Polling cannot repeatedly consume native observations until an otherwise usable session loses its content budget. Cold observation and content admission must exclude each other atomically before charging; unresolved/expired owners remain charged until positive closure. A cached fact never proves the regional worker is currently available. Cache loss or an unavailable original result does not authorize another preparation.

Raw grant maxDuration also bounds the transfer; the planner/review resolves a practical transfer allowance (30-minute default, narrowed by original access expiry and administrator limits) rather than reusing a short debugger-query or collection-action timeout. Per-query tool limits remain unchanged. Prepare reserves one transfer and worst-case requested output; resume reserves additional emitted bytes, including retransmission, without refunding uncertain spend. Default two concurrent streams per principal and sixteen per installation, further narrowed by workload/node/region budgets; downloads yield to protected incident saving/uploads. Sessions default thirty minutes, configurable up to eight hours but always clamped to artifact/grant/freshness limits.

[ADR-113](../docs/decisions/113-large-native-response-accounting.md) separates that original HTTP response lifetime from finite accounting windows and short delivery leases. A window reserves at most 64 MiB of contiguous output plus bounded read work and paired durable audit/control capacity before effects; it grants no access by itself. A fresh identity and SQL authorization lease lasts at most five seconds, capped by all original limits. Sequential application chunks are at most 1 MiB and each checks that exact unexpired lease, cancellation, version/range and prepaid remaining bytes. Several chunks may consume one still-current lease; no output occurs while obtaining the next. The private regional source may retain the same cursor and original key opening across leases within one fixed bounded conversation; a newer current lease must bind the same source/window/owner/generation and monotonically advance the existing native owner. Original operation, caller, token/certificate, worker and access deadlines remain binding. Immutable initial processing identity is not a current disclosure observation: current SQL processing/recovery and peer checks remain mandatory. Unknown renewal and failed writes stop that conversation without refund or replay. Regional worker binding may remain the immutable result of its initial full attestation within that fixed conversation, capped by its independently reviewed actual token expiry; the next window fully reattests. Kubernetes-only binding changes have bounded visibility within that original window. Each checked remote chunk carries any earlier native cutoff through final write and acknowledgement. Unknown window outcomes stay fully spent, and the next window requires the previous immutable outcome acknowledgement. Whole-response completion requires exact contiguous acknowledged progress; the legacy small-context batch ceiling must not cap supported native file sizes.

A hub-owned live reader obtains fresh short identity observations for the original connection without renewing an old observation or passing human credentials to workers. Browser GET reads the original session and never refreshes it; independently authorized refresh may update its current groups without extending the fixed session expiry. OAuth GET stops at the presented token's expiry/group-freshness bound and may resume under a new authenticated request within the original transfer/grant budget. Known authority/SQL/audit failure stops output. Bounded TLS/socket buffers mean bytes already emitted cannot be recalled. Cancellation disconnects the active stream and denies further ranges without deleting the source artifact.

Browser-native downloads read the current browser session and never refresh it. Under [ADR-224](../docs/decisions/224-remove-download-refresh-owners.md) (superseding ADR-114) the Download/prepare POST is the ordinary audited operation, as for MCP, and admits no server-side refresh owner. When the session, token or group freshness is no longer current, the content GET fails closed (a session that is only busy because another request is refreshing it is retried without output for at most two seconds) and the console resumes with Range after its own explicit refresh, within the original transfer, grant and session deadlines. Known limitation: a long download whose console tab is closed or frozen stops when the session next needs refreshing; reopening the console and resuming continues it. Browser tab closure is distinct from cancellation of the actual download connection.

The regional acquisition role has a distinct download-only Job template: exact-object read/unwrap authority, verified streaming decrypt/decompress, bounded memory, no target code/parser/debugger execution and no plaintext scratch. It does not require the offline analyzer's PVC path to be available. Transfer data uses separate bounded transient relay I-13 through configured connector/hub routes; no file content in SQL/outbox/logs or retry caches. Hub/API relay has no unwrap key. All relay locations must be permitted for that artifact; an unapproved location is an explicit blocker. Authenticate encryption segments before emitting plaintext and validate final digest/length. For a full-file transfer, withhold the final bounded delivery batch until those final checks pass; after all Content-Length bytes have been emitted, a server-side error alone cannot reliably signal an incomplete download. A partial range verifies its authenticated indexed frames and exact range length; the client still verifies the full checksum when assembling a resumed file. Resuming compressed/encrypted formats must bound reread/decode work; qualify seeking or visibly offer an authorized full restart where a bounded resume is unavailable. Never advertise cheap random access over an unqualified format. New work uses the distinct internal `downloadArtifact` purpose.

### SC-DLD-003

Given a multi-GiB core transfer interrupted mid-file, when resumed, then current rights, immutable version and cumulative bytes are rechecked, exact range bytes are returned, and the completed file matches its full checksum. Revocation, source expiry, short authority-lease loss, exhausted quota, changed object identity, invalid ranges and corrupt ciphertext stop delivery. Duplicate requests, parallel readers and slow clients stay within reservations; concurrent downloads do not starve incident uploads. Logs/caches/SQL contain no artifact body.

## REQ-DLD-004 — Visible download UX and external-copy limits

Every artifact viewer and artifact list offers Download or an actionable reason it is unavailable. A missing raw grant opens the prefilled review; a covering grant starts without redundant review or a generic confirmation modal. Show native type/size, optional companion files, integrity/coverage and a concise persistent notice: “Downloaded copies are outside Asservat's automatic deletion. Follow your organization's handling and deletion policy.” Do not force a checkbox or claim DRM, remote erasure, local encryption or expiry after bytes leave the service. Local tools need ordinary readable bytes; managed storage encryption remains mandatory.

Record preparation, authorization, emitted/uncertain bytes, cancellation and outcome in minimized durable audit. Successful HTTP delivery is not proof of local analysis or deletion. The managed copy ledger tracks actual server buffers/staging obligations and source copies, not a fabricated verified-deletion state for a developer's laptop. Source expiry still blocks new/resumed delivery and cleans managed copies on schedule. This is an ordinary investigation workflow, separate from privacy-rights responses.

### SC-DLD-004

Given an unfamiliar non-lead developer, when asked to investigate a saved packet capture or core using a local tool, then they can find Download, obtain only missing authorization, get native files plus any selected exact companions, and explain both coverage and the local-copy deletion responsibility. Repeat for every collected kind and an otherwise ineligible share recipient. Validate with actual files/tools and users, not only an internally consistent screen walkthrough.

## Implementation boundary: initial context control

The private [context download coordinator](../docs/architecture/context-download-control.md) implements original-key preparation/status orchestration and fresh SQL metadata observations for approved pod-status. Normal acknowledged worker startup may use finite automatic same-key preparation continuation while the initiating view/session is active; it does not require another click at the five-second observation boundary. Status reads stay read-only. Unknown replies preserve the original key, and post-ready metadata loss never silently re-decrypts or creates another session.

The private [regional result owner](../docs/architecture/context-download-result.md) retains one exact verified metadata result after acknowledged preparation, before the original first-response gate. A later authorized request can read those facts without another native read, unwrap or batch; unknown acknowledgements never create a readable result. Original worker/process/session identity and monotonically shortened lifetime remain binding. Closing cancels work and joins active calls before releasing the owning slot.

These components do not enable public download operations. Protected transfer allocation/environment producers, the actual regional native-work/result channel, cancellation/audit composition and native attachment relay remain prerequisites. SQL stores no native file metadata, bytes or unwrap keys. The [implementation record](../docs/implementation-progress.md) distinguishes passing real SQL/S3 coordinator checks from the result owner's synthetic authority/proof tests. Neither proves a complete installed native-download workflow.

Current download worker identity, enrollment/certificate activation, native parent operations and byte-window leases MUST reject retained audit acknowledgements without an immutable nonempty, non-`null` version. Existing wire/history bytes are preserved. Historical decoding MAY support cancellation, recording already performed I/O and independent retirement, but MUST NOT supply current disclosure or signing authority, renew a receipt, or fabricate a version.

[ADR-244](../docs/decisions/244-native-artifact-types.md) adds the artifact-type registry (PCAPNG `application/x-pcapng` `.pcapng`, syscall records as JSON Lines `.jsonl`, the HTTP header projection as JSON `.json`, pod status unchanged), server-generated filenames `artifact-<uuid><extension>` and coverage text that includes recorded history and window coverage, and native range delivery of multi-frame artifacts up to the 256 MiB streaming bound through the existing windowed transfer, HTTP sink and If-Match/If-Range resolver. Content-Type stays `application/octet-stream`; the native media type is part of the verified manifest. It is qualified at component level only (synthetic keys, identity, authority and session ledger); the installed worker exchange is pod-status-only until increment 4.
