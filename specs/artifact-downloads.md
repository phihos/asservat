# Download evidence for local investigation

The maintainer requires local-tool access to **all gathered evidence**, including packet captures and cores. Managed evidence remains encrypted; authorized delivery returns ordinary native files over authenticated HTTPS. Download is a common artifact operation, not a packet-only exception. Timescales and approvals follow [ADR-335](../docs/decisions/335-usable-by-default.md) D5, D9 and D17.

## REQ-DLD-001 — Native files for every artifact

Every retained collected artifact and saved derivative MUST support authorized download in its recorded native representation. This includes sanitized or raw PCAPNG, native cores/runtime dumps, pprof and other runtime profiles, logs, files/pseudo-file snapshots, syscall recordings, command output, approved extracts and available executable/symbol companion artifacts. Unknown/new artifact kinds inherit download support: no per-kind allowlist may make bounded query support a prerequisite. A structured HTTP projection downloads as structured data, not an invented packet capture. Download cannot recover bytes excluded, truncated or lost during collection, nor expose unsaved live buffers.

Serve exact verified artifact bytes after removing Asservat's storage encryption/compression wrapper; do not require a proprietary decryptor or access to object storage/KMS. Preserve intrinsic format compression (such as a native compressed profile). Show size, format, full-file SHA-256, acquisition coverage, truncation and actual managed retention. Content-Type stays `application/octet-stream`; the native media type is part of the verified manifest. Collected archives stay archives; do not silently execute or expand them. Optional adjacent provenance JSON is separately authorized and excludes hidden artifacts, credential material and unselected configuration.

The server names every file from recorded provenance: `<workload>-<pod>-<time>.<ext>`, where `<time>` is the acquisition start in UTC as `20261114T081500Z` and `<ext>` comes from the artifact-type registry ([ADR-244](../docs/decisions/244-native-artifact-types.md): PCAPNG `.pcapng`, cores `.core`, syscall records JSON Lines `.jsonl`, HTTP header projection `.json`). When two artifacts of one case would share a name, the second and later ones append `-<first 8 hex digits of the artifact ID>`. Names contain only `[A-Za-z0-9._-]` (other characters become `_`) and are at most 200 bytes, truncating the workload and pod parts first (file-name components are limited to 255 bytes on Linux `NAME_MAX`, NTFS and APFS; 200 leaves room for suffixes such as `.core.tar` and the disambiguator). Clients never choose the name.

### Debugger-ready core bundle

A native core download offers **Core bundle** as its default: one uncompressed POSIX tar named `<workload>-<pod>-<time>.core.tar`. Its single top-level directory `<workload>-<pod>-<time>/` contains:

| Member | Content |
| --- | --- |
| `<workload>-<pod>-<time>.core` | The core |
| `sysroot/<recorded absolute path>` | The executable and every available mapped library, at the paths the process mapped them |
| `debug/.build-id/<xx>/<rest>.debug` | Available separate debug files, keyed by build ID |
| `gdb.cmd` | `set auto-load off`, `set sysroot ./sysroot`, `set debug-file-directory ./debug`, `file`, `core-file` |
| `dlv.sh` | Present only for Go executables: `dlv core sysroot/<executable> <core>` |
| `README.txt` | Recorded architecture, runtime and build identity, how to start the debugger, and each missing or mismatched file |
| `SHA256SUMS` | The verified SHA-256 of every member |

Members are regular files with relative paths and no links; member paths can exceed the 100+155-byte ustar fields, so the tar uses pax extended headers for long paths; the generator derives every path and script line from verified provenance, escapes it and rejects `..`. The bundle contains only existing companion artifacts the caller may download; it never acquires new files, substitutes a current deployment image for the captured build or discloses registry credentials. Missing companions are listed before download and in `README.txt` and do not block the bundle. The tar is deterministic, so its Content-Length and strong ETag are known before the first byte and Range resume works as for a single file. The core and each companion also remain individually downloadable.

Local debugger choice is the user's. `gdb.cmd` and `dlv.sh` are conveniences for the recorded format, architecture and runtime; the UI calls other compatible tools ‘Your preferred compatible debugger’ and never implies every runtime dump opens in GDB. Asservat never launches a tool on the workstation. Sensitive bytes in local tools remain untrusted input.

### SC-DLD-001

Given an authorized developer and saved packet, ELF core, pprof, log, syscall, file and command-output artifacts, when downloaded, then each is available in its native representation with a meaningful name, verifiable checksum and coverage. The PCAPNG opens in Wireshark. Extracting the core bundle and running `gdb -x gdb.cmd` (or `dlv.sh` for a Go core) opens the core with its executable and libraries without manual sysroot setup; GDB is a representative test, not the only supported choice. Missing symbols are explicit and do not block download. An HTTP-header JSON artifact is never mislabeled PCAP. These are required runtime tests.

## REQ-DLD-002 — Reuse authority; review only where required

Each content GET authenticates its caller as the download session's principal and completes one full authorization before its response starts: identity, ordinary entitlement or share, retained audience, raw result access, processing restriction, retention and delivery policy ([ADR-311](../docs/decisions/311-operation-authority-recheck.md), [ADR-330](../docs/decisions/330-event-driven-system-design.md) D5). Per [ADR-312](../docs/decisions/312-started-downloads-run-to-original-bounds.md) the started response then reads no identity, permission, share or policy again and runs until one of its original bounds ends it: the download session's `AccessUntil` (the effective retention end, narrowed to an admitting share's or grant's end), an effective retention cut-off or managed deletion, explicit Stop, or the requested range. Expiry of the caller's access token or browser session after the response started does not end it. Retention cut-offs, deletion and Stop reach the stream as events (PostgreSQL `LISTEN/NOTIFY` cancels its context); they are not read per chunk. Permission, share and processing changes take effect at the next response start.

The installation download policy comes from a watched ConfigMap. The cached policy stays valid until the watch replaces it; a watch failure makes it unavailable until the relist completes (ADR-330 D1). Prepare and status requests reuse their operation's authorization for at most `identity.AuthorityRecheckInterval` (30 s), never past the original request deadline; each new public request authorizes again.

Download needs current retained-artifact entitlement or explicit share coverage, no deny/restriction, an authenticated principal, `evidence:download` for OAuth clients, reader capacity and an audit row. Ordinary artifact readers download the approved artifacts they can read without review. An extract view does not confer access to its hidden raw parent. Ordinary shares of an explicit approved artifact also authorize its native download; raw shares require explicit download coverage.

A raw artifact (raw packets, cores, raw syscall arguments, memory) downloads without another person's review when any of these holds (ADR-335 D5):

1. The caller holds the equivalent Kubernetes right on the recorded workload's namespace under [permission management](permissions.md): `pods/exec` for raw packets, cores, syscall arguments and file snapshots; `pods/portforward` or `pods/proxy` for runtime profiles.
2. A covering grant exists for the caller: the reviewed result access of the policy that collected it, a one-off investigation approval that included download ([investigation approval](investigation-approval.md)), or an earlier raw grant with `download_artifact` for that artifact.

Otherwise Download opens the independent review flow with the selected artifacts and exact sizes prefilled; no manual hashes or byte arithmetic. The review grants disclosure of the whole file: local inspection cannot be limited to particular debugger commands after delivery. A bounded `query_artifact` grant or a collection-only grant does not authorize full-file export. A grant covering download defaults to the artifacts' `AccessUntil`, capped by the administrator maximum. Raw sharing to another person still needs independent review. Being a team lead, evidence owner or administrator is not a prerequisite to request download.

Reading stored evidence (download preparation/transfer and approved inspection) MUST NOT depend on live capacity observations of the source workload; workload capacity gates collection only. Evidence of a deleted workload remains readable within retention, bounded by regional reader concurrency, per-principal limits and authorization (maintainer decision 2026-10-23). For a deleted workload or namespace, rule 1 uses the namespace's current RoleBindings; when the namespace is gone, only rule 2 applies.

A processing restriction (privacy restriction of an artifact or workload) is a flag on the artifact/workload rows and is checked in the same SQL query as the rest of the authorization; it covers ordinary metadata reads as well as native bytes. Publication or a new artifact ID cannot clear an existing restriction. Release requires current privacy-operator authority, not an ordinary read or capture approval. Storage, reader and connector placement is static Helm configuration and is not re-verified per request. A restrictive decision applies from the next content response start.

### SC-DLD-002

Given an ordinary reader of a sanitized capture, a namespace member with `pods/exec` reading a policy-collected core, a raw reader with a covering grant, and an extract-only recipient, when Download is selected, then the first three proceed without new human review and the recipient can download only the shared extract. A caller with neither the Kubernetes right nor a covering grant gets a prefilled review request. Repeated preparation with the same idempotency key returns the same session. A different principal cannot use the prepared transfer.

## REQ-DLD-003 — Authenticated transfer and resume

An `ArtifactDownload` session is a SQL row referencing the exact immutable artifact version (or the bundle's member versions), principal, idempotency key, `AccessUntil`, emitted-byte counter and outcome. It is neither a CRD nor a plaintext evidence copy. States: `Preparing`, `Ready`, `Completed`, `Failed` (with reason such as `Expired`, `Denied`, `Integrity`) and `Cancelled`. `Preparing` lasts only until the regional reader has opened the artifact and returned its verified native metadata (filename, format, size, checksum, ETag, coverage); before that the response omits the whole metadata group and never invents a size or checksum. An interrupted connection leaves the session `Ready`; the client resumes with HTTP Range at any time until `AccessUntil`. There is no request-count limit on resumes. `Completed`, `Failed` and `Cancelled` are terminal. Opaque paths are not bearer capabilities.

Preparation is idempotent under its key ([ADR-330](../docs/decisions/330-event-driven-system-design.md) D7): a retry with the same key returns the existing session. Prepare normally returns `Ready` in the same request. When it returns `Preparing`, the browser follows the session on the page's Server-Sent Events stream and MCP `download_artifact(action=status)` waits server-side (at most 30 s) for the next state change; both are woken by `NOTIFY` on the session row. Status reads never dispatch, unwrap, decrypt or re-prepare evidence and are never charged. Every status, including terminal ones, returns the artifact's verified size and SHA-256 from the catalog while the caller may read the artifact's metadata. `Completed` records the server transfer outcome and is not proof that a client saved or verified the local file.

Stop (`download_artifact(action=cancel)`) requires the original principal to be authenticated but remains available after loss of evidence-read/download rights. It is an idempotent SQL update of the session to `Cancelled`, one audit row and a `NOTIFY` that closes any active response. Already-terminal sessions keep their state and return `AlreadyTerminal`; the receipt reveals no hidden artifact metadata.

Browser and MCP share one operation, `download_artifact` with `action=prepare|status|cancel`. MCP returns bounded status/metadata and two links, never file bytes/base64 or a presigned storage URL: `content_path` (`/api/v1/downloads/{download_id}/content`) for clients that can stream an authenticated HTTP resource to disk, and `browser_url` (`/downloads/{download_id}`), a console page the user opens in a signed-in browser. When the browser is signed in as the same human, that page downloads the same session under the browser session without another consent or approval; another principal gets the ordinary not-found response. Never put credentials in a command line, query string or copied link. MCP cannot approve itself or select a local path/remote destination.

`GET /api/v1/downloads/{download_id}/content` serves attachment bytes over TLS and accepts either the same-origin browser session cookie or an OAuth bearer token for the installation's single protected resource ([REQ-MCP-004](mcp.md#req-mcp-004--oauth-and-untrusted-evidence)); no public CORS or redirects to storage. Return safe Content-Disposition with the generated filename, `application/octet-stream`, `nosniff`, `Cache-Control: no-store, private`, opaque version ETag and a known native Content-Length. No HTTP content compression or proxy response buffering. Support a single byte range; reject multipart ranges. Clients resume with `Range` plus the strong opaque `If-Match` ETag, returning 412 without file bytes on mismatch. Optional `If-Range` follows standard HTTP semantics ([ADR-054](../docs/decisions/054-native-download-protocol.md)): mismatch yields a full 200 response. Clients must never append a 200 response to a partial file. Unknown range units follow the same 200 fallback. If-None-Match uses weak comparison after authorization and If-Match, with a matching GET returning 304 without file bytes; no-store still applies. Date validators are unavailable and ignored. Sessions always pin the same immutable artifact version. Size, offset and exact version are checked before output. The server can report bytes handed to the transport, not prove client disk persistence. Local clients verify the complete SHA-256; interruption leaves a clearly incomplete local file.

A content GET that returns bytes writes one audit row in its authorization transaction and records its emitted bytes and outcome on the session row when it ends; 304 and 412 responses disclose no bytes and write no audit row (ADR-330 D6). Failure after response headers aborts the stream rather than appending an error body.

The long-running regional reader (A-READ, [REQ-EVD-005](evidence.md#req-evd-005--analysis-isolation-and-output-classes)) receives the authorized download over its connector stream and streams the exact object range. It unwraps the artifact's keysets from the key service under its own mTLS identity; the AEAD binding limits each unwrap to that artifact attempt, so no per-download ticket, Job or key slot exists. Delivery uses verified streaming decrypt/decompress with bounded memory, no target code/parser/debugger execution and no plaintext scratch. Bytes flow from the reader over its hub connection to the HTTP response with ordinary flow control (`io.Copy` under the response context); no file content enters SQL, logs or retry caches, and the hub has no unwrap key. All configured reader/hub locations must be permitted for that artifact; an unapproved location is an explicit blocker. Authenticate encryption segments before emitting plaintext and validate final digest/length. For a full-file transfer, withhold the final bounded delivery batch until those final checks pass. A partial range verifies its authenticated indexed frames and exact range length; the client verifies the full checksum when assembling a resumed file. A Range request starts at the frame containing its offset; resume never rereads earlier frames. A bundle streams its members in order through the same path.

A raw grant counts each artifact version once per principal: the first response start that discloses bytes of that version charges its native size against the grant, and later resumes, repeated downloads to another machine and the bundle copy of a member charge nothing further. Per-query raw tool limits are unchanged. Fairness limits are separate counters: installation concurrency is the reader replicas times the per-replica stream limit, whose default is the reader memory request ÷ the per-stream buffer, narrowed by workload/region bandwidth budgets; each principal may use a fair share of max(2, installation concurrency ÷ 4) concurrent streams; downloads yield to incident saving/uploads. A bundle counts as one stream.

Browser content GETs read the current browser session at response start and never refresh it ([ADR-224](../docs/decisions/224-remove-download-refresh-owners.md)); the prepare POST is the ordinary audited operation, as for MCP. Bounded TLS/socket buffers mean bytes already emitted cannot be recalled. Cancellation disconnects the active stream and denies further ranges without deleting the source artifact. Browser tab closure is distinct from cancellation of the download.

### SC-DLD-003

Given a multi-GiB core transfer over a slow link that outlives the caller's five-minute access token, when the token expires mid-response, then the response continues to completion. Given the same transfer interrupted mid-file and resumed the next day, then current rights and the immutable version are checked at the new response start, exact range bytes are returned, the raw grant is not charged again, and the completed file matches its full checksum. Revocation before a response starts, `AccessUntil`, the effective retention cut-off, deletion, Stop, changed object identity, invalid ranges and corrupt ciphertext stop delivery; a permission change after a response started does not (ADR-312). Parallel readers and slow clients stay within fairness limits; concurrent downloads do not starve incident uploads. Logs/caches/SQL contain no artifact body.

## REQ-DLD-004 — Visible download UX and external-copy limits

Every artifact viewer and artifact list offers Download or an actionable reason it is unavailable. A core offers **Core bundle** first and its single files under it. When review is required, Download opens the prefilled review; otherwise it starts without a confirmation modal. Show native type/size, generated filename, bundle members and missing companions, integrity/coverage and a concise persistent notice: “Downloaded copies are outside Asservat's automatic deletion. Follow your organization's handling and deletion policy.” Do not force a checkbox or claim DRM, remote erasure, local encryption or expiry after bytes leave the service. Local tools need ordinary readable bytes; managed storage encryption remains mandatory.

Audit rows record preparation, each byte-returning response start, emitted bytes, cancellation and outcome. Successful HTTP delivery is not proof of local analysis or deletion; Asservat makes no verified-deletion claim for a developer's laptop. Source expiry still blocks new/resumed delivery and cleans managed copies on schedule. This is an ordinary investigation workflow, separate from privacy-rights responses.

### SC-DLD-004

Given an unfamiliar non-lead developer with `pods/exec` on a workload, when asked to investigate a saved packet capture or core using a local tool, then they find Download, receive a meaningfully named file or core bundle without another person, and can explain both coverage and the local-copy deletion responsibility. Repeat for every collected kind, for a developer without the Kubernetes right (one prefilled review) and for an otherwise ineligible share recipient. Validate with actual files/tools and users, not only an internally consistent screen walkthrough.
