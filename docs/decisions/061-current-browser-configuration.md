# ADR-061 — Current protected browser configuration

Date: 2026-10-10. Status: implementation refinement of ADR-060; production bootstrap and recovery qualification remain open.

Browser ingress must not use a permanently enabled SQL root created by installation scripts. Administrator-owned Kubernetes configuration remains the source of session settings. A pinned ConfigMap carries the closed [browser-settings contract](../../specs/contracts/browser-settings.schema.json), with no credentials, independently of the existing identity/group policy. A separate observer projects a complete read into SQL for at most five seconds measured from the source read. Failed observations fence the preceding projection; an older failure cannot disable a newer successful observation. Ingress cannot renew or modify this configuration.

The projection pins source UID, monotonic revision/digest, installation session root, epoch, issuer, client and browser origin. Replacements and revision rollback require explicit reconfiguration; a same-revision content change is rejected. Changing issuer, client or origin requires a new epoch. Previously used epochs cannot return. Migration 00021 disables unqualified roots; first qualification removes their old login challenges and sessions. This migrates no credentials into trusted authority.

Finite administrator ceilings cover pending logins, retained sessions, logout receipts and absolute session lifetime. Lowering the lifetime shortens every existing session from its original creation time. Raising it permits longer new sessions but cannot extend a retained session. The observer performs shortening in the same bounded transaction as accepting the new maximum. A timeout rolls back the configuration update; the previous five-second lease still expires. Large-installation throughput qualification remains required.

Session identity, login and refresh require current configuration before and after blocking SQL work. Local CSRF-only lookup and revocation, signed provider logout and bounded expired-state cleanup remain possible during suspension or a settings-source outage, within their exact epoch and existing session deadlines. These paths return no identity or evidence and create no session authority. This keeps sign-out usable during an incident.

The implementation carries that original configuration deadline out of SQL in a transient session observation. Identity handoff intersects it with fixed session and token/policy expiry, including after callback session creation. CSRF-only reads have no such observation. This closes the application handoff without adding a stored lease, changing the session lifetime or extending any configuration observation.

Bootstrap must qualify the protected namespace, exact ConfigMap UID, provider/client endpoints, private credentials and restoration epoch before opening production ingress. Current settings reads are not evidence of a safe database restore. No directory-reader account, offline user token, alternate permission-management HTTP API or new service dependency is introduced. See [browser sessions](../architecture/browser-sessions.md) for the integration evidence and remaining composition.
