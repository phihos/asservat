# ADR-133: Close managed setup copies after positive original retirement

Status: accepted implementation direction; staged implementation and native qualification pending.

The original fixed command chain can create its manager, initialize the embedded schema, activate its original Pod and retire setup authority. Its v2 guard deliberately retains the SQL/provider source Secret copies and broad seed. Final installation must remove those managed copies after positive closure without changing the original authority or requiring operators to author dynamic pins.

Select `asservat-initial-bootstrap/v3` only for a positively fresh installation. It includes the closure capability and a distinct public denial marker from original guard installation. Existing v1/v2 guard bytes and deletion denial remain unchanged. The command recognizes a retained v2/v3 seed through exact bounded metadata. It can also recover a complete pre-seed prelude of that exact version through original public object shapes/UIDs, compiled guard identity and independent native denial. Partial unprotected preludes, unknown reads and contradictory objects remain unavailable; they never select a newer version. This boundary does not establish historical namespace cleanliness.

After complete original handover, independently read activation history and positively observe the original manager's privilege/login/session closure. Join owned setup work. Persist one public cleanup claim with original installation/root/seed/history/copy identities and a once-created fifteen-minute interval. Every attempt remains at most two minutes, observations remain at most five seconds, and retries retain the original claim and dates. Actual expiry needs separately qualified recovery; elapsed time cannot complete cleanup or restart the clock.

Install a separate permanent tombstone policy and binding under two original create claims. Only an acknowledged first claim may issue its CREATE. Unknown replies permit exact lookup only. Independently verify the unchanged original guard and the exact tombstone's native denial through its dedicated observation marker before touching copies. The product never replaces, broadens or removes the original v3 guard. The tombstone denies recreation of both fixed names, including administrator CREATE, while its protection remains installed. Kubernetes excludes admission policies/bindings from VAP evaluation: trusted installation administrator/RBAC ownership retains these guard objects, not another VAP. Runtime/probe roles gain no policy mutation rights. Missing, replaced or changed protection fails every subsequent effect and completed replay without recreation/adoption. This does not resist trusted Kubernetes administrator or cluster-admin sabotage.

For each original immutable copy, add only its exact closure annotation through UID/resourceVersion CAS, persist the returned original UID/version, then delete that exact object. A retained positive absence receipt requires current guards; a timeout, replacement or expired claim is insufficient. Finally, atomically replace the seed's private data with fixed `retired:true`, set immutable, and add its once-set final receipt. Admission couples those fields. Replay reads only PartialObjectMetadata and the exact retained history-only bundle, verifies protected completed history and both guards, and never recreates credentials or copies.

This removes only Asservat's two setup input copies and broad seed payload. It does not revoke operator-owned upstream credentials, remove operator originals, erase Go memory or guarantee erasure from Kubernetes/etcd backups. The retained history-only credential and public provenance remain purpose-scoped. Official Helm packaging and public runtime enablement remain separate qualification work.

See the [implementation contract](../architecture/initial-bootstrap-copy-closure.md) for ordering and unresolved crash cases.
