# ADR-064 — Versioned local key material and provider-neutral credential envelopes

Date: 2026-10-10. Status: engineering refinement implementing the maintainer-approved small-deployment alternatives in ADR-063. Crypto backends are implemented; authenticated key-service runtime, bootstrap and operational qualification remain pending.

Keep `asservat-framed/v1` and its Tink data/index/manifest encryption unchanged. Add a local wrapping provider using the existing Tink Go library's XChaCha20-Poly1305 AEAD implementation. Its library-generated 24-byte random nonce avoids introducing a persistent application nonce counter for a long-lived wrapping key. Asservat implements no cipher, MAC or nonce generator. This provider encrypts only bounded keysets, not bulk evidence. This choice does not assert FIPS qualification. [Tink AEAD guidance](https://developers.google.com/tink/aead), [pinned API](https://pkg.go.dev/github.com/tink-crypto/tink-go/v2@v2.8.0/aead/subtle#NewXChaCha20Poly1305).

The private `asservat-local-keys/v1` Secret payload contains one installation/purpose/key identity, one active version and at most sixteen unique 32-byte key versions. Protected wiring supplies the expected scope separately. Closed JSON, byte caps, exact member names, canonical base64, present active version, distinct versions/material and nonzero material are enforced before construction. Randomness comes from bootstrap; parsing cannot prove entropy. No default, lazy key generation, filesystem search or environment fallback. The [schema](../../specs/contracts/local-key-secret.schema.json) describes this sensitive private payload; it is not an identity/permission CRD or a chart value.

Local wrapping references bind provider format, installation, purpose, key ID and immutable decimal version. Canonical associated data binds that exact reference and SHA-256 of the existing canonical artifact/session binding. Full references must match a configured key before decryption. Purpose-specific roots and role isolation remain required even though associated data also rejects cross-purpose substitution. Rotation uses a new immutable snapshot and preserves required retained versions; lifecycle retirement and anti-rollback acceptance remain the service/installer's responsibility.

The separate policy-submission signer uses the standard Go Ed25519 implementation with a configured active version and independently pinned public key. It supports only the existing pure Ed25519 JWS mode, bounded input and cancellation; historical versions cannot become active merely because their material remains in the Secret. Existing signature types, trust epochs, verification deadlines and independent authorization do not change.

Browser credential envelopes now consume the existing `KeySealer` / `KeyOpener` ports rather than concrete OpenBao client types. Their encrypted format and binding stay unchanged. Both local crypto backends hold private/root material and belong only in the future isolated key-service role. Interface method sets are not a security boundary. No hub, collector, publisher or acquisition production wiring receives these local backends directly. The authenticated remote facets, current scope/effect authorization, PKI, credential delivery and durable key lifecycle must be completed before small mode is enabled.

Implementation/tests and remaining limits are recorded in [local key foundation](../architecture/local-keys.md). No new dependency, SQL migration, listener, Helm runtime switch or collection authority is introduced.
