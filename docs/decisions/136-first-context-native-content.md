# ADR-136: First approved-context native HTTP composition

Status: accepted for implementation; staged qualification remains incomplete.

The first approved pod-status result needs one working path from its accepted
allocation and worker to an authenticated native HTTP response. Existing SQL42
response/window accounting, SQL45 regional exchange, SQL46/47 prepaid Stop and
SQL50 current path/processing checks remain authoritative. This increment does
not enable public collection or a listener and does not qualify large native files.

Use the unique existing current allocation matching root, cluster, namespace and
workload, checking ambiguity before backing. Protected constructor inputs provide
finite per-session ceilings. Read the separately accepted control, native and Stop
backing without provisioning or renewing it. Preserve the earliest absolute backing
end in the private plan and intersect the reserved session deadline with it; all
short observation bounds survive blocking reads. There is no new source framework.

The concrete runtime uses the actual dispatcher, request-owned enrollment,
original SQL worker/preparation, native registrar and current authority. A legitimate
unchanged Job awaiting its sole Pod produces a typed Pending result. Only the
existing bounded same-key prepare POST may continue startup. Unknown creation,
mutation, foreign or terminal Pods never become Pending. The first-context preparation
adapter atomically admits only the original Preparing session with no prior attempt;
unknown preparation cannot start another decrypt or key attempt. Generic deliberate
re-preparation semantics remain separate.

The regional process retains immutable verified metadata under its original
lifetime. A hub cache holds at most sixteen exact session/worker/preparation/path
metadata entries, without payload, keys, credentials or authority. Each disclosure
still checks current identity, C03 and SQL. Warm status polls cost no NativeObserve
updates. A cache miss can only observe the positively committed original result.
Process loss, unknown conversation closure or lost regional cache never re-prepares.

First-context Observe and BeginResponse adapters both hold the original session
lock. Observe excludes every unclosed response and requires five remaining native
updates; BeginResponse excludes every unclosed native owner and requires three.
The minimum eight-update backing supports preparation claim/close (2), one cold
Observe claim/close (2), content claim/close (2), final proven retirement (1), with
one spare update. Unknown closure remains charged and exclusive after lease expiry.
The installed constructor requires both adapters. Cache pins remain until the
actual response/source closes and joins. Cached metadata does not prove liveness
or make a known uncertain owner downloadable.

The native GET uses exact HTTPS origin, separate cookie/bearer authentication,
original principal/client and token/session limits. Browser GET never refreshes
credentials or creates refresh ownership. The separately pinned download bearer
resource is advertised by fixed protected-resource metadata. No token or identity
is serialized into the worker command; the acquisition worker performs the existing
exact-object authorized read/unwrap, while the hub has no unwrap capability.

The HTTP-only `download_artifact_content` normal-lane audit intent precedes metadata
work. Its finite preflight outcome must be acknowledged before metadata/conditional
headers or body reservation, followed by a current authority recheck under the
original interval. It records no body completion. Response/window audit retains
byte and whole-response outcomes. SQL53 adds only the fixed audit classifiers;
public MCP tool allowlists and historical audit bytes are unchanged.

Standard conditional/range selection precedes reservation. A fresh identity batch
may follow positively joined metadata/preflight without renewing old authority.
After headers or partial bytes, failure aborts the stream after joined cleanup;
no JSON or second status is appended. Successful flush does not prove client disk
receipt. Positive restrictive Stop SQL cancels matching local active responses
before audit I/O, waiting only within the original Stop deadline. Timeout retains
charges and reports unavailable; registrations remain counted until actual closure.

See [the runtime contract](../architecture/context-native-content.md) for exact
composition, qualification and remaining installed producers. The approved context
is at most 4096 bytes. The generic ledger's one-TiB contract remains unchanged,
without claiming this single short I-13 conversation is a qualified long transfer.
