# ADR-072 — Process-owned acquisition credentials and private enrollment channel

Date: 2026-10-10. Status: implemented refinement; qualification is recorded in [implementation progress](../implementation-progress.md).

ADR-071 supplies audited issuance but does not supply the worker's private key or confidential token transport. Add a bounded TLS 1.3 bootstrap operation within the existing download control/relay boundary. Initial server authentication uses explicitly pinned server roots and the endpoint's verified DNS/IP name. Client authentication is the exact dedicated-audience Pod-bound token verified by the existing current worker attester. Do not require the not-yet-issued acquisition certificate or forward a developer's token into the worker.

The worker generates one ECDSA P-256 private key and an identity-free CSR with Go's standard cryptographic library. It keeps both in process memory and uses the same key for ADR-071 renewal periods. No exported key file, Secret containing the process key, environment credential, issuer token or master key is added. Projected Kubernetes tokens are read afresh from the existing fixed mount on each actual enrollment request, including after an atomic token-projection rotation.

The closed private wire carries installation/session/worker IDs, a fresh response-correlation nonce and DER CSR; its Authorization header carries only the dedicated Pod token. The response echoes those identifiers/nonce and contains public certificate/chain DER. No principal, requested signing period, authority lease, callback address, evidence or human credential is accepted. Independently verify the chain against pinned issuer roots, exact process key, acquisition role, Pod identity, strict usages and original worker certificate period before installing the response. Server TLS roots and acquisition issuer roots are distinct inputs; none are learned from a response.

Trusted control binds an enrollment operation to one currently authenticated browser/MCP request and the exact admitted worker. Its lifetime is at most thirty seconds and inherits parent cancellation; each proof uses a request-owned token reader. Current authority is re-evaluated by ADR-071, never copied from a principal supplied by the worker. This refinement implements the bound operation, not a durable credential registry or the cross-replica owner routing. Reconnecting or renewing must bind a new live control operation; expired operations cannot acquire offline authority.

Each actual enrollment uses a fresh TLS handshake to check current server-certificate validity before sending the projected token. The client permits one active request, does not follow redirects or automatically replay a failed POST, and spaces unsuccessful caller retries by at least one second. Current usable credentials require no repeated HTTP/token/provider request until the next original-time-derived renewal window. SQL independently owns finite signing attempts. The handler limits simultaneous requests and body/socket deadlines; aggregate admission across replicas remains REQ-CAP-003, not a property proved by a process-local semaphore.

TLS certificate snapshots retain their own original expiry during renewal. Closing the owner cancels enrollment and disables every retained signer snapshot. Go heap zeroization and termination of existing independent TLS sockets are not promised; runtime supervision must close its connections and every evidence/key effect must still check current identity/authority. No CA-valid certificate alone grants evidence access.

No database migration, public permission or additional developer approval is introduced. The [channel contract](../architecture/worker-credential-channel.md) and [schema](../../specs/contracts/worker-enrollment.schema.json) refine REQ-DEP-003, REQ-DLD-003 and REQ-CAP-003. A complete acquisition executable, protected issuer/endpoint provisioning, active requester/connector routing, runtime connection supervision and Helm wiring remain required before public use.
