# ADR-077 — Protected hub owner configuration

Date: 2026-10-10. Status: implementation refinement under the maintainer's continuation; full Go/race/import, composed owned Kubernetes/service and specification/design checks pass. Credential issuance/activation and forwarding remain pending.

ADR-076's pinned constructor inputs cannot establish where the installation's owner pool and public issuer roots came from. Add a private `owner-pool.json` ConfigMap contract, selected by independently configured namespace/name/UID and installation/cluster. The payload contains only public trust and routing configuration. Administrator identities, admission pins and private issuer credentials remain outside that payload, so it cannot declare its own protection or grant itself signing rights.

Reuse the existing worker configuration protection algorithm through a common ConfigMap guard. Preserve the worker's policy expression, denial text, pinned identity and protection digest. The owner guard uses its own policy/binding and denial cause. Both require the exact native admission policy/spec/status and a separately authenticated non-administrator probe with update RBAC whose dry-run is rejected by that exact policy. Ordinary RBAC denial, an immutable object, a webhook error or a status claim does not prove the required administration boundary. Kubernetes documents the relevant [dry-run behavior](https://kubernetes.io/docs/reference/using-api/api-concepts/#dry-run) and [native admission policies](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/); actual provider behavior remains tested separately.

The source uses closed canonical JSON, bounded current public CA roots, independent installation/cluster/namespace/UID pins, two matching value reads and protection revalidation. Observation deadlines remain at most five seconds and cannot exceed any configured root's expiry. A suspended source can still be observed for operator diagnostics, but cannot produce a usable route.

Compose route resolution in C-04: read current configuration, resolve the exact owner endpoint under that pool, then read matching current configuration again. Reject changes in pool, revision/digest, roots, protection or suspension. Preserve the first observation's deadline rather than renewing it with the second read. Bounded cached observations may be reused only while their original deadlines remain valid. No endpoint, key or configuration credential is selected from a worker callback.

This adds no SQL table, public permission API, external service or new user approval. It does not supply durable monotonic configuration acceptance, recovery authority, a protected workload-template/issuer bootstrap, certificate issuance/activation or forwarding. Those must compose with this observed configuration before any public credential or evidence path is enabled.
