# ADR-062 — Post-persistence policy submission signatures

Date: 2026-10-10. Status: engineering refinement of REQ-PER-007 and REQ-EXE-001; initial components, production ingress and compiler composition still pending.

Distinguish authenticated admission provenance from acceptance of the final persisted policy and resolved scope. Kubernetes mutating admission runs before storage and the API server clears client-supplied system metadata; the AdmissionReview request UID identifies the webhook round trip, not a persisted object. A controller must therefore compare the final stored object and bind its concrete UID/generation before accepting execution. [Kubernetes create handler](https://github.com/kubernetes/apiserver/blob/master/pkg/endpoints/handlers/create.go), [AdmissionReview reference](https://kubernetes.io/docs/reference/config-api/apiserver-admission.v1/).

The implemented profile is a short-lived, purpose-specific JWS over a private `asservat-policy-submission/v1` envelope. It covers permission root, installation, recovery issuer epoch, nonce, optional prior acceptance, authenticated human actor, exact source UID/generation/spec digest, cluster/namespace/name, resolved scope digest and original issuance/expiry. The envelope lives at most sixty seconds. It contains no bearer credentials, copied groups or authored diagnostic parameters. It is not an execution permit, approval or new public client token format. Direct Kubernetes admission attestations, GitOps workload identities, and the broader manual-capture submission workflow remain separate required implementations.

Use the existing JWX library for standard JWS framing, signing and verification with the already selected Ed25519 algorithm identifier. Accept exactly the protected `alg`, `typ` and `kid`; reject other key locations, unsupported headers, encoding ambiguity and noncanonical payloads. Verification compares the payload to independently supplied authenticated identity, persisted source and compiler facts, rather than treating signed caller claims as the expected facts.

Keep private signing material in a dedicated nonexportable OpenBao Transit Ed25519 key. A context-bound standard `crypto.Signer` lets the JOSE library use Transit without custom signature framing. Pin the Transit version and public key; verify the provider's output locally. The runtime token has only update access to that signing path, with no key management/export, evidence decryption or directory privileges. A provider rotation does not silently select a newer version. The [Transit API](https://openbao.org/docs/next/api/secret/transit/) documents Ed25519 signing, explicit key versions and non-prehashed input; integration tests establish behavior for the pinned provider image.

Current public signing trust comes from the pinned administrator ConfigMap described by [submission-trust/v1](../../specs/contracts/submission-trust.schema.json). It is scoped to the permission root, installation and issuer epoch, contains at most 32 public keys, and lasts at most five seconds from the original read. Key removal, source replacement, expiry or read failure prevents new verification; no incoming URL or embedded key can refresh trust.

`SignedPolicyAcceptor` carries the original verification deadline into the existing acceptance transaction. New acceptance requires a matching current `SubmissionCheck`, checked again after blocking SQL work. The transaction independently rechecks source, current human rights, team delegation, recovery and original scope, then consumes the nonce atomically. Fresh verification never changes the idempotency digest or renews an existing acceptance. Raw SQL exact-replay lookup remains an internal historical receipt operation; public request/status composition must still enforce current caller access. A sixty-second submission deadline does not replace a team's independently reviewed policy lifetime or authorize later execution by replaying personal claims.

Bootstrap protection, key lifecycle/restore supervision, qualified Kubernetes admission provenance, resolved policy compilation and public browser/MCP operation state remain pending. Tests use synthetic source/compiler/bootstrap inputs where those components do not yet exist. No collector or public acceptance endpoint is enabled by this change.
