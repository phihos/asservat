# Outward-facing interfaces

One application service layer serves the browser, MCP and authenticated Kubernetes request bridge. Its authorization, planning, admission, privacy and projection decisions are shared. Transport adapters do not own a second policy engine. The [operation registry](operations.yaml), [browser OpenAPI](browser-openapi.yaml), [MCP workflows](mcp-workflows.md) and [error catalog](errors.yaml) make the boundaries reviewable. All are designs; no endpoints are running in this repository.

## Complete surface inventory

| Surface | Audience / protocol | Contract and behavior |
| --- | --- | --- |
| Shared console | Maintainers, recipients, reviewers, operators; HTTPS HTML | [63 screen definitions](../ux/surfaces.yaml); one role-aware console, React/TypeScript, compiled assets served by Go |
| Browser data/commands | Same-origin session-authenticated JSON | OpenAPI 3.1.1: 48 shared operations, 23 human-console operations and one authenticated native-content stream; strict request/response schemas |
| MCP | External agents; authenticated Streamable HTTP | [48 tool definitions](../../specs/contracts/mcp-tools.json), [MCP requirements](../../specs/mcp.md); bounded structured results, approved extracts first |
| Declarative configuration | Administrators / GitOps / maintainers; Kubernetes API | [All 15 CRD kinds](../../specs/apis.md); Kubernetes discovery/schema/CEL, resourceVersion conflicts, controller Conditions |
| Authenticated capture submission | Browser/MCP or DebugCapture | Existing immutable accepted-scope service; DebugCapture is an optional request/status envelope, not a second execution store |
| Human reviews | Independent approvers; browser JSON | Exact scope, verified step-up and revision/idempotency; no MCP approval tool |
| Enrollment / install | Cluster operators; browser handoff + Helm / kubectl | Chart values, secret references, signed connector identity and readiness reports; no browser-held admin kubeconfig |
| Identity | Organization IdP / clients | OIDC browser flow; MCP OAuth protected-resource metadata, issuer/audience checks and scope challenges |
| Incoming incidents | Configured Alertmanager; authenticated HTTPS | Standard v4 webhook, bounded body/batches, fingerprint + startsAt + per-alert status deduplication |
| Outgoing notifications | Configured scoped webhook destinations | CloudEvents 1.0 structured JSON, signed exact bytes, stable retry ID, allowlisted minimized fields |
| Observability | Operators / monitoring | Protected `/metrics`, `/healthz`, `/readyz`; content-free state/counters, no evidence or workload-label cardinality explosion |
| Deep links / agent handoff | Signed-in users and agents | Stable `asservat://case/<uuid>`, `/capture/`, `/grant/`, `/share/` reference kinds; authenticated HTTPS resolver; no bearer credentials |
| Error responses | All clients | Shared domain codes; bounded reasons/actions; nondisclosing before access is established |
| Internal connector / node protocol | Enrolled service identities | [Federation](../../specs/federation.md), signed permits, polling/ack/fenced work; not a public generic execution API |

No new general CLI is needed in the first release: kubectl and Helm cover configuration; MCP covers agent investigation; the console covers human interaction. Do not expose arbitrary SQL, object-store credentials, public raw-download URLs, a generic Kubernetes proxy or approval automation through a model tool.

## Browser routing, sessions and data

Prototype routes are `#/screen-id` for offline navigation. Production routes are normal URLs such as `/workloads/<cluster-id>/<workload-uid>`, `/captures/<capture-id>`, `/cases/<case-id>/artifacts/<artifact-id>`, `/shares/<share-id>` and `/admin/clusters/<cluster-id>`. Screen IDs are stable design references, not an API promise to use hashes. Every route loads an authorized projection; a copied link never authorizes its target. Keep reasons, expressions, pcap/display filters, user names, handles and tokens out of URLs/referrers/access logs. Locale/timezone display never changes UTC contract values.

Use an HttpOnly Secure SameSite session cookie, exact origin checks, session-bound CSRF tokens for POST and validated local return paths. `GET /api/v1/session` bootstraps identity and CSRF metadata without mutation. Logout is a CSRF-protected POST; login starts server-side state/nonce/PKCE, the IdP callback verifies state/issuer/token before establishing a session. Step-up is server-verified context bound to the review; never a client boolean. OIDC values and short enrollment secrets are not stored in browser localStorage.

Shared browser operations use fixed `POST /api/v1/operations/<literal-operation-name>` endpoints. POST bodies keep sensitive filters out of URLs; `x-effect=read` still means side-effect-free planning/querying. This is an explicit typed operation API, not arbitrary tool-name dispatch. Request and output schemas mirror the MCP catalog exactly. A read cannot arm a recorder, trial a protocol survey or pin a ring. Analysis queries can create bounded analysis work where the existing contract explicitly permits it.

Shared operations return HTTP 200 with the existing `status=ok|pending|error` domain envelope. A pending result is acceptance of bounded work, not evidence availability. Auth/session/malformed body failures use appropriate 4xx/5xx `application/problem+json`. Console-only operations use typed successful projections/receipts and non-2xx problem details for failures. Clients must inspect both HTTP status and, for shared operations, domain status; never infer success from 200 alone. This deliberate compatibility boundary avoids inventing a different MCP error vocabulary.

All commands carry Idempotency-Key; where the existing body already contains an idempotency field, the values must agree. Key scope is principal + client + command kind; same key/different canonical body is Conflict. Expected domain revision is a bounded integer; expected Kubernetes resourceVersion is an opaque string. They are not interchangeable. Polling a command receipt through `get_operation` rechecks access and returns the same operation identity; receipts never leak a queue job’s privileged credential.

Lists default to 20 items, maximum 100, opaque expiring principal/client/query/revision-bound cursors. Shared MCP envelopes keep their 24 KiB default / 32 KiB structured maximum and 64 KiB combined limit. Console JSON normally has a 32 KiB hard response bound. Configuration impact preview retains the existing maximum of 1,000 targets and 256 KiB, with bounded partial pages and explicit completeness; protected editor-diff projection is at most 64 KiB; indicate truncation or reject oversized drafts rather than truncate semantic configuration. `stage_editor_draft` permits at most 64 KiB UTF-8 YAML inside a maximum 128 KiB request, no aliases/custom tags/multiple documents, and a fixed supported CRD-kind list. Other JSON requests have the existing operation-specific bound within a 64 KiB transport ceiling. No HTML from evidence is trusted. Use `Cache-Control: no-store`, a restrictive CSP and no third-party scripts/analytics.

## Configuration authoring without a second permission API

`stage_editor_draft` validates a bounded authored manifest against the supported kind’s server-pinned Kubernetes schema and semantic policy, then stores a short-lived encrypted draft. Its handle is principal/client-bound, expires within five minutes, and carries no permission. Empty base resourceVersion means create; existing resources require their observed opaque version. Resolve namespace/resource UIDs server-side and reject name reuse. Unknown kinds and controller-only runtime CRDs are rejected.

Own-access explanation defaults to the caller. An explicit other principal or hypothetical configuration evaluation requires the administrator delegation envelope; results are Allow, Deny or Indeterminate and never enumerate group members.

`preview_configuration` returns a protected, scoped diff handle, source revision, impact reasons and submission mode. `submit_maintainer_configuration` accepts only DebugPolicy, EvidenceRecipe and CaptureProfile. It uses authenticated submission provenance and current Kubernetes rights under REQ-PER-007, never an unbounded hub identity. For GitOps-owned fields, show/export the diff and let the existing field manager apply it; do not force conflicts. Execution acceptance remains separate from successful Kubernetes persistence.

AccessBinding, PermissionSource, CollectionCeiling, EvidenceRetentionPolicy and capacity/storage configuration are **Kubernetes-only writes**. Their browser editor is a local proposal/preview/export workflow; the OpenAPI has no endpoint that persists those resources. Authenticated diff rendering uses the originating draft handle through the protected editor view, with original expiry and output cap. It cannot render arbitrary object URLs. Raw evidence is not exported with configuration.

## Human commands unavailable to MCP

The console supports independent execution/raw-query/raw-sharing decisions, grant revocation, stopping future sharing, explicit owner-team replacement, privacy restriction/erasure, enrollment/revocation and cleanup retries. OpenAPI `x-required-role` labels describe authorization responsibilities, not additional AccessBinding role names; map them to the existing fixed roles, current resource scope and delegation rules. Every command has a narrowly authorized role, exact resource/revision and idempotency. Operator status alone does not automatically confer artifact-read or approval authority. The prototype's “Operator + maintainer” persona deliberately combines roles for review; real assignments are independent.

`decide_review` binds request ID, current revision, reviewed scope digest and verified step-up reference. The server checks separation of requester/reviewer, applicable role and current freshness. `stop_future_sharing` preserves existing concrete shares. `revoke_share` on an instruction denies child shares as specified; neither operation resets spent publication slots. `transfer_share` (ADR-238, shared browser/MCP operation; it replaces the earlier design-only `replace_share_managers`) validates the complete nonempty manager set against the current manager's own owner teams; it does not modify recipients, creator, grant or expiry.

`apply_privacy_action` binds an exact selection digest, propagates through authorized lineage, and returns work receipt. `retry_deletion` requests an attempt; it never marks absence verified. Enrollment delivers a one-use secret to the operator's configured secret channel reference; neither operation result nor logs return it. Readiness distinguishes configured, passively checked and actively qualified capabilities. No web button performs an undisclosed privileged qualification experiment.

## External transport behavior

Alertmanager input is `POST /integrations/alertmanager/<configured-receiver-id>`, authenticated before parsing, max 1 MiB body / 100 alerts and bounded field values. Reject oversized batches with 413 rather than silently dropping alerts; report the sender’s `truncatedAlerts`. Per-alert schema/target mapping failures are counted with safe reasons, never interpreted as a privileged arbitrary capture request. Receiver identity, fingerprint and startsAt identify the episode; resolved is terminal even when deliveries reorder. [Trigger semantics](../../specs/triggers.md) remain authoritative.

Outgoing event schema and signing are already specified in [federation](../../specs/federation.md) and the [event contract](../../specs/contracts/event.schema.json). A 2xx response acknowledges delivery; bounded retries/backoff preserve the event ID, respect deadline and destination scope, and surface exhausted work. No evidence content, reasons, usernames or arbitrary labels in default payloads. Recipients authenticate separately when resolving dataref. Webhooks cannot add destinations from capture parameters.

Health probes disclose only process readiness. `/readyz` distinguishes service acceptance from optional regional mechanisms; loss of one analysis capability must not falsely make every stored-evidence read fail readiness. `/metrics` is operator-only, with bounded labels such as region/capability/reason enum; never artifact IDs, raw labels, identities or URLs. Detailed diagnosis remains an authorized UI/API projection.

Transport/version policy: browser `/api/v1`, explicit MCP negotiated versions, Kubernetes `v1alpha1`, versioned manifests/events and immutable profile versions evolve independently. Breaking DTO changes need a new version or negotiated capability and migration fixtures. No silent default widens acquisition, retention or permission. The `asservat.io` API group and illustrative host remain subject to the existing domain-registration gate.

## Live observation boundary

The browser API has 72 operations: 48 shared MCP equivalents, 23 console operations and one authenticated native-content stream. Five fixed `/api/v1/operations/` routes (`list_live_sources`, `open_live_watch`, `read_live_watch`, `update_live_watch`, `close_live_watch`) implement [live watching](../../specs/live-watch.md). They reuse existing sessions/OAuth and bounded envelopes; no websocket, infinite response, new permission API or mandatory message service. A read can wait at most five seconds. An empty active batch can carry next_cursor as a continuation position; ordinary list pagination semantics remain unchanged.

Watch IDs and cursors are principal/client-bound and not share links. Filters remain in bounded POST bodies and protected session scope, never URLs/logs. Each session has an absolute deadline, idle cleanup and lifetime output budget. Pause/resume/filter edits are revision-checked and idempotent; they do not mutate recording. Read responses include source/view generations, gaps, timestamps/uncertainty, expiry and explicit untrusted/transient handling. Save current recordings is the existing independent acceptance operation. Per-client view opening can be disabled independently of capture tool enablement; no implied acquisition scope escalation.

Paused browser views continue bounded status-only reads while visible to receive access/expiry changes, within the same hard deadline; no new rows or automatic renewal. Hidden/closed tabs stop polling and best-effort close. Reconnect restores neither an expired view nor lost rows automatically. For 2026-07-28 and 2025-11-25 MCP, typed bounded reads are the interoperable baseline; resource subscription hints are deferred rather than advertised without implementation.

Live failures reuse stable codes: NotAuthorized for unavailable source/view rights, TargetGone for a stale source incarnation, CapabilityUnavailable for an unsupported approved projection, BudgetExceeded for view admission/spend, Conflict for revision/idempotency mismatch, InvalidCursor for an invalid authorized-view cursor, RetryLater for overlapping reads/rate pressure, and ClusterOffline when no live dispatch is possible. Valid but lagging continuation is represented by a gap plus a new cursor, not by inventing complete history. Closed/Expired/Exhausted sessions return their permitted terminal control state with no rows and no continuation; source-specific losses can leave other originally selected sources active. Filters unsupported by the chosen projection fail before reading it; they are never broadened or ignored.

## Download for local tools

All gathered evidence and saved derivatives support native download. Shared prepare/get/cancel_artifact_download operations use the existing application authorization boundary; GET /api/v1/downloads/{download_id}/content streams the exact file to a browser or authenticated OAuth client. Public here means documented, not anonymous: the path grants no rights, redirects to storage are forbidden, and raw grants must cover download_artifact. MCP hands off file transfer without putting bytes in model context. Browser and MCP prepare/get/cancel results share the canonical status definition. Completed can omit native file details; any included details remain an indivisible verified group. Ready, Streaming and Interrupted still require the complete group. An authorized terminal status may outlive the transfer deadline without a live worker or metadata cache; it grants no renewed download, resume or decryption and proves no local file save. The console replaces prior native fields when a terminal-only response omits them. It bounds displayed terminal results by the existing authorized `managed_read_until`, rechecks status at most once per minute while active, and clears the result before a recheck or when that interval has already ended. Transfer expiry still gates active download/resume; no timer starts preparation or retains a worker/key/cache. See [canonical contract](../../specs/artifact-downloads.md).

One bounded capture and its requesting human's selected result access can share a single independent review under [investigation approval](../../specs/investigation-approval.md). Shared preview/request/status schemas carry result_access; ordinary decide_review binds both collection and result-access digests, without another endpoint. Authentication, step-up and current underlying entitlements remain required. Native transfers use the existing authenticated content endpoint.

The initial [fleet-administration projection](../architecture/fleet-administration.md) maps enrollment operators through protected Kubernetes installation settings. It is separate from workload AccessBinding roles and grants no evidence access. The browser command still needs audited issuance and configured secret-channel delivery; the reader alone does not implement enrollment ingress.

The separate [browser authentication protocol](browser-auth-openapi.yaml) defines login/callback, read-only CSRF bootstrap, explicit refresh, local sign-out and signed provider logout. It does not add business operations or MCP tools. The [session architecture](../architecture/browser-sessions.md) records current runtime qualification and remaining deployment prerequisites.
