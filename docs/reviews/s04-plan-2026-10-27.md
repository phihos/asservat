# S-04 plan: continuous recording and explicit save (2026-10-27)

Phase A of [S-04](../architecture/implementation-slices.md): an audit of what exists, the
[AGENTS.md complexity gate](../../AGENTS.md#complexity-must-pay-for-itself) for each feature, the
test environment for privileged collectors and an ordered list of increments. This plan contains no
product code and does not amend the specifications. Where an increment implements a narrower or
different mechanism than the specification text, it updates that text, the contracts and
traceability in the same PR, as AGENTS.md requires.

Baseline: `origin/main` at `0bfb458e` (S-06 increments 1–11 merged, ADR-232–240, highest migration
00093). Traceability: C-05/06/07/11/12/14/15/23, TASK-05/06/07/08/11; EXP-02, EXP-03, EXP-21,
EXP-22. Relevant specifications: [packets](../../specs/packets.md) REQ-NET-001–006,
[syscalls](../../specs/syscalls.md) REQ-SYS-001–003, [action lifecycles](../../specs/action-lifecycle.md)
REQ-LIF-001–006, [recording saves](../../specs/recording-saves.md) REQ-SAV-001–004,
[capture assessment](../../specs/capture-assessment.md) REQ-ASM-001–005,
[capture profiles](../../specs/capture-profiles.md) REQ-CPR-001–005,
[capture history](../../specs/capture-history.md) REQ-HIS-001–004 (S-06 increment 12),
[downloads](../../specs/artifact-downloads.md) REQ-DLD-001–004,
[execution](../../specs/execution.md) (source sessions, recording-save identity),
[capacity](../../specs/capacity.md) REQ-CAP-002/004 and
[authorization](../../specs/authorization.md) REQ-AUT-003/006.

Out of scope: live watch (S-07), offline analysis Jobs and raw query operations that need the
ADR-036 encrypted scratch StorageClass (`pcap_query`, `syscall_query`: S-05), and dumps, cores and
process-stopping actions (S-08).

Labels used below: **[fact]** = research result or documented upstream behavior with its source;
**[measured]** = an actual result recorded in this repository; **[proposal]** = a design choice of
this plan, not yet implemented or measured.

**Summary:** none of S-04's recorders, rings, peers, saves or profiles exist in code, and there is
no node collector process at all. The reusable prerequisites are installed-qualified: policy
activation, occurrences and detectors (S-03), streaming custody up to 128 MiB (ADR-166), native
download sessions, worker Pod-token/CSR enrollment, history base (ADR-236), sharing (S-06) and the
preview/request pipeline. The largest new pieces are the privileged node role with its work
channel to the connector, the engine adapter, and the sensitive-acquisition grant foundation that
S-08 would otherwise build first.

| Result | Consequence for S-04 |
| --- | --- |

| libpcap matched all 11 filter samples; Gadget's bundled compiler rejected `ip6 and dst host 2001:db8::2` | Compile with real libpcap and feed bytecode to the engine; never use Gadget's compiler |
| All 11 libpcap programs, translated with cbpfc, passed the VM verifier and `BPF_PROG_TEST_RUN` | The libpcap → cBPF → eBPF path works for Ethernet IPv4/IPv6 TCP/UDP samples |

| A 16 KiB ring with a separately reserved frozen copy refused 10,000 competing snapshots during 100,000 writes; the accepted snapshot stayed identical | The bounded-copy ring model holds; allocator/metadata RSS was not measured |

Each row keeps the specified user outcome and invariants (pod scope, current authority before every
observation, finite budgets that never refill, truthful coverage, encrypted managed evidence, native
download). The implementing increment records the change in the affected spec/contract text.

### 6.1 Points for the maintainer

No mechanism this plan adds beyond the specification combines weak benefit with questionable
cost, so nothing is paused. Three points change scope or ordering and are stated so the
maintainer can object before the affected increment starts:

1. **The approval/grant foundation moves from S-08 into S-04 (increment 12).** HTTP headers,
   raw packets and syscall arguments are specified as sensitive acquisitions that need a grant
   before the first read, and no grant system exists. Building it here is required by the spec,
   not added. It does mean S-04 carries work the slice table assigns to S-08.
2. **Peer freshness by LIST polling instead of watches (S5).** Benefit is clear (simple,
   fail-closed); the cost is up to 64 consistent LISTs per second per cluster at the cap.
   Open item 7 measures it. If the API load is unacceptable, the fallback is a watch plus the
   spec's progress check, which is the more complex mechanism.
3. **Detection-latency ring margin (S3).** Without it, a 15 s detector poll silently loses up to
   half of the requested 30 s history. The margin raises only the age limit; the 16 MiB byte cap
   and memory reservation are unchanged.

Nothing in this plan marks a TASK checkbox or EXP gate complete. Increments that narrow or
restate spec mechanisms (§3) update `specs/packets.md`, `specs/syscalls.md`,
`specs/action-lifecycle.md`, `specs/capture-profiles.md`, `specs/capture-history.md` and
`specs/traceability.yaml` in the same PR.
