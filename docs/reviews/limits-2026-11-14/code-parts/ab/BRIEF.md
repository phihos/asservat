# Limit audit brief (READ-ONLY on the repository)

Repo: /home/phil/Projekte/asservat-ux (Go, Kubernetes evidence-capture product "Asservat"; unreleased). Do NOT edit any repository file.

Maintainer standing rule: "If you can not give a good reason for a limit then remove the limit."
A limit is justified ONLY by:
 (a) a concrete resource cost that grows with the value AND a bound derived from that cost;
 (b) an external protocol/API constraint (Kubernetes name/label lengths (63/253), OIDC/JWT, HTTP, PostgreSQL/pgx limits (e.g. 65535 bind params, 1 GB field), S3 part sizes/10000 parts, pcap snaplen, eBPF map limits, X.509, etc.);
 (c) an explicit maintainer decision. The ONLY (c) sources: administrator-enforced maximum evidence retention; protection against capture storms and cross-workload storage exhaustion (rate/concurrency limits); expiring policy grants for automatic intrusive actions with administrator-configured finite approval periods; bounded pcap filters; explicitly bounded recurring-policy sharing; one independent approval for manual collection; finite manual requests; monitor all authorized replicas within administrator ceilings and independently cap per-incident collection; ADR-311 authority reuse 30 s (60 s shared delivery-policy observation); ADR-312 started downloads run to original bounds; ADR-222 keeps 32 physical SQL connections.
Agent-written ADRs/comments are NOT a reason by themselves.

Accepted ADRs that already decide removals (cite D# in last column when applicable). Full text: /home/phil/Projekte/asservat-friction/docs/decisions/330-event-driven-system-design.md and 335-usable-by-default.md. Summary:
- ADR-330 D1 informers/watch not polling, no cache expiry by time; D2 one connector connection (no standby socket pools, owner relay, routing proofs, JWS envelopes); D3 standard identity (no per-process enrollment/registration/activation tables, certificate audits, signing budgets, process self-proofs); D4 no Kubernetes Job/certificate/key slot per download or query; D5 authorization once per op, no 5 s windows / per-chunk rechecks / proof bundles; 5 s only as I/O timeout; D6 audit is a SQL row (no envelope audit, intent/outcome pairs, ack roles, audit prepayment, deletion certificates); D7 idempotency, no never-refunded/uncertain spend, no prepaid renewals, no WAL/backup prepayment, no second charge ledgers; D8 small metadata in SQL, no CapacityReservation/DeliveryWork CRDs; D9 stateless previews (no preview handles, handle caps, expiry); D10 K8s-native status (no submission envelopes, intent versions); D11 no assignment-ID continuity/A->B->A proofs; D12 retention as stored deadlines (no watermarks, checkpoints, catch-up pages, topology pins, retention proofs); D13 no installer-era machinery (installer Pods, journals, witnesses, UID pins, dry-run probes, guard qualification).
