# SQL numeric-limit audit (migrations/ + migrations/queries/)

Scope: /home/phil/Projekte/asservat-ux/migrations (00001–00163) and migrations/queries. Only numeric caps (CHECK, plpgsql count/size raises, overflow-probe `LIMIT N+1`) are listed. I skipped format/enum checks, SHA-256 `=32` digests, positivity checks, timestamp sanity ranges, and pagination LIMITs with continuation. Effective = latest goose **Up** section; `-- +goose Down` blocks are ignored. "Go fails closed" means the Go caller rejects results longer than N (I checked permissions.go:115/619).

Verdict key: KEEP-a = resource cost that derives the bound; KEEP-b = external protocol/API; KEEP-c = maintainer decision; REMOVE; DERIVE = keep the concept, but replace the hard number (usually with an administrator/Helm value or a bound computed from another bound).
