# Review from user outcomes

Reviewed 2026-10-09 after the maintainer identified missing local downloads. This is an expert task walkthrough and contract/prototype inspection, **not a study with users and not proof of implemented behavior**. The question is whether a developer or operator can finish a useful task, including waiting, handoff and their existing tools. A correct rejection is not automatically a successful user outcome.

P0 blocks an explicitly required basic workflow. P1 blocks or substantially undermines a common investigation. P2 adds material avoidable effort or uncertainty. “Contract corrected” means written/schema/mockup work only; it does not mean the product is implemented.

## Evidence and exact failure traces

### U01: a request was specified without a usable grant

Before this pass, [request_raw_access](../../specs/contracts/mcp-tools.json) allowed download_artifact, while the rawQuery branch of [grant.schema.json](../../specs/contracts/grant.schema.json) enumerated only read_memory, debugger_command, pcap_query and syscall_query. Thus a download request passed its DTO check but a corresponding raw grant failed its own schema. The earlier download checks did not traverse that boundary. The same omission also prevented a capture-time raw-sharing instruction/resolved selection from including download. This pass corrects those enums, requires raw coverage for explicit full-file sharing, and adds paired request/grant and request/intent/share regressions. Ordinary approved shared artifacts retain native download through their ordinary read entitlement; no extra raw review is introduced for them. This does not claim real authorization works.

### U02: one investigation crossed repeated approval boundaries

[REQ-AUT-003](../../specs/authorization.md) and [REQ-DLD-002](../../specs/artifact-downloads.md) required separate existing-artifact approval after collection. The developer could get the file stored but not begin the intended inspection. Existing grant reuse solved repeat queries, not the first full investigation. The maintainer chose one combined bounded review during this review. [Investigation approval](../../specs/investigation-approval.md) binds a single capture, output selection, original human, explicitly reviewed clients and aggregate disclosure limits. It does not turn collection into blanket access or approve every future recurrence.

### U03: rates and expiry are not “finish after this incident”

[policy.schema.json](../../specs/contracts/policy.schema.json) has suspended, per-hour/cooldown/concurrency budgets, observation and evaluation controls; it has no authored total incident count/end condition. [Action lifecycles](../../specs/action-lifecycle.md) correctly separate finite manual sources and ongoing policy sources, but do not compose the basic temporary-watch outcome. Exhausting an action grant is a safety bound, not successful completion: multiple actions may consume it, and unrelated source work can remain. Needed acceptance: arm all eligible replicas, capture the admitted next episode once, stop only this watch's sources, leave committed evidence readable, and report timeout if no episode arrives. Refresh, browser closure, pod rollout and duplicate events must not reset the stop condition.

### U04: presentation promises exceed query contracts

[MCP prose](../../specs/mcp.md) advertises case status/time filtering, but list_cases currently accepts since without until/status. get_timeline and list_artifacts accept case_id/cursor/limit only. [Viewer workflows](../ux/workflows.md) call for occurrence/time/type controls; app.js implements text filtering over rendered data. Those are not equivalent to finding an older event on another page or aligning packet/log intervals. Needed acceptance: start with workload and an approximate local timestamp, find the authorized incident and relevant artifacts, carry the same interval through viewers, and distinguish “none observed” from “not recorded.” Avoid overloading unrelated query tools to hide a missing search contract.

### U05: a remedy needs an actual entry point

The core viewer in [app.js](../../design/ui/app.js) offers matching private symbols as the remedy. [REQ-EVD-007](../../specs/evidence.md) establishes exact identity and available companion acquisition, while [the operation inventory](../interfaces/operations.yaml) contains no symbol upload/attachment/source-selection operation. A developer might already have the exact private build artifact, but the product provides no specified route to use it. Do not solve this by forcing another core or by telling every developer to ask the platform administrator. User-supplied symbol artifacts must be marked supplied rather than observed, authorized and bounded, and processed as untrusted input.

### U06: the object that granted access may disappear

[REQ-PER-008](../../specs/permissions.md) explicitly records only the capturing principal for SAR-derived audiences and conditionally permits deleted-pod checks; otherwise a binding/share is needed. This is not a defect in every installation: stable team bindings can work. It is a failure of the promised simple exec-inheritance route in unqualified environments precisely when crash evidence is useful. A durable read basis must preserve revocation and original scope, not infer access from a replacement pod with the same name. Until that design is accepted, report the limitation during source setup and before affected capture, not after the crash.

### U07: an incident is not always one workload or signature

[REQ-EVD-004](../../specs/evidence.md) partitions cases by cluster/workload/versioned signature and says explicit links may connect upgrades. [The domain and operation catalogs](../domain/README.md) provide no usable link/edit investigation operation or shared multi-case view. Separate permissions are appropriate; forcing engineers to correlate many tabs and opaque case IDs is not an investigation model. A reference-based workspace must expose only authorized rows, retain source timestamps/uncertainty, and remain useful when one participant lacks access to another service. No implicit new capture or shared entitlement follows from grouping.

### U08: review time can consume the evidence

[REQ-NET-003](../../specs/packets.md) defaults to a 30-second ring; [REQ-SAV-002](../../specs/recording-saves.md) fixes t0 only at final acceptance after preview and never pins before admission. A developer who sees the event, spends 35 seconds reading/selecting, and then saves cannot preserve it from that ring. This pass offers immediate Save for displayed, already reviewed defaults; Customize still previews changes. Backend preview/signing/admission remain required, but are performed without another human round trip on the unchanged path. No promise is made to recover an already evicted row or to pin on page view.

### U09: a non-firing trigger needs a testable explanation

[Final review](final-review.md) deliberately deferred trigger replay. Its health/status remedies explain availability and suppression, not whether a sample JSON field, multiline event or window condition matches. A read-only test must use the same production evaluator and bounded authorized input, disclose limitations, and never be presented as proof that a real sensor is attached. Do not add a second toy evaluator or silently run a production sample capture.

### U10: “ask an approver” is still work the product leaves to the user

[Error contracts](../interfaces/errors.yaml) link to own review or say contact-operator; raw requests do not carry a review assignment. list_reviews provides scoped review discovery, but the prototype labels it Assigned approval requests. The label is corrected to Available approval requests. A real handoff needs a permitted reviewer/support destination or an explicit unresolved configuration state, then a durable return to the same request. A copyable link can support existing chat tools without Asservat posting externally. Waiting time, queue abandonment and missed capture deadlines must count in usability results.

### U11: a native file is sometimes only one piece

[REQ-DLD-001](../../specs/artifact-downloads.md) makes every file available and offers exact companions, but prepare_artifact_download accepts one artifact. This solves access to bytes; it does not yet solve assembling a many-library debugger environment or handing off a selected incident bundle. A follow-up needs native names/layout mapping, checksums, build identities and relative safe paths without executing an artifact-provided script. Never include hidden/unselected parents or treat a bundle as one enlarged permission.

### U12: irrelevant configuration still leaks into the simple path

The current prototype already lets capture-compose proceed directly to review; it does **not** force the process and network pages. However, it offers both configuration links even for context-only selections, while the [capture journey](../ux/surfaces.yaml) lists both pages without a conditional branch. This pass conditions those optional links on applicable selected profiles and clarifies the journey. Context-only stays direct-to-review; network/core users can use defaults or edit only relevant controls. Production compilation must discard inactive settings. Navigation regressions exercise actual clicks instead of merely visiting every route.

## Preserve real constraints without disguising failures

This review does not propose automatic TLS interception, raw live delivery, other-team collection, limitless history, silent retention extension, guessed symbol substitution, arbitrary debugger scripts on servers or outbound messages. Those are existing boundaries, not defects solely because they constrain a task. The design must expose them before a user waits or collects, offer a useful supported alternative, and report when the requested outcome cannot be achieved.

Minimalist screens, counts of routes, schema validation and automated accessibility scans cannot establish task usability. Future evaluations must record unassisted final outcome, total elapsed time including review/queueing, active effort, handoffs, missed evidence, recovery, and explanations of scope/retention. Include non-lead developers, on-call users, recipients and operators, not only maintainers of this codebase. The investigation tasks above remain **NOT RUN with participants**.

## Method references

[GOV.UK's whole-problem guidance](https://www.gov.uk/service-manual/service-standard/point-2-solve-a-whole-problem) supports evaluating the user's complete journey across tools and organizational boundaries. [Its moderated testing guidance](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing) calls for observing likely users attempting concrete tasks. [Nielsen's heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) inform checks for real-world fit, user control, recognition and actionable recovery. These sources guide the review method; the Asservat findings above come from the cited local contracts, not from an external claim that this product has been user-tested.
