# S-05 plan: profiles, analysis and deeper inspection (2026-11-02)

Phase A of [S-05](../architecture/implementation-slices.md): an audit of what exists, the
[AGENTS.md complexity gate](../../AGENTS.md#complexity-must-pay-for-itself) for each feature, the
test environment and an ordered list of increments. The structure follows the
[S-04 plan](s04-plan-2026-10-27.md). This plan contains no product code and does not amend the
specifications. Where an increment implements a narrower or different mechanism than the
specification text, it updates that text, the contracts and traceability in the same PR.

Baseline: `origin/main` at `b3184301` (S-04 row 17 merged, highest ADR 283, highest migration
00122). Traceability: C-06/14/15/18/23, TASK-03/05/08/11; EXP-13, EXP-14, EXP-15, EXP-22.
Relevant specifications: [profiles](../../specs/profiles.md) REQ-PRF-001–005,
[evidence](../../specs/evidence.md) REQ-EVD-005/008, [MCP](../../specs/mcp.md) REQ-MCP-002/003/005,
[downloads](../../specs/artifact-downloads.md) REQ-DLD-001–004,
[authorization](../../specs/authorization.md) REQ-AUT-003/004,
[investigation approval](../../specs/investigation-approval.md),
[actions](../../specs/actions.md) (`profile`, `httpDiagnostic`, `processSnapshot`,
`networkSnapshot`, `fileRead`, `logs`), [capture profiles](../../specs/capture-profiles.md)
(`builtin/go-cpu/v1`, `builtin/process-context/v1`) and [syscalls](../../specs/syscalls.md)
(`syscall_query`).

Out of scope: runtime packs other than Go and the eBPF CPU sampler (JFR, EventPipe, Python/Node
heap, `get_runtime_summary`; TASK-10), cores, `read_memory`, `debugger_command`, symbol intake for
cores (U05) and process-stopping actions (S-08), live watch (S-07), raw-share approval (S-06 F10).
The S-04 plan handed `builtin/process-context/v1` and `builtin/go-cpu/v1` to this slice
([S-04 plan §2.2](s04-plan-2026-10-27.md)); no other slice plan claims the `fileRead`, `logs`,
`processSnapshot`, `networkSnapshot` or `httpDiagnostic` actions, so the "file queries" of the
slice row include them.

Labels: **[fact]** = research result or documented upstream behavior with its source;
**[measured]** = an actual result recorded in this repository; **[proposal]** = a design choice of
this plan, not yet implemented or measured.

**Summary:** the Go acquisition mechanism and the endpoint planner are component-qualified but
unconnected: nothing dials a pod, admits a profile, publishes or reads one. Everything downstream
of acquisition reuses installed machinery: the node work channel (ADR-246/248), connector
encryption and publication (ADR-244), ad hoc/policy grants (ADR-249/259), the approved query
ledger and worker (ADR-206/282) and native download. The largest new pieces are the profile
compiler and node work kind, the pprof verifier/analyzer, the two-artifact comparison scope and
the standalone raw-query grant.

## 6. Open verification items (facts to measure, not decisions)

1. Worker memory to parse a profile at the 64 MiB output cap: decompressed size and Go object
   count. Until measured, the analyzer limit is 32 MiB decompressed [proposal]; larger profiles
   return `AnalysisUnavailable` with the download remedy.
2. `profile_cpu`: whether IG's mount-namespace filter applies before stack collection, the
   configurable sampling frequency (default 49 Hz in `gadget.yaml`), and node CPU/RSS during a
   session on the runner.
3. Whether the gadget's user-stack output carries mapping build IDs for native frames; if not,
   the artifact reports missing mapping identity instead of fabricating it.

5. Loopback dialing via `setns` on a locked thread from the Go node process, including that the

### Saved-packet query contract closure (2026-11-05)

[ADR-305](../decisions/305-bounded-saved-packet-queries.md) and the
[bounded implementation plan](s05-packet-query-implementation-2026-11-05.md)
record the explicit language change and the complete metadata/raw user outcome.
Implementation and qualification remain pending; declared schemas are not a
callable route. Keep today's8MiB packet-source/resource scope separate from the
1GiB API scan ceiling. Full-tail authentication is mandatory after a logical
scan stop. Queries create no stored derivative or capture-history row.

Standalone rawQuery and combined resultAccess currently implement download only.
Extend pcap_query operation coverage, exact artifact/human/client identity,
current grant checks and immutable once-only debit. Query-only pools fund output
rather than require native-file-size coverage; a scope including download keeps
that coverage and the existing larger download ceiling. All uses share the same
finite parent pool. The public initial idempotency key needs a durable exact
query/request-digest association in the existing query ledger; grant-use replay
must also compare operation. Do not claim atomic query/debit association from
separate unlinked calls or add another lifecycle journal.

Added services/watch/RBAC/permission names/network destinations/dependencies/
expression parsers/PVCs/acquisition/stored artifacts:0. Reuse one worker/query,
three key roles/source and existing query states. Extra SQL checks/locks and query
units/resource declarations must be measured. No new timer, pool or cache is
introduced to manage the query. Earlier local resource or installed summary
passes retain their named source/shape scopes and do not qualify the new filter,
field/prefix work or maximums.
