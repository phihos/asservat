# Capture profiles and syscall tracing: feasibility

Checked 2026-10-09. Capture-profile composition is an Asservat design addition, not an upstream product capability claim. Versioned Kubernetes configuration plus the existing typed recipe compiler can express the catalog without a new runtime service. The proposed bounded literal-field registry avoids adding a templating language or executing user schemas. [Capture profiles](../../specs/capture-profiles.md) and [syscalls](../../specs/syscalls.md) are normative.

Inspektor Gadget's [v0.56.0 traceloop documentation](https://inspektor-gadget.io/docs/v0.56.0/gadgets/traceloop/) describes eBPF syscall capture, process attribution, return values, argument/buffer output and kernel-side syscall-name filters. This establishes a plausible integration path within the already selected engine family. It does not establish Asservat's pod confinement, metadata-without-memory-reads mode, full ABI coverage, observation accounting, ring semantics or overhead targets. In particular, its argument-bearing examples must not be advertised as a safe metadata collector. These require a qualified adapter/source changes or the affected mode remains unavailable.

The same documentation contains a misleading tip suggesting a syscall-name filter shows only failures; a name filter alone does not express an errno predicate. Asservat defines result filtering separately and accounts for any sensitive observations before the result is known. No failing runtime reproduction is claimed.

An attempted v0.57.0 GitHub tree lookup was unavailable in this research environment. The older versioned documentation is feasibility evidence, not confirmation of the production pin. TASK-01 must inspect the selected source/image digest, architecture support, licence, egress and map/event implementation. Neither a ptrace fallback nor relaxing workload Pod Security is authorized by this choice.

HTTP composition preserves the existing researched boundary: [HTTP/1 framing](https://www.rfc-editor.org/rfc/rfc9112.html) requires bounded parsing across packet boundaries; a snaplen or port filter alone cannot isolate arbitrary headers. The shipped profile is therefore named HTTP/1 headers, both directions, uses the existing approved projection, and makes HTTPS/HTTP2/HTTP3 gaps visible. It does not introduce TLS-key capture or automatic decryption.

Required gates: deterministic compiler/override/dependency/deduplication fixtures and real CRD/admission publication tests; same browser/MCP plan; stale/disabled versions and historical replay; combined resource/approval accounting; syscall ABI/fork/exec/reuse/loss/overhead tests; metadata absence of secret bytes and argument-mode pre-read budgets; raw-query/share/expiry adversarial checks. EXP-21/22 remain **NOT RUN**. No collector was started and no workstation privileges or seccomp/core settings were changed.
