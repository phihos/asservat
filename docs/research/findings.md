# Research findings and feasibility

Inspection date: **2026-10-09**. Sources are primary project documentation, specifications, source code, release metadata and provider documentation. The original source-inspection pass accessed no production evidence and modified no Kubernetes cluster, node sysctl, cloud resource or registry. Later authorized [VM/storage experiments](feasibility-packet-downloads.md) used only new disposable infrastructure and synthetic evidence. The original brief is [preserved here](original-brief.md).

**Finding:** the platform is feasible on qualified Linux worker nodes, with significant engineering in privilege isolation, dynamic policy evaluation, artifact lifecycle and authorization. It cannot offer every action on every managed Kubernetes product. Documentation verification is not a substitute for the integration experiments in [the validation plan](../validation.md).

## Brief claim audit

| Claim | Assessment and consequence | Primary evidence |
| --- | --- | --- |
| Every core collector requires a privileged node component | Too broad. Node-global crash interception does; runtime-produced dumps or application-managed files can avoid it. Preserve the node agent for transparent kernel interception, offer cooperative recipes where available. | [Linux core mechanism](https://man7.org/linux/man-pages/man5/core.5.html), [.NET dump mechanisms](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dumps) |
| Piped `core_pattern` ignores `RLIMIT_CORE` | Confirmed. Enforce policy and bounds before accepting a stream. Container runtime defaults are environment-specific; inspect them rather than assuming unlimited. | [core(5)](https://man7.org/linux/man-pages/man5/core.5.html) |
| The crashing process always remains inspectable | Incomplete. `core_pipe_limit=0` does not guarantee `/proc` availability. Qualify a nonzero concurrency limit and time-bounded helpers. | [Kernel sysctl documentation](https://docs.kernel.org/admin-guide/sysctl/kernel.html#core-pipe-limit) |
| Core socket mode requires Linux 6.17+ | Supported by source inspection: `v6.17/fs/coredump.c` implements socket handling. Use pipe mode initially; kernel version alone is insufficient capability detection. | [Tagged Linux source](https://github.com/torvalds/linux/blob/v6.17/fs/coredump.c) |
| Exit 134/139 identifies a core; OOM produces one | Incorrect as a guarantee. Exit codes are clues; SIGKILL/OOM does not yield a kernel core. Use actual signal/core reports and pre-OOM thresholds. Preserve status and pressure even without a dump. | [signal(7)](https://man7.org/linux/man-pages/man7/signal.7.html), [Pod lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/) |
| `kubectl debug` can always gather privileged diagnostics | False under ordinary Baseline/Restricted policies. Those policies restrict host namespaces and capabilities. Keep the privileged collection boundary outside workload namespaces. | [Pod Security Standards](https://kubernetes.io/docs/concepts/security/pod-security-standards/) |
| Managed Kubernetes is one support category | False. Ordinary managed worker pools, immutable images, Autopilot and serverless workers have different permissions. Require a per-node capability report. | [GKE privileged admission](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/about-autopilot-privileged-workloads), [EKS Auto Mode security](https://docs.aws.amazon.com/whitepapers/latest/security-overview-amazon-eks-auto-mode/eks-auto-mode-data-plane.html), [Fargate considerations](https://docs.aws.amazon.com/eks/latest/userguide/fargate.html) |
| Inspektor Gadget supports pcap-ng and filters | Confirmed in versioned tcpdump documentation. Reuse its packet engine; build Asservat's ring retention, policy, encryption and upload. An eBPF transport ring is not a historical incident recorder. | [tcpdump gadget v0.56.0](https://inspektor-gadget.io/docs/v0.56.0/gadgets/tcpdump/), [gadget data sources](https://inspektor-gadget.io/docs/latest/gadget-devel/gadget-intro/) |
| Short snaplen means header-only | Incorrect. The same byte count can include payload for one packet and omit headers for another. Parse and retain only approved L2/L3/L4 fields; unsupported encapsulations are dropped. A short capture containing payload is a raw artifact. | [snaplen definition](https://inspektor-gadget.io/docs/v0.56.0/gadgets/tcpdump/) plus packet-layout inference; test fixtures must prove the sanitizer |
| Pod/veth capture gives plaintext | Only relative to node transport encryption. Application TLS remains encrypted; loopback, hostNetwork, overlays, socket load balancing and duplicate observation points need qualification. | [Cilium WireGuard](https://docs.cilium.io/en/stable/security/network/encryption-wireguard/), [Inspektor Gadget tcpdump](https://inspektor-gadget.io/docs/v0.56.0/gadgets/tcpdump/) |
| Gadget client filters are a security boundary | False. Upstream explicitly warns otherwise; experimental server-side multi-tenancy now exists, so the brief is incomplete about current capabilities. Asservat uses a private service identity and performs its own target authorization; the upstream feature does not create a multi-tenancy requirement for Asservat. | [Inspektor Gadget multi-tenancy](https://inspektor-gadget.io/docs/main/devel/multitenancy/) |
| Inspektor Gadget is entirely Apache-2.0 | Incomplete. User-space is Apache-2.0; BPF templates have GPL-2.0 with Linux-syscall-note. Preserve notices and record transitive licences. | [Tagged README licence section](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/README.md#license) |
| A top-frame signature can rate-limit ingestion | Only after analysis yields frames. First use a provisional image/executable/signal/trigger key, then assign a versioned refined signature without losing occurrence identity. | Engineering consequence of staged collection; [GDB backtraces](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Backtrace.html) |
| Analysis should run the crashed image | Correct intent—matching binaries—but unsafe/incomplete execution model. Distroless images lack tools; application entrypoints are untrusted. Unpack exact image layers as inert data into trusted analyzer images. | [OCI image specification](https://github.com/opencontainers/image-spec), [GDB auto-loading security](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/Auto_002dloading.html) |
| An analyzer can have no network while contacting S3/KMS/symbol services | Contradictory in one pod network namespace. Split acquisition, offline analysis and publication into separate Jobs and identities. NetworkPolicy cannot isolate containers within the same pod. | [Kubernetes NetworkPolicy model](https://kubernetes.io/docs/concepts/services-networking/network-policies/) |
| Secret/high-entropy filtering makes extracts safe | Not a guarantee. Redaction misses contextual secrets and identifiers. Prefer bounded field allowlists, keep extracts access-controlled, classify uncertain output as raw, and track transform versions. | Engineering threat-model conclusion; no measured redaction-completeness claim |
| A shared Transit key version can be deleted to shred one case | Incorrect isolation. Shared key destruction affects unrelated artifacts; policy changes are not destruction and copies/backups matter. Default expiration deletes all object versions; stronger erasure needs a separately scoped key design. | [OpenBao Transit](https://openbao.org/docs/secrets/transit/), [Transit API](https://openbao.org/api-docs/secret/transit/) |
| Bucket lifecycle enforces an exact 72-hour access deadline and legal hold | Incomplete. Access must stop at `expiresAt`; deletion is asynchronous. Versioning, Object Lock, multipart remnants, caches and backup copies need separate controls. | [S3 lifecycle expiration](https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-expire-general-considerations.html), [Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html) |
| MCP 2026-07-28 exists; Go supports it | Confirmed by the published specification and tagged Go SDK `v1.8.0` docs. Both `2026-07-28` and `2025-11-25` are documented; one stateless Streamable HTTP endpoint is the proposed integration, still requiring client tests. | [Release announcement](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [SDK protocol guide](https://github.com/modelcontextprotocol/go-sdk/blob/v1.8.0/docs/protocol.md) |
| Roots, Sampling, Logging and DCR should not be newly adopted | Consistent with the July deprecations. No Asservat requirement needs them. Elicitation is not used as an independent second-person approval mechanism. | [MCP release](https://blog.modelcontextprotocol.io/posts/2026-07-28/) |
| Every OIDC provider is a sufficient MCP OAuth server | Too broad. Discovery, access-token audience, supported grants, client registration and step-up must be tested. An OIDC ID token is not an evidence access token. | [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) |
| Projected ServiceAccount tokens are interchangeable with OAuth tokens | Incorrect. Prefer IdP token exchange/federation; a Kubernetes TokenReview adapter is a separate explicitly configured trust path, not universal MCP OAuth compatibility. Never accept ordinary API-server audience tokens. | [Kubernetes ServiceAccounts](https://kubernetes.io/docs/concepts/security/service-accounts/), [MCP token requirements](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) |
| `sub` + `azp` fully identifies everyone | Incomplete across issuers and providers. Bind `issuer`, `subject`, normalized `client_id` and identity type, validated against the configured identity policy. A required `azp` claim cannot be assumed on every access token. | [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html), [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) |
| All persistent records belong in CRDs | Rejected. Kubernetes explicitly discourages using custom resources as application/monitoring data storage. Keep configuration/local control in CRDs, transactional hub state in PostgreSQL (ADR-023), and immutable evidence/audit in object storage. | [Custom resources guidance](https://kubernetes.io/docs/concepts/extend-kubernetes/api-extension/custom-resources/) |
| No DNS records means the domain can be registered | Not established. DNS, domain registration and trademark clearance are separate. Leave this as a publication prerequisite owned by the maintainer. | No availability or legal-clearance claim made |

## Runtime feasibility and preparation

| Runtime | Useful evidence | Constraints and preparation | Evidence |
| --- | --- | --- | --- |
| Native C/C++/Rust | ELF core, stacks, registers, memory mappings | Exact executable/libraries and DWARF/build IDs; ptrace/Yama/LSM permissions for live capture; stack extraction can fail on corrupted/missing unwind info. | [GDB core files](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Core-File-Generation.html), [Yama](https://docs.kernel.org/admin-guide/LSM/Yama.html) |
| Go | Panic trace, goroutines, pprof, native core | `GOTRACEBACK=crash` for crash cores; Delve is preferred for Go semantics; gcore does not guarantee a clean managed-runtime snapshot. Pprof endpoint access is opt-in and bounded. | [Go debugging](https://go.dev/doc/gdb), [runtime package](https://pkg.go.dev/runtime), [Delve](https://github.com/go-delve/delve) |
| .NET | Diagnostic port dumps, counters/traces, SOS summaries | Match architecture/runtime/DAC; shared diagnostic socket path and permissions matter. A host PID alone does not solve the diagnostic-port namespace problem. Dump generation may increase memory use. | [dotnet-dump](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dotnet-dump), [diagnostics FAQ](https://github.com/dotnet/diagnostics/blob/main/documentation/FAQ.md) |
| Python | faulthandler logs, native/Python stacks, core | `py-spy dump` is a stack sample, not a core file. PyStack supports live/core modes; interpreter/version coverage is qualified per pack. Native extensions need their own symbols. | [PyStack](https://bloomberg.github.io/pystack/), [py-spy](https://github.com/benfred/py-spy), [faulthandler](https://docs.python.org/3/library/faulthandler.html) |
| Node.js | Diagnostic report, CPU profile, heap snapshot | Heap snapshots can pause execution and require substantial extra memory; generating one during memory pressure can worsen the outage. Configure diagnostic report/signal behavior in the application, never assume an arbitrary signal is safe. | [Node reports](https://nodejs.org/api/report.html), [heap snapshot guidance](https://nodejs.org/en/learn/diagnostics/memory/using-heap-snapshot) |
| JVM | Thread dump, JFR, HPROF, hs_err | Runtime/JDK attachment and UID permissions; heap dumping is high impact. OOM heap dump is a JVM behavior, not a kernel OOMKill guarantee. | [jcmd](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jcmd.html), [Eclipse MAT](https://help.eclipse.org/latest/topic/org.eclipse.mat.ui.help/welcome.html) |
| CUDA | GPU exception dump, explicit GPU dump, separate host core | Runtime opt-in, supported driver/GPU/debugger combination and generated-file path required. GPU dump and host core are distinct artifacts. Skip-memory flags change diagnostic completeness. | [CUDA-GDB manual](https://docs.nvidia.com/cuda/cuda-gdb/), [CUDA-GDB sources](https://github.com/NVIDIA/cuda-gdb/) |

Commands that insist on seekable output cannot be promised as pure streams. They need a bounded memory filesystem or encrypted temporary filesystem with measured limits. Large cores and heaps are opt-in; node-local scratch is never treated as durable storage.

Profiles are a separate evidence category: Go pprof, Go runtime traces, JFR, EventPipe and sampled profiles have different units, sampling and attachment prerequisites. The [profile specification](../../specs/profiles.md) records these distinctions, source documentation, baseline semantics and MCP comparisons. They do not require building or deploying a continuous-profiling database.

## Existing projects and positioning

- **IBM core-dump-handler:** GitHub release API returned `v9.0.0`, published 2024-11-12. This supports the narrow release-date claim, not a conclusion that nobody maintains it. Its S3-oriented collection is useful prior art. [Release](https://github.com/IBM/core-dump-handler/releases/tag/v9.0.0), [project](https://ibm.github.io/core-dump-handler/).
- **Inspektor Gadget:** selected by the brief. Its Go API, packet gadget, container enrichment and growing authorization features are appropriate building blocks. Asservat still supplies incident lifecycle, encrypted retention, sharing, grants and bounded evidence queries. [Go API](https://inspektor-gadget.io/docs/main/api/golang/).
- **Kubeshark:** its current repository explicitly advertises MCP. The brief's categorical claim that existing tools do not expose captures to agents is outdated. It also documents network hooks, scheduled jobs and snapshot/webhook helpers. The requested broader native log/resource/probe/file/core workflow was not established in those sources. Current Community/Pro documentation requires successful telemetry for licence validity; this conflicts with Asservat's dependency rules. See the [detailed comparison](kubeshark-comparison.md) and [official licensing page](https://docs.kubeshark.com/en/license_portal).
- **Cilium/Hubble:** useful optional context. Recorder capabilities changed across releases; a deprecation was documented for 1.18. Do not make universal claims about every Cilium version. Inspektor Gadget avoids depending on a CNI-specific recorder. [Cilium deprecation record](https://github.com/cilium/cilium/discussions/39853).
- **eCapture and unnamed telemetry-key claims:** a targeted immutable-source audit was not completed. Do not repeat accusations about unnamed projects as established facts. Their behavior is not a premise required by this design. [eCapture repository](https://github.com/gojue/ecapture).

Asservat's proposed distinction is the combination of workload-bound dynamic recipes, multiple evidence kinds, custody/integrity, expiring action grants, sharing within the organization, and a bounded agent interface. This is product positioning, not an exhaustive novelty claim.

## What is not proven yet

The following remain experimental: managed-node core interception and restoration; node replacement gaps; packet correctness on encrypted CNIs and IPv6; zero-payload sanitizer coverage; diagnostic-port attachment; 100+ GiB stream behavior; isolated analyzers for malformed artifacts; IdP step-up and group freshness; transactional PostgreSQL hub accounting and prepaid local recovery; S3 conditional-write interoperability; two-protocol MCP clients; complete dependency egress behavior. Each has an experiment and a no-go criterion in [validation](../validation.md).

No synthetic cluster/crash experiment ran during the initial source-inspection pass. The later [packet lab](feasibility-packet-downloads.md) ran real capture and standalone BPF probes in a disposable VM-backed K3s cluster, plus encrypted S3/native-download tests. The subsequent [SQL/crash lab](feasibility-control-crash.md) exercised selected PostgreSQL races and a static local helper on native/nested-PID synthetic processes; production crash interception and distributed authority remain unqualified. A privileged `core_pattern` test in host-based Kind could affect the workstation kernel, so crash tests must use disposable VMs. Paid managed-cluster and GPU investigations require separate authorization.

## Permission automation follow-up

The [permission research](permission-automation.md) covers Kubernetes API/GitOps management, trusted namespace annotations, protected workload metadata, exact pod-exec/access-review inheritance, identity mapping and service-catalog limitations. These are planned authorization features with a separate real-cluster qualification gate; they do not reintroduce multi-tenancy.

## Ergonomics and privacy follow-up

The [ergonomics review](../ergonomics-review.md) covers all user/operator journeys and maps each friction point to revised requirements and acceptance tasks. The [privacy review](privacy-retention.md) adds Commission/EDPB guidance, administrator hard caps, derivative/copy deadlines, deletion verification, rights-request handling and limits of external AI disclosures. These are design revisions, not measured UX or compliance certification. EXP-17/18 remain release gates.

## Storms and storage isolation

The [capacity review](capacity-isolation.md) distinguishes native Kubernetes quotas, backend quota caching and kernel crash limits from the required workload-level guarantees. The design now includes transactional hub capacity reservations with staged local handoff, protected storage and separate shared burst, fair upload/analysis, workload-wide dump budgets and explicit overload outcomes. EXP-19 must verify these under load/failure; no runtime isolation measurement has yet been made.

## Accepted follow-up architecture

The user accepted [PostgreSQL hub state](../../specs/persistence.md) after reassessment, while keeping CRDs for permission/configuration authoring and object storage for evidence/audit. Multiple managing owner teams are now distinct from immutable share creators. [Packet research](packet-capture-flexibility.md) supports a checked-filter and live-peer adapter design, segmented rings and bounded plain HTTP/1 header projection; seamless integration, privacy and overhead remain EXP-02/03 gates.
