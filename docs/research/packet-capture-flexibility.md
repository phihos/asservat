# Packet capture flexibility: evidence and design boundary

Research date: 2026-10-09. The accepted direction is specified in [packet requirements](../../specs/packets.md). The source inspection below preceded the [measured follow-up](feasibility-packet-downloads.md). EXP-02 now has partial experimental evidence; its complete qualification and EXP-03 sanitization remain pending.

| Question | Source evidence | Asservat consequence |
| --- | --- | --- |
| tcpdump expressions | Gadget's versioned tcpdump documentation exposes `--pf`, PCAPNG and snaplen. The inspected v0.57 compiler uses a Go pcap-filter compiler. | Offer checked pcap syntax; qualify the supported subset, not a blanket libpcap compatibility claim. [Gadget docs](https://inspektor-gadget.io/docs/v0.56.0/gadgets/tcpdump/), [compiler source](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/pkg/libpcap-compiler/cbpf.go). |
| Updating peers without restarting capture | The inspected operator compiles filter instructions during initialization; the service API supplies run/stop/attach, not a general update-filter RPC. Lower-level TC code updates a program array. Linux map-in-map supports replacement of an inner map reference. | Build and test a bounded membership-map/generation adapter within the Gadget integration. Existing documented CLI flags do not prove hot updates. [operator](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/pkg/operators/ebpf/ebpf.go), [API](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/pkg/gadget-service/api/api.proto), [TC adapter](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/pkg/tchandler/tracer.go), [kernel maps](https://docs.kernel.org/bpf/map_of_maps.html). |
| Services and rollouts | EndpointSlices divide a Service's endpoints across objects and address families; consumers must aggregate and deduplicate them. | Follow all slices with UID/port/freshness checks; distinguish VIP observation from matching shared backend addresses. [Kubernetes EndpointSlices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/). |
| Packet size | The inspected tcpdump BPF source uses a 16-bit snaplen and truncates packet output to a fixed length. | Initial raw snaplen contract is 1–65,535, further narrowed by engine capability; zero is not a portable unlimited value. This does not implement safe HTTP extraction. [pinned source](https://github.com/inspektor-gadget/inspektor-gadget/blob/v0.57.0/gadgets/tcpdump/program.bpf.c). |
| Segmented rings | Dumpcap documents size/time rotation and ring-file counts. | Useful established UX, implemented in Asservat's own bounded Gadget output ring; this does not add dumpcap as a second privileged capture engine. [dumpcap manual](https://www.wireshark.org/docs/man-pages/dumpcap.html). |
| HTTP headers | TCP is a byte stream; HTTP/1 message boundaries require framing, and HTTP/2 compression depends on connection state. | Retain structured projected HTTP/1 headers from bounded reassembly; do not promise a protocol-aware snaplen can strip all bodies. Defer HTTP/2 plaintext parsing until qualified. [TCP](https://www.rfc-editor.org/rfc/rfc9293.html), [HTTP/1](https://www.rfc-editor.org/rfc/rfc9112.html), [HTTP/2 compression](https://www.rfc-editor.org/rfc/rfc9113.html#section-4.3.1). |

The existing TC implementation's hostNetwork behavior, CNI hook position, packet loss, generation replacement and parser cost require experiments. Neither seamless updates across all CNIs nor a production-safe HTTP parser has been demonstrated in this repository. The specification records expected behavior and the conditions that must block its advertisement.

The follow-up captured actual synthetic pod traffic with Gadget v0.57.0 and preserved a native PCAPNG through encrypted S3/TLS delivery into tshark. Real libpcap compiled all 11 sampled expressions; Gadget's default compiler rejected one IPv6 expression. The libpcap outputs passed VM kernel test-run checks through Gadget's cbpfc dependency, but are not yet injected into the Gadget operator. A separate one-attachment TCX probe followed actual EndpointSlice backend replacement using map generations. It is not the finished watch, provenance or recorder integration. Explicit VM host-loopback capture worked; automatic pod-loopback coverage, CNI-wide continuity, HTTP privacy and overhead are still unqualified. These findings reinforce the actual-libpcap compiler and explicit bounded-adapter choices; they do not introduce a custom filter language.
