# Protected identity settings implementation

Scope: partial REQ-AUT-001/002, REQ-PER-001/006/008, TASK-07 and S-01/S-02. This continues the [identity boundary](../architecture/identity-eligibility.md); it does not qualify a production IdP or enable an endpoint.

The Kubernetes adapter implements the current `PolicyReader` using one pinned installation ConfigMap with a single `identity.json` value. Its [canonical contract](../../specs/contracts/identity-settings.schema.json), [wire DTO](../../internal/contracts/identity_settings.go) and [example](../../examples/identity-settings.json) are checked offline. The existing JSON Schema library and strict bounded JSON parser are reused. Endpoint/credential selection remains in protected bootstrap; a token issuer only matches a fixed configured value. The shared installation reader also handles the separately enrolled permission-bootstrap review. No extra permission API, identity database, IdP plugin or runtime dependency is added.

The unit matrix covers current organization removal, replaced object UID, unknown/case-aliased keys, duplicate clients, false qualification assertions, empty eligibility, overlong group age, Unicode controls, wrong issuer, null arrays, duplicate JSON, oversize content, unexpected binary data, wrong namespace, deletion, slow I/O and clock rollback. The real Kubernetes fixture adds read-only, exact-resource RBAC, inability to read another protected ConfigMap, group removal and same-name recreation. Its identity claims and provider qualifications are synthetic; these tests establish configuration behavior, not successful real-provider sign-in.

`make permission-integration go-check go-architecture-check sql-check spec-check architecture-check` completed with exit 0, recorded in `test/results/identity-settings-check.log`. The run checked 23 Go packages and 54 internal import edges, 44 canonical schemas and 156 design examples. The Kubernetes fixture also ran native admission and the complete explicit-binding watch/SQL/encrypted-audit composition. Owned containers and the cluster were removed. The environment report records source hashes; future source changes do not inherit that exact-source qualification automatically.

One initial schema expression used a Unicode-escape syntax unsupported by the Go validator's regular-expression engine. Compiling the complete embedded bundle rejected it before any reader could be constructed. The expression now uses the common hexadecimal escape form; domain validation still rejects the complete Unicode control set. Both the Go and design schema checks pass.

Actual provider access-token distinction, stable group IDs, refresh membership, human/workload client separation, discovery/login/PKCE/session behavior and step-up remain required. Current upstream research confirms these are provider-specific rather than guaranteed by the label OIDC: the [RFC 9068 profile](https://www.rfc-editor.org/info/rfc9068/) specifies an access-token media type; Keycloak exposes configurable [protocol mappers](https://www.keycloak.org/admin-api/protocol-mappers) and its [group mapper implementation](https://github.com/keycloak/keycloak/blob/main/services/src/main/java/org/keycloak/protocol/oidc/mappers/GroupMembershipMapper.java) must be checked against the chosen release before claiming immutable group identifiers. A provider preference was requested while independent implementation continues; no provider is silently made a mandatory dependency.
