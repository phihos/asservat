# Kubeshark comparison

Inspected 2026-10-09 after the maintainer asked whether Kubeshark already covers this project. This is a documentation comparison, not a hands-on product evaluation. "Not established" means the reviewed sources did not demonstrate the feature; it is not proof that an extension cannot implement it.

## What overlaps

Kubeshark's documented product covers retrospective packet snapshots, network/API inspection, Kubernetes identity enrichment and MCP access. Its scripting documentation also provides packet/L7 hooks and scheduled jobs. It would be inaccurate to call it only a manual snapshot tool or claim that it lacks programmable triggers. [Product documentation](https://docs.kubeshark.com/), [automation hooks](https://docs.kubeshark.com/en/automation_hooks).

| Capability | Kubeshark evidence | Asservat's intended scope |
| --- | --- | --- |
| Historical packet snapshots | Documented | Packet evidence as one action among several |
| L4/L7 traffic inspection and TLS diagnostics | Documented; detailed network specialization | Bounded packet/flow extracts; avoid trying to rebuild a complete traffic-analysis dashboard |
| MCP | Documented for network queries/snapshots | Shared case model across packet, file, process, runtime and crash evidence |
| Programmable network triggers | Packet/item/query hooks, scheduled jobs | Typed log/resource/probe/crash/network expressions with hold windows, missing-data semantics and lifecycle-aware identities |
| Trigger actions | Snapshot/file manipulation and webhook helpers documented | Container-root/pseudo-file capture, live/kernel cores, profiles and custom in-container commands under action grants |
| Files | Worker-side file helpers exist | Explicit target-container/process namespace access and confinement; worker filesystem helpers are not evidence of equivalent container access |
| Native log/CPU/memory/PSI/probe detectors | Full requested native set not established in reviewed docs | First-class local sensors with defined gaps/freshness and no Prometheus requirement |
| Runtime core/heap diagnostics | Full requested native set not established | Qualified independent runtime packs and matching symbol/rootfs acquisition |
| Combining non-network evidence in one incident | Not established | Immutable occurrence/action/manifest model and common provenance |
| Expanded access via explicit evidence shares within the organization | The particular grant composition required here is not established | Artifact-snapshot user/group shares, raw approval, revocation and organization identity eligibility |

Traffic hooks and scheduling are described in [Hooks](https://docs.kubeshark.com/en/automation_hooks). Snapshot, webhook and worker-file operations are described in [Helpers](https://docs.kubeshark.com/en/automation_helpers). MCP capabilities are described in the [official MCP article](https://kubeshark.com/post/kubeshark-mcp-kubernetes-network-traffic-for-ai-agents). Some automation pages are outside the current navigation's main workflow, so exact edition/version availability should be tested before depending on them.

## Dependency suitability

The current licensing documentation says Community and Pro require internet connectivity and successful telemetry for licence validity, while air-gap operation is available for Enterprise. It also describes licence attributes including expiry. That conflicts with this brief's no-call-home/no-licence-key requirements as documented, regardless of the licence of individual open repositories. [Licence portal](https://docs.kubeshark.com/en/license_portal), [air-gap installation](https://docs.kubeshark.com/en/air_gapped).

This is sufficient to reject the documented product as a mandatory Asservat dependency. It is not a statement that every historical source version or every Kubeshark component has identical licensing/network behavior. A fork or embedded component would need its own maintenance, source, licence and egress review; the current plan does not depend on one.

## Architectural consequence

Keep Inspektor Gadget for packet collection, as the brief already decided. Invest Asservat engineering in generic trigger/action orchestration, durable evidence, runtime diagnostics and access control. Borrow useful interaction ideas—retrospective time selection, clear packet-loss indicators, narrowing queries—without copying its implementation or claiming feature novelty.

An operator could later feed an authenticated external network alert into Asservat's existing alert adapter, including one generated by a separately operated network product. Such an integration would not make that product a dependency, confer new target rights, or let untrusted webhook contents become commands. It is not necessary for the first release.

## Accepted live-view extension

The maintainer subsequently requested [live observation](../../specs/live-watch.md). Asservat now specifies finite packet/HTTP/syscall approved live projections, independent display filters, pause/resume, gaps and explicit saving through UI/MCP. This extends the earlier bounded-inspection scope without attempting full Kubeshark protocol/dissection parity or introducing a dependency. Raw live payloads remain outside the selected first-release boundary; save then use existing artifact review. [Live-view research](live-watch.md) distinguishes documented upstream behavior from unqualified Asservat adapter work.
