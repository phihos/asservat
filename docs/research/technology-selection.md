# Technology selection and feasibility evidence

Research date: 2026-10-09. The [maintenance review](dependency-maintenance.md) applies the maintainer’s preference for established, actively maintained dependencies. The [stack](../technology.md) records selected engineering choices; the [component matrix](../architecture/build-or-reuse.md) records integration work. User acceptance of React/TypeScript is explicit. Other engineering selections are implementation recommendations within the reviewed architecture, with release qualification still required.

## Artifact layout decision gate

Select Tink and zstd now; keep the **persistent large-artifact layout unfrozen** until this small but consequential integration is qualified. The current manifest schema accepts `tink-streaming-aead/v1`; the experiment does not silently introduce a second wire format. The existing download contract's bounded restart fallback remains valid, but routine full rereads of huge cores are not an acceptable target experience for resumable downloads.

The preferred candidate is one physical artifact object containing independently compressed frames, each protected as a complete Tink streaming ciphertext, plus a protected index. Use a fresh keyset per physical object and library-generated stream headers; never implement custom nonce arithmetic or splice Tink internals. Bind artifact/version/frame order/native offset in canonical AAD. Encrypt/authenticate offsets, lengths and per-frame checksums as sensitive metadata; authenticate the index before using it. Whole-native-file and whole-stored-object SHA-256 remain distinct. Do not expose frame boundaries in the downloaded native file.

Qualification must compare sequential small-file storage with 8/16/32 MiB native frame candidates using compressible and incompressible synthetic cores/PCAPNG. Measure startup/resume latency, read amplification, RSS, compression loss, frame/index overhead and full-download throughput. Bound index pages, frame counts, decoder memory and worst-case encrypted size before reserving capacity. Decide whether index pages are within the object or separate managed objects, and include every copy/object in retention/accounting. No one-object-per-small-frame explosion, plaintext scratch or KMS request per frame.

Test index corruption/substitution, truncated last frame, reordered frames, decompression bombs, range overflow/If-Range changes, cancellation, mid-transfer expiry/revoke, interrupted multipart and restore. Partial authenticated chunks are not automatically a committed partial artifact. Commit must authenticate the exact complete index/object identity; salvage needs an explicit new artifact and truthful completeness. Publish a versioned format/schema/fixtures before enabling it. This is an S-00/S-02 release gate under REQ-EVD-001/002 and REQ-DLD-001–004, not a demand for the user to design encryption.

## Nonprivileged experiments actually run

See [reproduction instructions, logs and locked inputs](../../experiments/technology-selection/README.md). Six Go tests passed: standard-library RFC 8785 canonicalization, all-contract offline compilation, encrypted/compressed stream validation, explicit-algorithm JWS, native packet/filter handling, and independent-frame range composition. The frontend static build passed. Direct TS generation produced output that failed type checking; a reference-hoisted bundle generated output that passed strict tsc. Go generation still failed after hoisting, on a multi-type union. The initial npm version set failed compatibility resolution. Both failures are retained as evidence.

No live interface was opened, no real workload or evidence was used, and no cluster/host crash settings were changed. These tests do not prove kernel safety, dynamic packet-filter updates, runtime overhead, S3/KMS compatibility, IdP integration, database races, browser journey usability or no-call-home behavior. A package licence label is not a complete redistribution/security assessment.

## Subsequent VM and object-store experiments

The [first mechanism spikes](feasibility-packet-downloads.md) followed that nonprivileged pass. They add actual Gadget capture in a new disposable Kubernetes VM, a sampled real-libpcap/kernel corpus, standalone live EndpointSlice map replacement, a race-tested ring model and encrypted multipart/native-range delivery against a real isolated S3 fixture. A downloaded Gadget PCAPNG opened in tshark with the original SHA-256. A generated 2 GiB artifact used approximately 133 MiB peak test-process RSS; its last 1 MiB required about 8 MiB of ciphertext with 8 MiB native frames. These are bounded local measurements, not production guarantees.

The experiments support retaining Gadget, actual libpcap, Tink and zstd, and using 8 MiB independently compressed/encrypted frames as the next prototype baseline. They also exposed Gadget's rejection of one valid IPv6 expression and a corrected download-finalization bug. Integration into Gadget, the production format/key/commit contract, Ceph/OpenBao, authentic authority and operational recovery remain open. No production enum or new required service is introduced. The subsequent [PostgreSQL and crash-helper spikes](feasibility-control-crash.md) now provide limited real transaction/kernel evidence and reinforce post-lock expiry checks, bounded handoff and explicit completion. Their full production gates below remain open.

## Remaining qualification, ordered by consequence

| Gate | Required concrete result | Decision if it fails |
| --- | --- | --- |
| Large native download/storage | Format vectors plus real object-store range, corruption, expiry and memory tests; open exact native PCAPNG/core/profile with compatible local tools | Rework storage layout before production format freeze; never remove native download |
| Gadget packet integration | Actual libpcap-compiled semantics including link types/IPv6; live peer generations without hook restart; gap/loss metrics; bounded HTTP reassembly | Qualify a minimal pinned Gadget extension/upstream change; report unsupported combinations rather than widening the filter |
| Syscall modes | Metadata implementation proven not to read user memory; bounded maps/rings, process and ABI coverage | Keep unqualified mode unavailable; no ptrace fallback that changes impact/privacy |
| Kernel core path | Disposable-VM core pipe: absent receiver, resource pressure, remote outage, timeout, helper uninstall and exact process fidelity | Narrow support or redesign local handoff; language choice alone proves nothing |
| SQL authority/identity | Real PostgreSQL races/restore; grant revocation/expiry; actual OIDC/SAR mappings; monotonic work fencing | Fix transaction/identity design before collectors can act |
| Contract fidelity | Full positive/negative corpus in Go/TS, duplicate JSON keys and numeric bounds, unions/conditionals, canonical bytes and UI/MCP parity | Retain explicit DTO adapters; do not weaken authoritative schemas to satisfy a generator |
| Operator readiness and delivery | Exact images/toolchain/OS packages, encrypted CSI, backend semantics, transitive licences/CVEs/SBOM, mirrored offline install, measured attempted egress | Do not advertise the affected deployment profile as qualified |
| Developer completion | Ordinary developer captures, downloads, opens locally, shares and repeats without implementer help; failure paths included | Fix workflow/approval defaults; a successful build is not user success |

Rust remains confined to the core helper. No benchmark in this pass establishes that Rust is faster or safer than a comparably bounded Go helper; the choice is a small native failure-path artifact with a deliberately tiny dependency surface. Revisit ADR-006 if measured maintenance or kernel-path behavior defeats that benefit.
