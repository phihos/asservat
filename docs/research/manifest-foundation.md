# Complete pod-status verification record

Date: 2026-10-09. This continues the [artifact](artifact-foundation.md) and [custody](custody-foundation.md) components. The [verification contract](../architecture/manifest-verification.md) describes the supported profile and why successful verification still leaves evidence unpublished. This is partial S-01/S-02 implementation, not a complete investigation service.

Subsequent [identity/eligibility work](identity-foundation.md) adds verified access-token and ordinary permission components. Its current-policy readers are still test projections; it does not yet replace the synthetic accepted execution facts used in this record or provide durable audit/publication.

Implemented: an explicit expected-context value, canonical native pod-status schema, offline embedded manifest/commit/native validators, full-manifest encoding and semantic checks, a separately wired S3/KMS verifier, and a coordinator that stores receipts only after that verification. Existing encryption, fixed object layout, copy reservations and conservative storage accounting are reused. No production execution authority, durable audit, signed manifest, catalog publication or download endpoint is claimed.

The runtime validator uses the already selected `github.com/santhosh-tekuri/jsonschema/v6` **v6.0.3**, explicit Go DTOs and standard-library `encoding/json/jsontext`. This reuses the selected JSON Schema implementation rather than introducing another schema language or a generated partial Go model. The implementation enables format assertions, denies remote loading and bounds strict parsing before validation. Primary references: [upstream validator](https://github.com/santhosh-tekuri/jsonschema), [v6 API](https://pkg.go.dev/github.com/santhosh-tekuri/jsonschema/v6), [jsontext API](https://pkg.go.dev/encoding/json/jsontext). These library capabilities are distinct from the measured integration below.

## Real-service integration

`make context-integration` passed with the race detector against two owned Kubernetes clusters and private OpenBao, S3 and PostgreSQL fixtures. The [test log](../../test/results/context-storage.log) and [environment/source report](../../test/results/context-storage-environment.json) contain actual results, exact image pins, source hashes and cleanup outcomes. The fixture's read-only collector still reads only the pinned pod/namespace; the fixture administrator resolves node/boot/workload identities without granting the collector node or exec access.

For each cluster the new test registered capacity before key preparation/acquisition, prepared all three wrapped keys, collected bounded pod status, wrote data/index/full encrypted manifest/envelope, independently verified the entire chain, and stored the exact four receipts in PostgreSQL. Changing the expected audience caused rejection and left custody `reserved`. Valid verification plus identical replay produced one stored event, retained the original conservative charge and ended `stored_unpublished`. Native hashes were absent from the SQL copy receipts. The existing separate context/KMS/range-read and real OpenBao role-denial cases also passed.

`make custody-integration` separately passed all nine existing real PostgreSQL/S3 scenarios, including last-slot contention, duplicate reservations/receipts, post-lock expiry, protected neighboring workload capacity, version/marker/multipart removal and stale deletion fences. This preserves earlier storage behavior; it does not make the new context test's synthetic authority real.

The fixture uses synthetic audience, plan, policy and collector-digest facts. Matching them is a semantic consistency test, not an IdP/configuration/grant or image-attestation test. OpenBao runs in-memory dev mode; S3 uses the existing test backend; PostgreSQL is a single primary; private backend hops remain plaintext behind verified client-facing TLS bridges. Broad fixture S3 credentials do not qualify production prefix IAM. Cleanup removes all owned clusters, containers, anonymous volumes, network and fixture credential files. No privileged collector or host kernel setting was changed.

## Negative and mechanical checks

Manifest tests reject substituted cluster/artifact/case/occurrence/pod/namespace/boot identity, unexpected container scope, audience/plan/collector/policy changes, class promotion, later deadlines, false parents/completeness and mismatched object identities/hashes/sizes. Native tests reject hidden argument/environment/label/message/container-name fields, impossible counts and observations outside the collection interval. Envelope tests reject wrong identities, duplicate keys and trailing documents, while allowing explicitly null unversioned storage identities.

Parser tests reject invalid Unicode, unpaired surrogates, duplicate keys, excessive depth/bytes, oversized numbers and noninteger exponent notation. The bounded fuzz campaign passed **88293 executions** in approximately 16 seconds; it is a robustness sample, not exhaustive parser or resource-use qualification. [Fuzz log](../../test/results/manifest-fuzz.log).

`make go-check go-architecture-check sql-check manifest-schema-check` passed vet/race tests, the 12-package/19-edge import check, three unchanged sqlc outputs and eight byte-identical embedded schemas. [Go gate log](../../test/results/manifest-go-check.log). `make go-vuln-check` found zero affected code/imported packages; its module-only advisory remains subject to the existing prohibited OpenPGP import rule. [Scan log](../../test/results/manifest-vuln-check.log).

All seven design gates passed: specification, architecture, design, OpenAPI, downloads, combined investigation and live watching. The specification gate checked 43 schemas, 155 examples, 171 requirements/scenarios and 329 rejected invalid examples. [Design gate log](../../test/results/manifest-design-checks.log). These are contract/component checks, not UI/MCP workflows, user studies, production deletion or full EXP acceptance. Earlier successful reports are retained under `context-storage-before-manifest.*`, `custody-before-manifest.*` and, for the run before dependency-lock tidying, the `*-manifest-initial.*` files.

Starting the final two fixture suites concurrently exhausted Docker's available default network subnets before the custody lab created any service. The [failed fixture log](../../test/results/custody-network-exhaustion.log) and [report](../../test/results/custody-network-exhaustion.json) preserve that infrastructure failure; it is not a product-test pass. Run these labs sequentially on this host so each releases its owned network before the next starts. No unrelated network or cluster is removed to make room.
