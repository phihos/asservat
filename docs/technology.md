# Technology choices and dependency review

Status: technology baseline selected for implementation planning, inspected 2026-10-09. React/TypeScript is explicitly accepted by the maintainer; the engineering selections below still require their stated integration/release qualifications. A dependency is not approved merely because its repository licence is acceptable. Exact image digests, all transitive packages, build provenance, source notices and egress tests are release requirements.

Read the [component build/reuse matrix](architecture/build-or-reuse.md), [research and remaining gates](research/technology-selection.md), and [reproducible experiments](../experiments/technology-selection/README.md). Observed versions are research snapshots, not a claim that every combination is qualified.

Subsequent [packet/download feasibility experiments](research/feasibility-packet-downloads.md) provide real Gadget/Kubernetes and S3/TLS evidence, including native PCAPNG opening and a 2 GiB framed artifact. They support the selected libraries without freezing the production format or qualifying the full adapters. The isolated SeaweedFS fixture is test evidence, not production qualification. [Small-deployment research](research/small-deployments.md) now separately recommends bundled SeaweedFS alongside the external Ceph reference.

The follow-up [SQL/crash-path lab](research/feasibility-control-crash.md) used PostgreSQL 18.6/pgx v5.11.0 and a static Rust 1.96.1 helper with libc 0.2.190. It supports keeping those choices, with explicit post-lock expiry checks and bounded local IPC. It does not qualify production SQL recovery, key wrapping or Kubernetes crash attribution. The experimental GNU-linked helper's ELF ABI note names Linux 6.1; qualify a compatible pinned build environment before claiming the proposed 5.15 floor or arm64 support.

HashiCorp Vault API compatibility is an adapter goal, not a recommendation to ship current Vault as an open-source dependency. Current licensing must be reviewed independently. Likewise, an operator's proprietary Kubernetes/GPU platform is an environment prerequisite, not bundled Asservat code; the core platform must remain functional without GPU integrations.

Keycloak is a reference provider for interoperability tests, not a bundled mandatory installation. A production Keycloak deployment has its own database requirements; this plan does not hide that service inside the Asservat chart. Reuse an operator's qualified IdP or select the planned internal identity provider under [ADR-063](decisions/063-small-deployment-alternatives.md). Local accounts use the existing hub PostgreSQL with dedicated identity authority; an external IdP's storage remains separately operated and isolated. Reusing a PostgreSQL service does not mean sharing its database roles or schema.

## No-call-home qualification procedure

For each exact image and tool: enumerate executable entrypoints and package hooks; inspect outbound-client code/default endpoints; run startup, collection, analysis, shutdown, error paths and scheduled timers with public egress and external DNS blocked; record attempted destinations as well as successful connections. Permit only operator-selected Kubernetes, hub, S3, KMS, IdP, registry, symbol and webhook endpoints. Distinguish intentional local Prometheus metrics from third-party reporting. If an unwanted request is attempted, disable/remove its code path and rerun; a firewall silently blocking it is not proof of no call-home.

NetworkPolicy alone does not control every privileged/host-network packet. The qualification environment needs VM/host firewall enforcement and network observation outside the collector. Mirror all transitive images/gadgets/build inputs and include hashes/licences in a release bill of materials. Re-run on dependency upgrades. None of these end-to-end results is claimed yet.

## PostgreSQL and packet additions

PostgreSQL 18 is the first qualification baseline; managed, operator-provided or planned Helm-bundled service, dedicated database/roles, TLS and finite encrypted backups. Qualify failover when HA is offered; bundled single-instance mode explicitly reports downtime and lacks automatic failover. No mandatory extension or operator. PostgreSQL uses the [PostgreSQL License](https://www.postgresql.org/about/licence/); exact images, extensions, backup tooling and egress still require release review. Use native pgx v5/pgxpool with sqlc-generated query bindings and goose-managed explicit SQL migrations; no ORM or workflow engine. This refines the earlier database/sql adapter recommendation: only PostgreSQL is supported, so one native pool/transaction API is sufficient. A migration-only database/sql connection may be used by goose; it does not add a second application persistence API. [pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool), [sqlc](https://github.com/sqlc-dev/sqlc), [goose](https://github.com/pressly/goose). Driver retry must never repeat an ambiguous remote action. CloudNativePG remains optional; [the small deployment recommendation](research/small-deployments.md) uses a limited first-party StatefulSet and pgBackRest without requiring a database operator.

Packet enhancements keep the Gadget engine. Asservat owns the qualified live-peer map adapter, bounded ring and protocol projection pipeline. Do not replace this work with an unbounded tcpdump sidecar or assume the Gadget CLI supplies a runtime filter-update API. Plain HTTP/1 is first; advanced protocols remain capability-gated. See [source findings](research/packet-capture-flexibility.md).

The measured compiler comparison reinforces actual libpcap compilation: Gadget's bundled compiler rejected one valid IPv6 sample that libpcap accepted and the VM kernel executed after translation. Feed qualified native bytecode through an explicit pinned Gadget integration; a passing standalone map test does not complete that adapter. For storage, ADR-048 now fixes 8 MiB native frames with complete library-managed Tink streams and a paged encrypted index. The [first implementation](research/artifact-foundation.md) leaves backend, retention and commit qualification explicit.

## Reusable profiles and syscall adapter

Use data-only CaptureProfile CRDs plus the existing Go plan compiler, JSON Schema/CEL/admission and PostgreSQL configuration projections. Literal typed overrides replace a new template/interpreter dependency. The Python fixture compiler in this repository checks design examples only; it is not the production controller.

Inspektor Gadget traceloop is the syscall integration candidate within the chosen engine. Upstream documentation establishes argument-bearing tracing, not Asservat's no-user-memory-read metadata mode or bounded accounting. Pin and inspect the selected source/image, then qualify an adapter under EXP-22; unsupported modes remain unavailable. See [research evidence](research/capture-profile-feasibility.md). No additional tracing daemon or ptrace fallback is selected.

## Offline analysis storage prerequisite

Accepted ADR-036 requires operator-provided encrypted CSI-backed scratch StorageClass qualification for separate-Job analysis. Per-analysis input/output PVCs need explicit writer fencing, read-only handoff, capacity/key/reclaim/snapshot constraints and independent verified cleanup under REQ-EVD-005/008. Prefer qualified ReadWriteOncePod exclusivity where supported; access modes alone do not prove encryption or deletion. No specific CSI product is selected without platform testing. This prerequisite applies to analysis; missing qualification does not discard safely collected encrypted evidence.

## Application packaging and internal contracts

The [implementation architecture](architecture/README.md) fixes the modular Go package graph, shared role-selecting executable and separate authority/image boundaries. Internal control remains bounded versioned JSON over mTLS; nodes initiate connections to the private connector service. Signed work selects standard JWS with the explicit Ed25519 identifier; [source rationale and qualification](architecture/research.md) distinguish this from evidence encryption and OAuth/TLS provider choices. Library/key-provider support is a release gate, not an implemented claim. No new broker, workflow engine, Go module per component or frontend runtime is introduced.


The maintainer requires established, actively maintained libraries wherever possible. The [maintenance review](research/dependency-maintenance.md) and [source snapshot](research/dependency-maintenance-snapshot.json) document the selection screen and outstanding supported-branch/security checks. Unmaintained dependencies are not accepted merely because they pass a functional test.

## Production console

Use React Aria Components for accessible buttons, fields, menus, dialogs and table interactions, styled with the current native CSS tokens. Use React Router in library mode for normal URLs and shared route context. Use TanStack Query for bounded server metadata, and React local state/reducers for forms and finite live views. Avoid Redux, a second table framework, a CSS utility framework and a general visualization framework until a concrete gap justifies them. Tables are paginated; any virtualization must preserve keyboard/screen-reader use. Profile charts/flame views may use a separately qualified focused renderer; do not embed an external profiling product.

The initial product console locks React/react-dom 19.3.0, React Aria Components
1.22.1, Vite 8.3.4 and TypeScript 5.9.3 in `web/package-lock.json`. The
experimental TanStack Query 5.104.1 and React Router 8.4.0 choices remain planned
for server-data pages and multi-page routing, not unused dependencies in the
session-only build. TypeScript 7.0.2 was rejected by the current generator's
declared TypeScript 5 peer requirement; no force/legacy-peer override is used.
Node is build-only; qualify a supported LTS version for the eventual release
toolchain (this continuation uses local Node 26.11.1). Dependency lifecycle
scripts are disabled; no remote fonts, CDN imports or runtime package downloads.
Preserve all prototype workflows as implementation expands.

Go embeds or packages hashed assets with the API image. Serve a small app shell and assets on the existing origin; preserve server-side login/callback/CSRF handling. Assets may be immutable cached; session/API/evidence responses remain private/no-store. SPA fallback applies only to recognized console paths, never API/content/error paths. A strict CSP has no unsafe-eval dependency, and browser source maps are not published by default. Production does not use Vite's development server.

Client state is a usability concern, not an authorization cache. Clear scoped caches on logout/identity change; abort requests on navigation/cancel and discard late unauthorized results. No localStorage/IndexedDB/service-worker persistence for evidence or grants. Explicitly disable automatic mutation retry and uncontrolled focus/reconnect refetch. Finite live polling follows the protocol cursor/expiry and stores at most the permitted rows/bytes; it does not use an unbounded infinite query. Do not cache evidence globally through TanStack defaults. Deadline/revocation signals clear visible evidence; current server checks remain decisive.

Download links use the authenticated same-origin transfer flow and browser download manager; do not load a multi-gigabyte artifact into a JavaScript Blob. Status/control JSON remains separate from the native byte stream. The UI says compatible local tool and reports native media type, checksum and companion availability, without prescribing GDB for every core.

TS types are generated from reviewed OpenAPI/contracts; no second handwritten public API vocabulary. Go wire DTOs are explicit until generator fidelity is established. Validate untrusted inputs using authoritative schemas and implement domain conversions separately. Generation cannot enforce grants, freshness, transaction invariants or decoded-byte budgets. Build-time generation must resolve local schemas only; browser bundles contain no remote schema loader or runtime schema compiler requiring eval.

Use portable Make targets, pinned multi-stage OCI builds, Helm charts, digest-locked runtime packs, mirrored module/npm/crate caches, SBOM/licence notices, vulnerability review and offline cosign verification. Go services can use minimal non-root images; node images need their actual qualified libc/libpcap/native dependencies, and analyzer packs need their trusted tools. Do not promise every role is one static distroless image. Pin OS packages and compiler/Clang versions with images. Keep optional diagnostic packs out of the base control image. An operator's already-qualified infrastructure is reused; no particular CI host, registry or cloud provider is imposed.
