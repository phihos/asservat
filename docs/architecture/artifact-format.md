# Persistent artifact format and commit boundary

Decision: ADR-048. Implements the storage detail behind REQ-EVD-001–003 and REQ-DLD-001/003. The first product codec is `asservat-framed/v1`; the earlier `tink-streaming-aead/v1` examples remain illustrative legacy contracts, with no product reader or existing production data to migrate. Capability negotiation must name the supported format explicitly. Neither format name permits reinterpretation of the other.

This document fixes the byte layout for implementation. It does **not** qualify a production object backend, KMS deployment, hub commit transaction or download endpoint. [Implementation evidence](../research/artifact-foundation.md) separates implemented components from the remaining S-01/S-02 work.

[ADR-064](../decisions/064-local-key-material.md) adds a versioned local wrapping backend through the same key ports. Its opaque reference/ciphertext replace only the provider wrapper; the native file, framed data/index/manifest and custody contract are unchanged. Root keys belong in the isolated key-service process. The [local foundation](local-keys.md) and [private service boundary](local-key-service.md) supply crypto and authenticated transport components; production authority/bootstrap remain required before small-mode collection.

## Native files and physical objects

The native file remains unchanged. PCAPNG stays PCAPNG, a core stays its recorded native dump format, and a context projection is ordinary JSON. Storage compression removes only Asservat's wrapper; intrinsic compression in a pprof file, archive or other native format is preserved.

Each attempt uses four immutable keys:

```text
v1/{clusterUUID}/{artifactUUID}/{attemptUUID}/data
v1/{clusterUUID}/{artifactUUID}/{attemptUUID}/index
v1/{clusterUUID}/{artifactUUID}/{attemptUUID}/manifest
v1/{clusterUUID}/{artifactUUID}/{attemptUUID}/commit
```

UUIDs are canonical lowercase, nonzero identities; names, paths from the target, label values and user reasons never enter object keys. Keys cannot be reused, even after expiry/deletion. Every retry that acquires new bytes receives a new attempt and fresh keys. Receipt reconciliation for the same attempt never reacquires bytes.

| Object | Representation and bound |
| --- | --- |
| data | Concatenated complete Tink streams, one per native frame. Native frames are 8 MiB except the last; an empty file has one authenticated empty identity frame. Native size is at most 1 TiB. There is no extra delimiter/header between streams; the authenticated index supplies exact offsets. |
| index | Concatenated complete Tink streams containing JSON pages. At most 256 frame entries per page, 512 pages, 256 KiB decoded JSON per page. No compression. The encrypted manifest contains the page directory. |
| manifest | One complete Tink stream containing the detailed `artifact/v1` manifest, including the framed layout and exact data/index object identities. At most 1 MiB decoded JSON. Full evidence metadata, native hashes and wrapped data/index keys remain encrypted. |
| commit | At most 32 KiB plaintext JSON matching `artifact-commit/v1`: opaque cluster/artifact/attempt IDs, format and the manifest's ciphertext digest/size, exact object identity and wrapped manifest key. This is a storage receipt, not hub publication or a bearer capability. |

Schemas: [layout, index and commit](../../specs/contracts/framed-storage.schema.json), [detailed manifest](../../specs/contracts/manifest.schema.json). The `storageObjects` field pins data/index ETags and, when supported, version IDs. The commit envelope pins the manifest identity. The envelope's own identity/digest is pinned in the verified custody record. Unversioned backends use `versionID: null`, conditional creation, immutable attempt keys and exact ETag comparisons; they do not pretend to supply versioning.

Control-audit consumers can explicitly use `objectstore.NewVersionedAudit` to
require nonempty, non-`null` versions at write acknowledgement, reconciliation
and pinned reads. The existing evidence format and legacy constructor retain
their original contracts. This stricter adapter does not establish backend IAM,
capacity or recovery; [audit-store qualification](../research/audit-storage-qualification.md)
records its real-service evidence and the fresh installation profile's remaining
gates. An unacknowledged write remains a possible physical copy to account for
and delete.

Every data frame uses either identity encoding or one complete independent zstd frame. Use zstd only when its output is smaller than the native frame. Decoder window and output are limited to 8 MiB; no shared dictionaries, cross-frame compression, guessed codec, or arbitrary decompressor. Each encrypted data frame is bounded by native bytes plus 64 KiB. The deliberately conservative overhead budget is enforced; changing library overhead does not silently raise it.

Index entries contain sequence, native offset/length, ciphertext offset/length, codec and both SHA-256 hashes. The page directory additionally contains contiguous data/index spans and each encrypted page's hash. Root totals/hash fields must equal the detailed manifest's native/data size and hash fields. `sizes.ciphertextBytes` and `hashes.ciphertextSHA256` describe the data object only; index, manifest, envelope and all other copies have their own capacity charges. Object ETags are opaque identities, never integrity hashes.

## Cryptography and key scope

Use Tink `AES256_GCM_HKDF_1MB`, with a fresh keyset for each of data, index and manifest. Readers accept exactly one enabled RAW primary key: AES-GCM-HKDF key version 0, 32-byte key material, 32-byte derived key, SHA-256 and 1 MiB ciphertext segments. Other Tink-supported suites are not implicit format compatibility. Independent streams within one physical object share that object's keyset; Tink generates each stream's random salt/nonce material and authenticates its internal segments. Asservat does not implement or persist custom nonces. Never restart encryption into an existing committed stream. [Tink's streaming primitive](https://developers.google.com/tink/streaming-aead) defines these cryptographic properties.

Prepare and wrap all three keysets before opening the source. The collector has only wrap permission, the regional reader only its currently authorized unwrap permission, and the hub has neither. Tink's ordinary encrypted-keyset writer performs a decrypt self-check; it cannot be used with a wrap-only collector. The adapter therefore serializes the small keyset into bounded process memory, wraps it, and clears its temporary byte buffer as best effort. No clear keyset file, Go zeroization guarantee or memory-only production recovery fallback is permitted.

The OpenBao adapter uses a fixed operator-configured Transit mount/key and encrypts a bounded JSON payload containing `format: asservat-keyset/v1`, `bindingSHA256` and base64 Tink binary keyset. On unwrap it checks the binding digest before parsing the keyset. The binding lives inside authenticated Transit ciphertext; this does not rely on a caller-controlled context field or on enabling derived Transit keys. Invalid/foreign key references fail before a KMS request. Credentials, keysets, raw KMS responses and evidence never enter ordinary logs. [OpenBao API client](https://pkg.go.dev/github.com/openbao/openbao/api/v2) is the maintained protocol implementation; deployment/key-backup/rotation qualification remains separate.

OpenBao/Vault therefore sees the small encryption keys and their bindings; it never receives artifact payloads. Each prepared attempt needs three storage key-wrap operations, regardless of dump size, compression ratio, number of 8 MiB frames or multipart upload parts. A reader that opens manifest/data/index unwraps three keysets and then decrypts frames locally. These counts exclude separate audit, identity and signing work, new readers, retries and derivative artifacts. The keyset limit is 4 KiB; the actual current template serialized to 131 bytes in the synthetic constant-call regression. That measurement is not a frozen serialization size or a provider throughput claim. [Vault's envelope-encryption explanation](https://developer.hashicorp.com/vault/docs/secrets/transit/envelope-encryption) describes the same separation between payload and key encryption; [OpenBao Transit](https://openbao.org/docs/secrets/transit/) provides the bounded encrypt/decrypt operations used here.

The regression `TestArtifactKeyCallsIndependentOfPayloadSize` covers empty, 4 KiB and 16,777,295-byte native files, verifies full readback, and checks that later range reads invoke no extra key calls. Provider burst qualification must additionally include aggregate admission, authentication/audit overhead, failure/retry pressure and caller replicas under REQ-CAP-003. The crash path uses unique prewrapped attempts and never asks the host helper to make a network call.

Every Tink stream and wrapped-key payload uses canonical RFC 8785 associated data with **all** these fields:

```json
{"format":"asservat-framed/v1","schema":"artifact/v1","clusterID":"UUID","artifactID":"UUID","attemptID":"UUID","mediaType":"native type","role":"data","sequence":0,"nativeOffset":0,"nativeBytes":8388608,"codec":"identity"}
```

The illustration is not canonical byte ordering. The implementation canonicalizes with Go's standard library. All integers are nonnegative and below 2^53. Data roles bind frame sequence/offset/length and `identity` or `zstd`; index roles bind page number/native span and `json`. Key roles are `data-key`, `index-key`, `manifest-key`, with sequence/offset/length zero and codec `none`. Manifest role has zero numeric fields and codec `json`. Manifest and manifest-key AAD use the fixed media type `application/vnd.asservat.manifest+json`, so bootstrapping does not require exposing the evidence's native media type in the envelope. The native type is then verified inside the decrypted manifest and data/index bindings.

## Bounded writes, reads and corruption behavior

For native limit L, reserve N = max(1, ceil(L / 8 MiB)) frames and P = ceil(N / 256) index pages. Reserve data capacity L + N × 64 KiB, index capacity P × 320 KiB, manifest capacity 1088 KiB and envelope capacity 32 KiB, plus all admitted copies, multipart/staging obligations and audit resources. Reserve four final object slots, even for an empty file. At 1 TiB native this permits 131072 frames and 512 pages; the index ceiling is 160 MiB. Do not apply a native-byte grant ceiling to ciphertext overhead accounting.

The encoder holds a frame and one index page, with bounded compressor/encryptor working memory; it never retains a full native artifact or full index. It may consume one extra source byte to detect overflow, but never emits/retains it. Actual acquisition adapters separately enforce source/output/time limits. A source I/O error fails the attempt. Deliberately truncated evidence needs an explicit acquisition completeness result and correctly finalized ciphertext; a storage EOF alone cannot declare a native diagnostic file complete.

A native range loads only its overlapping index pages and data frames. Each page is fully authenticated, checked for strict JSON and contiguous ranges, and each selected data frame is fully authenticated/decompressed/hash-checked before delivering any of that frame. A range can decode at most its requested native length plus two boundary frames; index work is the intersecting pages, each bounded by 320 KiB ciphertext. Reserve this work and worst-case ciphertext overhead before reading. Unknown formats, malformed directories, gaps/overlaps, changed versions, wrong AAD, overflow and trailing/truncated ciphertext fail closed.

Full-file reads also verify the whole data/index/native hashes and exact native length. Hold the final delivery batch until these checks pass; otherwise an HTTP client could receive its complete Content-Length despite an integrity failure. Delivery chunks are at most 1 MiB and each checks the application's exact current permit, cancellation and prepaid range. [ADR-113](../decisions/113-large-native-response-accounting.md) places durable spend/audit on a bounded 64 MiB accounting window and independently refreshes the at-most-five-second authority lease; a window never supplies authorization. The legacy small-context path remains unchanged. Partial native ranges authenticate their selected frames; the local client must verify the complete file hash when assembling resumes. The codec does not supply or cache authorization.

The framed adapter exposes a sequential pull cursor over one exact range. The original owning context bounds its lifetime; each `Next` also consumes the current call's cancellation and earliest deadline. A successfully completed call detaches its cancellation callback before the next call can start. The cursor never performs idle reads or prefetches, opens no additional keys and grants no authority. At most one call is admitted at a time. A canceled call rejected before admission performs no work; a failed or canceled admitted read makes that cursor terminal rather than silently rereading an uncertain request. `Close` cancels and joins the actual pending object read and its callback. A source that does not finish after cancellation keeps closure pending; cancellation alone cannot certify joined completion.

Each pull returns an independently owned buffer of at most 1 MiB, including one empty final buffer for an authenticated empty file. The caller clears that buffer after use and still applies its current delivery checks. The cursor retains at most one bounded index page and one decoded 8 MiB frame, in addition to the bounded decoder/cipher workspace and manifest directory. It clears retained plaintext frame buffers on completion, error or joined closure; it does not promise Go heap/key zeroization or erase bytes already delivered to the caller. Existing push `Reader.Read` uses the same cursor, so both paths share page/frame validation, whole-file final checks and key counts. Only a full-file final result reports whole-file verification; completing a partial range reports selection completion alone.

`Layout.RangeReadWork` computes a bound before opening the encrypted index. It counts all selected full native frames (including boundary portions outside the requested range), their intersecting pages and those pages' exact index ciphertext bytes. For each selected page, the data ciphertext bound is the smaller of the page's complete data span and the selected full-frame native lengths plus 64 KiB per selected frame. This is conservative until the authenticated frame entries are known. Empty files still owe one page and one encrypted frame. Arithmetic validates the directory and 1 TiB limit before summing. Independent overlapping cursors or accounting windows owe the overlapping work again; this helper does not infer reuse from previous receipts.

Per-pull work reports requested index/data bytes before each object read and the full native decode allowance before decoding. Failed or unknown reads retain those attempted bytes; the report is neither a refund nor a substitute for prior admission. Counts distinguish native decode work from compressed storage bytes. Page counts separately bound decoded index JSON to 256 KiB per page. Manifest/key opening, delivery, audit, transport and independent retries remain separate charges. These codec counters are not yet wired into a generic public download admission or the SQL/window-key contract.

The focused cursor regressions use synthetic codec inputs, including a sparse encrypted two-page layout with real ciphertext only for its two selected frames. They do not qualify an entire 2 GiB transfer, backend latency, installed authority or large-file RSS. The existing streaming pagination regression remains separate. Generic published-artifact authority, a live regional window reader with independently admitted short conversations, finite window/control retirement and production large-object publication remain necessary before replacing the 4096-byte context transport. No context limit, persistent format, private wire protocol or SQL/key allowance changes here.

Multipart parts are independent of native frame boundaries. A future 1 TiB uploader should use a bounded part size large enough to remain below S3's part-count limit, such as 128 MiB, and account for its memory/staging. The first implemented `PutSmall` adapter deliberately caps ciphertext objects at 16 MiB and does not claim production large-object upload. The generic streaming codec supports the larger layout without promoting the earlier experimental multipart code.

## Commit, uncertain outcomes and cleanup

The coordinating application performs these transitions through I-05 and the named SQL transaction facets. Remote I/O never runs while holding SQL row locks.

1. In a short admission transaction, check current authority and expiry **after all blocking locks**, reserve worst-case capacity/object slots, register all pending copies, and durably record the audited acquisition/attempt with a stable deadline.
2. Prepare wrapped data/index/manifest keys. Start the authorized source only after key preparation succeeds. Write data and index using scoped writer credentials and conditional creation. Record exact upload IDs for reconciliation. Conditional `PutObject`/`CompleteMultipartUpload` prevents ordinary overwrite, but versioned delete markers and unknown completion still need the ledger and a fresh attempt identity. [S3 conditional-write semantics](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html).
3. Finalize complete ciphertext, produce the schema-valid detailed manifest, conditionally create its encrypted object, then create the minimal envelope. Persist bounded completion references locally if the hub is disconnected. A successful HTTP upload alone never publishes evidence.
4. A separately authorized verifier pins exact versions and verifies ciphertext hashes/lengths, authenticated manifest, index structure, origin/audience/deadlines and class/projection provenance. Only then may a short SQL commit make the artifact/catalog association visible and enqueue minimized durable work. Duplicate receipts resolve the same artifact; conflicting content is an error. Child sharing/download grants can materialize only after this verified commit.
5. An unknown upload/COMMIT outcome remains charged and non-discoverable until reconciled. A lost SQL response is retried under the original idempotency key. Failed verification never refunds storage that may still exist. Reconciliation cannot repeat acquisition or grant the writer read permission.
6. At the read cutoff, deny new/resumed access. Cleanup covers data, index, manifest, envelope, noncurrent versions, incomplete multipart uploads and registered copies. Release capacity only after trusted verified deletion. Failed/unreachable cleanup is overdue and still charged. KMS shared-key rotation is not selective artifact erasure.

This contract does not add a service, broker, alternate database or public configuration API. The initial [custody transaction facet](custody-transactions.md) reserves all four copies and verifies ciphertext receipts into `stored_unpublished`; it deliberately does not implement step 4's complete authorized catalog commit. The subsequent [pod-status verifier](manifest-verification.md) implements full semantic manifest/envelope and native-document validation for one bounded context profile. It still uses independently supplied expected facts without a production accepted-execution resolver. Actual durable execution/audit intent, current authority, authorized catalog publication, backend IAM, writer fencing, restore and all-copy deletion remain mandatory before enabling the context slice for users.

[ADR-244](../decisions/244-native-artifact-types.md) connects the framed encoder to the [ADR-166](../decisions/166-bounded-streaming-custody.md) multipart data writer (small index, manifest and commit objects alongside), raises that path to 256 MiB native (33 parts of 8 MiB) and adds the artifact-type registry whose native media type enters the AAD binding: `application/x-pcapng`, `application/x-ndjson` (syscall JSON Lines) and `application/json` (pod status, HTTP header projection). The byte layout above is unchanged.
