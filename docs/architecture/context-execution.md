# Bounded context execution and encrypted production

Partial S-01/S-02, TASK-02/03/05 and REQ-EXE-001: C-11 now composes signed work, independently resolved current scope, the prepaid local start journal, bounded pod-status acquisition and C-14 encrypted artifact production. This internal coordinator is not a public execution endpoint.

`ContextExecutor` accepts an authenticated receiver incarnation and signed `runAction` work. `ContextWorkResolver` must supply independently accepted, current scope and capacity facts; its production adapter remains required. The executor matches all action, target, budget, audit, authority and epoch bindings, including the receiver's collector process epoch. Public configuration remains whole-pod; the internal epoch prevents a replacement collector process from consuming a previous process's reservation.

Before acquisition, lookup the immutable start record and prepare all three wrapped artifact keys. Repeat signature/trust and current-reference checks after that blocking I/O, preserving the original expectation and deadlines. Only a successful, definite `ConsumeStart` response with `MayStart` may capture. Concurrent/replayed deliveries return `AlreadyStarted`. A lost CAS reply remains `Indeterminate`; it never authorizes a second capture. Collection, oversized output and storage failures after consumption remain spent.

The single-use `ContextProducer` validates native pod-status against its independent expectation, encrypts the data/index/full manifest and writes the four immutable attempt objects under their prepaid limits and original write deadline. It has no SQL/catalog authority, decryption capability or refund path. Partial writes remain obligations. `StoredPendingVerification` requires separate full verification, outcome audit and authorized publication. Go/Tink primitive references are dropped on close; this does not promise physical memory erasure.

Verification on 2026-10-10: race tests in `test/results/context-execution-unit.log` passed, including eight deliveries producing one capture, failed/lost starts, changed authority after key preparation and changed collector epoch. `make context-integration` passed with the real producer and verifier against two owned Kubernetes clusters, PostgreSQL, OpenBao and S3 (`test/results/context-storage.log`, `context-storage-environment.json`: exit 0, unchanged source, empty cleanup failures). That integration still supplies synthetic accepted authority facts; it is not full executor qualification. `make go-check go-architecture-check sql-check spec-check architecture-check design-check` passed (`test/results/context-execution-gates.log`).

Production current-reference resolution, collector process exclusion/attestation, dispatch, writer fencing, outcome/catalog publication and the end-user session/download path remain necessary before enabling collection.
