# Current case metadata through browser and MCP

C-20 optionally composes the C-16 ordinary context catalog service through
`ContextCaseOperations`. Its sole operation is the existing canonical
`get_case({case_id})`. A case ID from authorized capture progress is navigation,
not evidence authority. The real service must independently check current
identity, whole-pod rights, retained audience, verified publication, recovery
and effective retention. Publication rows or a native download reader cannot
implement this public service port.

The explicit projection is `Ready` / `ordinary`, verified `pod-status` metadata
with complete artifacts and effective access/deletion dates. Its digest is the
immutable verified ciphertext-copy receipt version, not native SHA-256. The
handling notice identifies possible personal identifiers, network addresses and
paths; it states that downloaded copies cannot be recalled. No native filename,
file checksum, file bytes, storage key, target locator, invented title or
timeline is returned. Raw/shared access and other artifact kinds are unsupported
by this first service and cannot fall back to ordinary metadata access.

The existing offline investigation schema generator now derives six qualified
subsets. The previous five schemas remain unchanged. `get_case` rejects wider
canonical branches that this service cannot supply. The same bounded validated
JSON is delivered through browser and MCP. Results preserve the original
service metadata interval through final identity checks, encoding and socket
writes. A shorter final identity deadline also restricts delivery. Missing,
foreign, unpublished, denied and failed-provider results share a nondisclosing
unavailable response; no target or provider error is echoed.

`NewInvestigationOperations` composes explicitly configured capture and case
services and rejects mixed origins or duplicate advertised names. The common
transport port retains only origin, tool discovery, schema lookup and bounded
Call. Case-only configuration exposes only `get_case`. Capture-only remains
unchanged. A disabled configured capture service retains its existing browser
explanation; its mutation is absent from MCP discovery. No native download
operation is registered merely because its canonical schema or UI exists.

Metadata retains the existing 24 KiB response ceiling so MCP can carry both
structured and compatibility-text copies within 64 KiB. The current manual
context case contains one artifact. An oversized projection is unavailable,
never silently truncated; broader case browsing needs separately designed
pagination. Browser case reads still use exact-origin TLS, session-bound CSRF,
POST and no idempotency header. MCP uses its separately pinned bearer identity.
There are no subscriptions, anonymous links or delegated client credentials.

This is transport composition, not an enabled public installation. Protected
runtime wiring must still supply the required pre-disclosure access/denial
outcome audit mediation and qualify the complete service before mounting it.
The focused tests use explicitly synthetic C-16 data to exercise projection and
real loopback TLS/session/MCP boundaries. They do not qualify SQL authorization,
evidence bytes, worker execution or production audit. The native-download
composition gaps remain in [the evidence wiring map](context-evidence-workflow.md).
