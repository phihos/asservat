# Retention checks at effect transactions

Partial C-01/C-15/C-14 implementation under REQ-PRV-002/004 and S-01/S-02. Evaluating a current policy set is insufficient if its source changes before collection admission, publication or disclosure. These operations must compare the evaluated versions against current accepted source state inside the same SQL transaction that authorizes their effect.

`AcceptedRetentionReader` now returns an internal `RetentionProof`: the authority root, exact cluster/namespace/workload/pod identity, protected topology revision, policy and selector revisions, complete ordered source versions, and the original observation interval of at most five seconds (30 seconds, `artifact.RetentionProofInterval`, since the ADR-200 revision of 2026-10-23, migration 00075). Each source binds the protected namespace, source role, guard digest, runtime epoch, audited acceptance revision and semantic snapshot digest. A fixed two-entry value contains exactly one hub and at most one configured local source; unused entries must be empty. Copies cannot alias mutable source lists. This value is provenance, never a public request field or bearer credential.

Runtime source epochs and renewed observation times do not enter the collection approval digest. The accepted scope continues to bind effective retention values and policy UID/generation/definition digests. Restarting a reconciler invalidates an old effect proof without making unchanged collection settings require another approval. Pure policy arithmetic and historical audit decoding can omit the proof; they cannot authorize current SQL effects.

`RetentionTransactionGuard` is composed with the installation's protected topology reader, independently of request input. Before a transaction, it obtains a fresh complete topology observation. Inside the transaction, it compares the original proof and topology, locks the accepted sources and requires current epoch, exact checkpoint/snapshot, live observation, completed ordered catch-up and both source/lifecycle audit acknowledgements. It checks database time after blocking reads. Neither the topology read nor transaction retry renews the earlier proof.

All involved transactions acquire the permission root first. This serializes source changes/catch-up with capture admission, verification, publication and download permits. Existing custody/session locks remain under that root; source reads cannot race a writer holding the same root. No Kubernetes or object-store call occurs while SQL locks are held. Write paths repeat their authority checks after writes; failures roll back new effects and preserve previously committed accounting.

The initial integration covers context admission, context semantic verification, catalog publication, download session reservation, batch start, metadata permit and every content batch permit. Exact capture replay remains a historical lookup under current ordinary rights, with no acquisition, new quota spend or clock extension. Audit acknowledgement, accounting completion and cancellation remain available without manufacturing a new collection/disclosure decision. Constructors without a retention guard support those read/audit/configuration facets only; effect methods reject that composition.

Production role grants need SELECT on accepted retention state and the narrowly scoped locking privilege, with no ability to acknowledge audits, alter source epochs/freshness, advance history or mark catch-up complete. The real SQL fixture exercises separate roles and encrypted source-audit receipts. Its initial installer topology/review observations remain explicitly synthetic; the separately qualified Kubernetes adapter supplies the actual production observation mechanism.

Real SQL/S3 qualification passed in `test/results/retention-effect-second-integration.log` (51.789 seconds; unchanged source and complete cleanup in the named environment report). Source restart rejects old proofs without changing the approval digest; withdrawing source readiness blocks verification, publication and prepaid download output. Historical capture replay preserves its original accounting. Go/race/import/SQL/spec/architecture/design gates also passed in `test/results/retention-effect-gates.log`. This component does not establish current fleet/result authority, storage locality, protected selector history or installation pin enrollment. Those are still required before public collection/download. Native file downloads remain the intended developer workflow; these internal checks add no user approval step.
