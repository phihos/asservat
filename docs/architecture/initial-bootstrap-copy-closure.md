# Positive setup-copy closure

C-20's private bootstrap composition extends ADR-131 with a fresh persisted v3 capability. The existing trusted input producer, original manager retirement and independently protected SQL history remain the only source of original installation identity. The new cleanup metadata is bounded provenance and completion tracking, not SQL activation/recovery or disclosure authority.

The public prelude adds one fixed ConfigMap marker and named get/update rights for its existing observation account. No Secret read/delete rights are added to that account. The original v3 guard permits its explicitly dry-run update to reach the later tombstone; persistent mutation remains denied. The tombstone permits only exact original copy UID/closure-ID metadata marking and DELETE, and rejects all recreation. Its policy/binding are single-create in the product journal and owned by trusted installation administrator/RBAC authority. VAP cannot evaluate admission-policy/binding mutations, so no self-protection is claimed. The product pins both original identities/content and checks them before every effect and completed replay; missing/replaced protection is unavailable with no recreation/adoption. Runtime/probe roles receive no admission-object mutation permissions. Kubernetes administrators remain the trust boundary.

The first cleanup observation must independently establish complete native handover and its exact SQL activation claim, plus original positive manager retirement. First manager retirement may use original setup material after completed-history classification; the manager pool joins before copy closure. An already-retired invocation only opens the existing history reader and public observation projection. It never opens administrator SQL, DDL or provider inputs.

The seed retains a fixed set of once-set public annotations: the original fifteen-minute cleanup claim, original policy/binding create times and receipts, each copied Secret's pre-DELETE UID/resourceVersion and positive removal receipt, and final completion time. No list, extensible operation queue, secret data/hash or arbitrary reason enters this state. All observations intersect their original caller deadline and the original cleanup end. The two-minute command budget is an attempt bound, not a new cleanup interval.

| Transition | Positive prerequisites | Unknown result |
| --- | --- | --- |
| Original cleanup claim | Exact protected original root/history and manager closure; both original copies present | Read the same immutable annotation; never renew its interval |
| Tombstone policy/binding CREATE | Newly acknowledged original fixed claim | Exact object lookup only; absence is not another CREATE |
| Copy metadata mark | Both independently proved guards; original immutable copy UID/current resourceVersion | Read that original metadata; never adopt replacement data |
| Copy DELETE | Retained original mark UID/resourceVersion and both current guards | Exact absence under permanent recreation denial; otherwise remain incomplete |
| Seed sanitization | Both removal receipts and current exact absence/guards | Metadata-only final receipt lookup; no broad seed fallback |
| Completed replay | Exact history-only bundle, original handover/SQL activation and both current guards | Unavailable; never recreate missing state |

The final seed update couples fixed sanitized data, immutable=true and its once-set final annotation in one CAS. Native admission must qualify the actual Secret/CEL encoding. A completion annotation cannot coexist with retained setup payload. The existing private preparation journal has already been sanitized by its own qualified handover transition; it is not another deletion here.

Fresh selection checks all fixed owned names and the target namespace. A retained seed selects only its exact v2/v3 desired digest. A complete protected pre-seed prelude can select its same original version read-only, preserving namespace/account/anchor/policy/binding pins through subsequent Open. A partial prelude without a provable original guard currently fails unavailable. This is an explicit recovery gap, not completed automatic crash recovery. No format choice is exposed to operators and absence of the seed alone never means fresh.

Tests distinguish local state/CAS/transport coverage from real API enforcement. The full native command case must observe the actual original manager-retired seed event before sanitization, verify its old credential/session denial, then independently verify final immutable seed data, exact tombstone, absent copies and recreation denial. Missing watch evidence fails; no completed flags are synthesized from final state. Setup-free replay then runs all four actual commands in a fresh Restricted runner using the same original identities. Native RBAC checks cover the actual probe identity; after replay, actual administrator removal of the tombstone binding must be detected and must not trigger recreation. No managed-copy native result is claimed until that fixture passes.

It exposed and corrected cleanup rejecting the producer's required installation/request annotations; every metadata read now matches both against the original retained claim. The terminal report records three passing entries, 1,348 unchanged source hashes and complete owned cleanup. Initial upstream services and administrator credentials remain fixture inputs; product-created manager/schema/activation/retirement are exercised by the compiled commands. See [implementation progress](../implementation-progress.md) for exact image identity and verification scope.

These API deletions make no claim about operator-owned originals, upstream S3 credential revocation, Go heap erasure or historical control-plane/etcd backups. Expired cleanup, lost original tombstone CREATE with no visible object, and partial unprotected pre-seed state remain retained and require separately qualified recovery. Helm runner and public-runtime enablement remain off until their complete composition is qualified.
