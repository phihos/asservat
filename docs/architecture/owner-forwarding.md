# Outbound owner enrollment transfer

[ADR-086](../decisions/086-outbound-owner-enrollment.md), extended by [ADR-087](../decisions/087-live-owner-delivery.md), adds `mtls.OwnerForwarder` alongside the [private receiver](owner-relay.md). C-21 owns socket/protocol composition and the concrete protected configuration. C-04 owns the new `OwnerClientIdentity` port and current local-client check. C-14 owns `WorkerOwnerLookup`, embedded by the existing `WorkerOwnerStore`; the sender receives only the read facet. Domain values and SQL migration 30 are unchanged. This is an internal I-13 certificate transfer, not a new user interface or evidence permission.

## Configuration and lookup

Protected composition supplies an exact `OwnerPool`, process-owned client credential, explicit owner roots, an installation-bound worker trust catalog, current route/authentication services, and purpose-scoped owner/worker readers. [ADR-089 routing](worker-routing.md) resolves the exact worker profile from current audited SQL dispatch and selects issuer roots by that profile's control-document digest and cluster. Never combine cluster roots or accept worker-supplied trust. Current profile and catalog checks repeat before token transmission and after receipt. Reject cross-installation or wrong-purpose configuration and invalid concurrency. Catalog contents and constructor success do not establish profile acceptance.

A call accepts installation/session/worker IDs, a bounded dedicated Pod token and a valid identity-free signed CSR. It does not accept an endpoint, caller principal, human credential, selected process, key material or locator takeover. Verify input and acquire one of 1–16 immediate slots. Capture one original thirty-second context, bind root cancellation, and intersect the actual locator and admitted worker deadlines. Resolve the locator once; its exact request/fence/Pod/process/timestamps cannot change during the call. The current worker must match the pinned profile and requested IDs.

Read a protected route for that exact owner binding. Require matching accepted pool and copy its configuration/address observations. Dial only canonical qualified Pod IPs from that observation. At most two TCP attempts are possible, each with a two-second dial ceiling and the same earlier route/worker/setup deadline. A second address is tried only after TCP connection failure before TLS/HTTP. There is no DNS lookup, Service load-balancer substitution, private-host override, callback or ambient proxy. The deterministic DNS SAN is only the TLS verification name. Constructor API exposes no test dial hook; unit fixtures explicitly replace an unexported function inside the package.

## Before transmitting credentials

Use fresh mutual TLS 1.3, HTTP/1.1 ALPN, explicit owner roots and disabled resumption. The actual client certificate must match the captured owned credential; closure/renewal cannot silently swap it during the exchange. `OwnerAuthenticator.CheckOwnerClient` independently verifies its current registration, roots, native protection and Ready routing. It uses a local client identity port, never a fabricated TLS handshake.

Authenticate the actual remote connection with the exact expected server Pod/process and current registry/configuration/protection/Ready route. Require the same pool, original route configuration revision, Pod name and ReplicaSet UID. Re-read the exact shared locator. Check all original route/worker/peer intervals after blocking work. Set the write deadline to their earliest cutoff before making the HTTP transport usable. Recheck root/caller cancellation and the installed client identity at the one-use transport handoff. These checks precede the Pod token and CSR leaving the process.

The HTTP transport can consume only that one authenticated connection. Its ordinary dial path always fails; it cannot reconnect, follow a redirect, use system proxy/CA settings or replay the non-rewindable POST. There is no cookie jar or connection cache. The owner-relay/v2 request remains bounded to 20 KiB; the generated 32-byte nonce is unique to this exchange. Another call must start with new current lookup/admission; no uncertain result triggers an internal retry.

## Receiving and validating

The original request/locator/worker/client-certificate deadline bounds reading; response headers are capped at 4 KiB and the single length-prefixed closed JSON response frame at 49664 bytes. Reject non-200 status, content encoding, cookies, redirect location, trailers, mismatched format/IDs/nonce and absent chain arrays. Certificate DER is individually bounded to 16 KiB and collectively to 32 KiB with at most three intermediates.

The worker and sender share `checkWorkerCertificate`: parse actual DER, verify the CSR's key, explicit worker issuer, exact acquisition role/Pod, bounded profile and original worker-derived certificate period. It permits only the original or completion-side period at an actual renewal boundary. HTTP metadata and an owner certificate do not substitute for verification of the worker certificate. The owning coordinator still supplies audit, signing spend and activation; a returned public certificate alone supplies no current access authority.

After receiving, revalidate the actual original server TLS snapshot and current local client credential. Require unchanged remote certificate/enrollment/configuration/protection, the exact current locator and the same admitted worker binding, Job, generation, profile, scope and original times. Preserve the earliest fresh identity deadlines through remaining lookup work; reject cancellation, clock rollback, changed/expired sources or worker replacement. Return a live delivery containing independently owned verified certificate bytes only while all current checks hold. Its context additionally retains current worker freshness and the remote output deadline. Raw network/provider errors and tokens are never surfaced in diagnostics.

Root closure or caller cancellation interrupts the raw socket during handshake, request transmission and response reading. Every call owns its socket and transport until delivery Close; there are no cached channels to survive credential shutdown. Sender closure does not close the shared client key; the process credential supervisor owns that key lifecycle. Configured per-instance slots and finite deadlines do not qualify installation-wide fairness, rate limits or HA load behavior.

## Live delivery through the worker response

`BeginWorkerEnrollment` implements C-14's existing `WorkerEnrollmentExchange`. It returns a live `WorkerEnrollmentDelivery`, backed by an open authenticated connection to the original request owner. The receiver sends one bounded length-prefixed `OwnerRelayResponse` frame, containing format, original effective deadline and the existing worker certificate response, with `application/vnd.asservat.owner-enrollment-stream`. Require chunked HTTP/1.1 and no Content-Length. The owner keeps the body open and silent after that frame; the initial thirty-second exchange and final five-second identity proof bound its lifetime. There is no heartbeat, authority token, renewal or reconnection.

One bounded reader waits for a single additional payload byte. Any byte, EOF or error cancels the delivery. Local caller/root cancellation and the original deadline close the raw socket. `Close` is mandatory, idempotent, closes the connection and joins the reader before releasing the concurrency slot. Slots stay charged through the downstream write, including cancellation cleanup. The receiving owner also retains its original operation and slot until disconnect/cancellation. This adds no detached background owner or durable state.

The existing worker handler now accepts the forwarder directly and keeps this delivery through its write and flush. Cancellation interrupts a blocked downstream TLS write. Normal completion closes the relay. The finite `ForwardWorkerEnrollment` utility explicitly closes its delivery before returning a public certificate; callers cannot derive a live context from that value.

A healthy connection propagates owner cancellation; a silent network partition is bounded by the original effective local output deadline, at most five seconds after the final local identity check. Already delivered bytes cannot be recalled. The certificate still needs current activated identity and operation/evidence authority on use. Protected process startup, native routing and connector-local proof mediation remain required before enabling a public workflow.

## Verification boundaries

Synthetic component tests use the actual sender, receiver, TLS/key implementations and strict certificate validator. They establish zero HTTP requests for retired/removed-root/foreign-owner/stale-locator/cancelled-client cases; rejection after identity/locator/worker changes during the response; wrong worker key/identity/root/expiry; non-replay after a lost reply; redirect/malformed/oversized-header rejection; bounded concurrent work; interruption of a stalled response; and pre-HTTP fallback to the second qualified address.

The unit network remaps synthetic Pod addresses to its owned loopback listener. Registry, worker binding, locator and signing authority remain synthetic ports. This is not a native routing or installation test. Native Kubernetes/OpenBao/SQL/S3 regression separately tests the new local-client check before readiness, while current, after root removal and after Pod deletion, and retains previous receiver/worker-credential cases. Actual commands, results, source hashes and cleanup are in [implementation progress](../implementation-progress.md).

Additional real TLS tests retain ownership after certificate receipt, exercise deadline/EOF/extra-byte/network-loss cancellation, hold slots through close and compose the actual worker handler with a blocked final TLS response. Parser tests reject oversized/truncated and open-shape frames. These remain synthetic authority tests.
