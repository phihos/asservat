# Private owner enrollment receiver

[ADR-085](../decisions/085-private-owner-enrollment-receiver.md), extended by [ADR-087](../decisions/087-live-owner-delivery.md), connects current owner identity to an actual bounded HTTP receiver. C-20 owns `internal/transport/ownerrelay` and the shared wire shape; C-04 owns `OwnerServingIdentity` and current checks; C-21 supplies actual TLS/server-key adapters. C-14's `WorkerOwnerEnrollment` resolves existing live operations. Existing domain identities and SQL migration 30 remain unchanged; no durable object or public API is added.

## Wire and exact request ownership

POST `/internal/hub-owner/v2/enroll-worker` over mutually authenticated TLS 1.3, with `Content-Type: application/json` and exactly one dedicated Pod `Authorization: Bearer` token. The body is the closed [owner-relay/v2 schema](../../specs/contracts/owner-relay.schema.json), at most 20 KiB with a known Content-Length. Reject unknown/duplicate/aliased fields, absent values, invalid nonce/CSR, query/callback URLs, cookies, encoded/chunked bodies, trailers and Expect. The enrollment retains its existing installation/session/worker/nonce/CSR values. The locator includes request UUID, destination Pod/process, fence, original start and expiry; no network address or human principal appears. Replies carry one four-byte big-endian length prefix and at most 49664 bytes of closed owner-relay/v2 JSON with an effective deadline and nested worker-enrollment/v1 result. Combined certificate DER remains at most 32 KiB. The response is chunked HTTP/1.1 with `application/vnd.asservat.owner-enrollment-stream`; the body remains open and silent after that frame. EOF is loss of live ownership, never successful handoff. The worker still verifies actual issued DER, key and identity.

`WorkerRequestOwners.Register` attaches the successfully claimed registration to its exact already bounded router entry. Receiving resolves that entry under the router lock, then retains the exact handle across shared SQL reads. A wire locator cannot construct an operation, select a new request after replacement, revive a closed handle or transfer authority between processes. Require exact identity/fence/timestamps; timestamp equality compares instants after JSON/SQL serialization. Closing a route drops its registration reference after in-flight work releases. No second map, background cleanup queue or per-request durable row is introduced.

## Admission, execution and output

Each call has an original maximum thirty-second context, intersected with the existing connection, locator and operation deadlines. Concurrent calls are bounded to a configured 1–16 slots with immediate 429 at exhaustion. Invalid/unavailable responses contain only status, never provider errors, tokens or caller input.

Before body consumption, check local serving eligibility and actual client TLS, each through active registration, accepted roots, native protection and exact Ready routing. Retain the earliest original observation with a five-second aggregate ceiling. Body reading must finish within it. Restore the original bounded socket read deadline afterwards so its background disconnect reader does not accidentally cancel independently authorized operation work when the initial admission proof expires.

The initial peer observation admits the request only. During enrollment, the exact operation performs its existing current developer/Pod/locator checks, independent encrypted audit, finite signing spend and activation. It does not retain initial peer identity as execution authority. Before response bytes, repeat local and actual-peer authentication under the surviving operation/owner deadline. Require the same caller certificate, registration, pool, Pod/controller, configuration revision and protection digest. Clip writing to the earliest fresh observation, original request/owner/locator deadline and returned worker certificate expiry. After flush, retain the exact delivery and slot until the original effective deadline, owner/root/request cancellation or the forwarding client disconnects. There is no renewed deadline or extra payload. The sender keeps this connection open through its downstream worker response. Owner/root/request cancellation interrupts a blocked write; join the cancellation callback before resetting connection deadlines.

`OwnerAuthenticator.CheckOwnerServing` uses the shared current-state orchestration with a distinct process-owned server identity port. `mtls.OwnerCredentials` revalidates copied DER under both pinned and currently accepted roots, rejects client-purpose credentials, suspension, closure and changes during verification. This does not fabricate actual TLS or expose a new authenticated-peer capability. `mtls.OwnerRequestPeers` adapts these local checks and actual HTTP TLS state; bootstrap must compose the same server credential owner and independently pinned pool sources.

## Listener and shutdown

`ownerrelay.Serve` takes an owned TCP listener, explicit roots, an enrolled process-owned server credential and the concrete handler. It uses only HTTP/1.1 with TLS 1.3, required verified client certificates, no session tickets/resumption and no default mux. There is no plaintext/anonymous health route on this listener. Identity availability permits listening; request admission additionally requires current Ready routing. Protected startup must compose readiness without making enrollment depend on an already Ready endpoint.

Bound accepted connections to 1–64 before TLS. Set a five-second header/idle limit, 32 KiB header budget and thirty-second request read/write ceilings. Each accepted connection has an immutable lifetime of at most thirty-five seconds, intersected with the server certificate observed at acceptance. A wrapper clips every later deadline, including attempts to clear it; an independent cancellation closes the raw socket at that bound. `tls.Conn` remains the outer type seen by net/http, preserving `Request.TLS`. No HTTP hijacking or evidence streaming can outlive ownership.

Root cancellation closes listener and active sockets and cancels request contexts. Shutdown joins bounded active handler cleanup for at most five seconds. An uncooperative dependency is reported as failed shutdown rather than successful cleanup; the process supervisor still owns final process termination and credential-pair closure. No ordinary access/error log contains protocol inputs. Source/provider failures remain diagnosable through the existing bounded application result/audit interfaces, not raw TLS or body logs.

## Scope of evidence and unfinished work

Synthetic transport tests use real TLS and explicit synthetic identity/operation ports: they do not establish Kubernetes authority. Cases include revocation before receipt and during work, fresh response checks after the initial proof interval, malformed/oversized wire, wrong owner, cancelled delivery, repeated admission, concurrency saturation, missing client certificate, TLS 1.2/HTTP2 rejection, disabled resumption, immutable deadlines and socket shutdown. Application tests exercise every current boundary for both local and remote identity, plus replacement during shared-locator lookup. SQL integration now routes through the exact registration receiver.

The native owner fixture uses actual current Kubernetes workload/configuration, purpose-separated process-owned OpenBao certificates, encrypted audit and SQL activation with this listener. It checks denial before Ready, reaching an explicitly unavailable synthetic operation after Ready, and denial after root removal and Pod deletion. This is still a test-owned loopback listener outside the pause Pod. The full outbound authenticated relay, connector token/proof exchange and native worker enrollment through this receiver remain unqualified. [Implementation progress](../implementation-progress.md) records actual runs, including failures.

The [sender](owner-forwarding.md) now supplies current pre-transmission checks and live forwarding through the actual worker handler in synthetic tests. Next compose protected in-Pod startup and connector proof mediation, then native transfer and the public developer flow. Aggregate admission fairness and provider/connection burst sizing remain separate release requirements; local semaphores alone do not establish fleet-wide protection.
