# One-use connector bootstrap claims

C-04/C-21/C-24 under TASK-03, S-01 and REQ-FED-001/002. This is the claim boundary for an existing administrator-issued, audited bootstrap slot. Issuing that slot, publishing its issuance audit, activating certificates and exposing enrollment routes remain separate work. A bounded PKI adapter and claim-audit publisher are now implemented; they do not themselves activate peers.

The initial credential has a random 256-bit secret in canonical unpadded base64url. Only a purpose-, installation- and bootstrap-bound SHA-256 digest is stored. Bootstrap IDs are opaque, and secret possession never allows the caller to select installation, cluster, peer or issuer epoch; these are frozen by the existing slot. The secret belongs in an authenticated request body/header, never a URL, log, CRD status, copied command line or error. Syntax checking cannot establish entropy; the issuer must use a CSPRNG.

The request carries a DER PKCS#10 CSR of at most 8192 bytes. Standard-library X.509 verifies proof of key possession. The initial profile accepts Ed25519, named-curve ECDSA P-256/P-384/P-521 and RSA 2048–4096 with exponent 65537 and SHA-2/PSS signatures. It rejects requested subjects, SANs, extensions and all attributes; identity is assigned from the slot. The signed ASN.1 attribute set is checked explicitly because the standard library's legacy parsed Attributes field drops some shapes. ASN.1 framing checks do not replace library-owned key parsing and signature verification.

The canonical public-key digest is the claim identity. A fresh valid CSR signature for the same key may recover the existing claim, without another peer or renewed expiry. This avoids requiring byte-identical randomized ECDSA/RSA-PSS signatures after a client retry. A different key cannot claim a consumed slot. Clients must persist their private key securely before submission; Asservat does not return or escrow it through this protocol.

Migration 00007 adds `fleet_bootstrap` with an original at-most-five-minute interval, preassigned peer/cluster/epoch, issuance authority and exact issue-audit receipt, revocation, and write-once claim fields. The claim adapter locks trust root then bootstrap, checks current root freshness/recovery/epoch, secret and expiry after waits, and saves one key/claim time. It checks deadlines again after the write. Duplicate requests return the original binding, time and expiry. Expired/revoked credentials cannot recover a new usable grant, and a lost COMMIT response never causes a new slot, refund or identity.

The claim role can read the two tables and update only the claim columns (plus the minimum root lock column privilege). It cannot issue a token, change its expiry/revocation, enable a peer or reset recovery. A database trigger additionally rejects rewriting the frozen slot, undoing revocation, starting in a claimed state, or resetting/rebinding a consumed claim, even through direct SQL with the allowed claim-column privileges. The future issuer must enforce finite outstanding/history limits and retirement. Production migration/role composition, restore fencing and enrollment request-rate limits remain required; fixture column privileges alone do not establish those boundaries.

`ClaimConnector` returns a pending internal enrollment, not a certificate or an authenticated peer. There is no public endpoint accepting caller-created domain values. Certificate issuance/activation must independently require the claim's durable audit, current root and original deadline, verify the issued certificate's exact identity/key/profile and publish its registration atomically. No public collection or disclosure is enabled by this component.

The subsequent [connector PKI adapter](connector-pki.md) provides only the bounded provider/signature-check facet. It does not supply that coordinator or activate claimed registrations.

## Verification

The ignored-CSR-attribute case failed before its fix in `test/results/enrollment-csr-regression.log`; fixed proof-of-possession, identity rejection, malformed/tampered/oversize CSR, supported-key and stable-retry tests passed under the race detector in `test/results/enrollment-csr-unit.log`. The [standard-library CSR API](https://pkg.go.dev/crypto/x509#CertificateRequest.CheckSignature) supplies the signature check; its installed source was inspected to identify the attribute omission.

Real PostgreSQL tests passed in `test/results/enrollment-integration-check.log`: eight matching claims produce one first claim and seven replays; competing keys have one winner; reconstructed adapters recover the same peer; wrong secret/key, revocation, root recovery/epoch changes, stale trust, expired credentials and expiry during a row-lock wait deny. The role cannot widen issuance/peer authority, and claiming creates no active peer. Existing authority, custody, context admission and registration checks also passed. Source hashes were unchanged and owned fixtures were removed. This does not qualify token issuance/audit provenance, certificate delivery or production restore.

## Durable claim audit

Migration 00008 adds a write-once encrypted claim-audit receipt. The audit binds the original bootstrap/installation/cluster/epoch/peer, public-key digest, original issuance authority/audit and unchanged claim/deadline. It contains no secret or CSR. Each publication pass handles at most two records, with a thirty-second I/O budget. Conditional object creation followed by authenticated readback preserves the first stored ciphertext after a lost reply. A changed record cannot overwrite it or acknowledge a different object.

SQL acknowledgement locks installation then bootstrap and compares the immutable record. It remains permitted after revocation or expiry to preserve explanation; it grants no signing or peer authority. The audit role cannot claim tokens or enable peers, and a trigger prevents clearing or changing an acknowledged receipt. Receipt version may be empty on a qualified unversioned store; ETag, length and SHA-256 are still exact.

The envelope's identity/purpose/corruption tests passed under the race detector. The real SQL/S3 publication, retry, role and immutable-receipt checks passed with exit 0 in `test/results/enrollment-audit-integration-check.log`, with unchanged source hashes and complete fixture cleanup. These checks do not qualify production issuance provenance. The subsequent [activation coordinator](enrollment-activation.md) composes claim audit with finite provider attempts and certificate activation.
